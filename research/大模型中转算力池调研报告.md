## 一、总体概览

"大模型中转算力池"指在用户/开发者与模型供应商之间插入的统一代理层：它屏蔽厂商差异、统一 API 形态，通过路由、限流、故障转移、KV 缓存复用等手段提升可靠性与资源利用率，并把用量转化为按量计费收入。其存在基础是 LLM 供应商的碎片化——多套账号、多套 API Key、多套计费系统、多套调用格式（尽管多数遵循 OpenAI 接口规范，细节差异仍存在）。

调研显示当前实现呈现两类算力池模式 + 三层生态结构：

- **两类算力池模式**：
  1. **纯聚合/中转型**：以 OpenRouter 为代表，不自建大规模 GPU 集群，核心价值在路由、计费与体验聚合；
  2. **自建算力平台型**：以 Together AI、Fireworks AI、DeepInfra、硅基流动、火山方舟为代表，自营 GPU 集群 + Serverless 推理层，自托管开源模型。
- **三层生态结构**（国内视角）：官方平台（阿里云百炼、火山方舟、智谱、硅基流动、DeepSeek 开放平台）直接提供推理 API；开源网关（LiteLLM、OneAPI/new-api、Higress）提供"一个 API Key 接入多家上游"的聚合底座；第三方中转站在开源网关之上做商业化运营。

**共性实现要点**：统一 OpenAI 兼容 API 层、API Key 与令牌管理、按量计费（token/GPU 秒/次）、模型目录化、路由与故障转移、用量可观测。

**证据缺口（先声明）**：火山方舟、智谱、DeepSeek 开放平台官方文档页未成功读取正文（仅搜索摘要）；各平台公开定价页均未披露可引用的 P50/P99 延迟与吞吐数据；vLLM Autoscaling、Volcano 调度器、NVIDIA device plugin、昇腾 vLLM 适配等页面读取失败，相关内容仅作一般性知识引用。

## 二、国际主流聚合/中转平台

### 2.1 OpenRouter —— 聚合网关型代表

**定位**：纯聚合/中转层，单一 API 接入数百个模型（官方表述 "One API for hundreds of models"）。

**实现要点**（来源：https://openrouter.ai/ 首页、https://openrouter.ai/docs/llms.txt 文档索引，已验证）：
- **Provider Routing**：请求路由到"最佳供应商"（成本/可用性最优）；
- **Model Fallbacks**：模型/供应商间自动故障转移；
- **BYOK**：用户自带供应商 API Key，自行承担供应商费用；
- **Batch API**：异步批量推理；**OAuth PKCE** 与 **Management API Keys**：编程式管理密钥；
- **Stripe Projects**：面向应用内嵌的计费集成；
- **可观测性**：trace 广播到 Langfuse、LangSmith、Datadog、ClickHouse、BigQuery、Grafana、Arize 等；
- **MCP Server**：`https://mcp.openrouter.ai/mcp`，OAuth 登录后接入 MCP 客户端；
- 集成方式三选一：直接 API、Client SDK、Agent SDK。

**模式判断**：【推断】OpenRouter 的算力池以聚合第三方供应商为主、不依赖大规模自建 GPU 集群（依据：Provider Routing + BYOK + Fallbacks 机制的存在）；计费为按 token 转售 + 平台抽成，具体抽成比例无公开数据。

### 2.2 Together AI —— 自建算力平台型

**定位**：美国推理云，自建 GPU 集群 + Serverless 推理。

**实现要点**（来源：https://www.together.ai/pricing，已验证）：
- 产品线覆盖从 Serverless 到裸算力的阶梯：**Serverless Inference**（按 token）、**Provisioned Throughput**（预留吞吐）、**Dedicated Inference**（专享推理）、**GPU Clusters**（GPU 集群）、Fine-Tuning；
- 微调按训练数据集 token 总量计费（数据集大小 × epoch 数 + 验证集 token）；
- 参考价（每百万 token）：Qwen3.5-122B-A10B $6.00 / $15.00（页面列名被截断，输入/输出两列对应关系未完全确认）；Qwen3.5-397B-A17B $8.00 / $20.00；
- 页面宣传 B200 按需实例上线、DeepSeek V4 Pro 与 GPT-5.6 Sol 基准对比。

**模式判断**：【推断】自托管主流开源模型（Qwen、DeepSeek 等）+ 微调服务，非第三方聚合。

### 2.3 DeepInfra —— 推理云

**定位**：推理云（"inference cloud"），按 token 与按图像计费。

**实现要点**（来源：https://deepinfra.com/pricing，已验证）：
- 语言模型按 token 计费；图像模型按张计费，公式含分辨率与迭代次数，例如 FLUX-2-dev 为 $0.01 × (w/1024) × (h/1024) × (iters/28)，FLUX-1.1-pro 为 $0.04/张；
- 页面公告：完成 $107M Series B 融资以扩展推理云。

**模式判断**：【推断】自建 GPU 推理云，自托管开源模型（FLUX、语言模型等）。

### 2.4 Fireworks AI —— 两层计费并存

**定位**：美国推理平台，Serverless 按 token + 按 GPU 秒的裸部署。

**实现要点**（来源：https://fireworks.ai/pricing，已验证）：
- **Serverless Inference**：按 token 计费、宣称零冷启动、$1 免费额度、后付费；
- **Training**：开源模型微调；
- **On Demand Deployments**：按 GPU 秒计费，更高速度/限流/低成本；
- 按 GPU 小时价格（8 月 31 日前 → 9 月 1 日起）：H100 80GB $7.00 → $8.00，H200 $7.00 → $8.00，B200 $10.00 → $13.00，B300 $12.00 → $15.00，GB300 $18.00 → $20.00；
- 区域受限部署加收 **1.5 倍溢价**（暗示多区域部署能力）。

**模式判断**：【推断】自建 GPU 集群，是本次调研中唯一给出明确"按 GPU 秒"裸金属定价的平台；价格上调反映 GPU 成本上行或供需变化，原因未披露。

### 2.5 小结

1. **两类算力池模式并存**：聚合中转型（OpenRouter）与自建算力型（Together、DeepInfra、Fireworks）。
2. **计费分层**：Serverless 层普遍按 token（含缓存命中价、分时价）；重负载客户走预留型计费（Together Provisioned Throughput）；裸算力层按 GPU 秒/小时（Fireworks）。
3. **API 形态趋同**：OpenAI 兼容 + 多模态扩展 + MCP/Agent SDK 成为标配；OpenRouter 额外提供 Batch API 与可观测性 trace 广播。

## 三、国内官方平台与第三方中转生态

### 3.1 官方平台

#### 阿里云百炼（已验证）

来源：阿里云帮助中心《模型价格》页面，读取成功。

**实现要点**：
- **按量计费**：按输入/输出 token 分别计费，默认后付费；
- **阶梯计费**：部分模型按"单次请求输入 token 总量"分档，请求内所有 token 按落档单价结算。例：qwen3.7-flash 分三档——0~32K 输入 0.2 元/M、输出 0.8 元/M；32K~256K 为 0.6/2.4 元/M；256K~1M 为 1.2/4.8 元/M；
- **上下文缓存折扣**：显式缓存创建按标准输入单价 125% 计费（缓存写入有额外成本），缓存命中侧价格更低；
- 普遍引入阶梯计费、上下文缓存折扣、批量调用半价、峰谷定价等精细化价格机制。

#### 硅基流动 SiliconFlow（已验证）

来源：https://siliconflow.cn/pricing 模型价格中心，读取成功。

**实现要点**：
- 定价页一屏对比输入/输出/缓存命中价格（元/百万 token），支持按厂商筛选（DeepSeek、Qwen、MiniMax、Z-AI、Kimi、Stepfun、混元、Wan 等）；
- **分时定价**（DeepSeek-V4-Flash）：2:00–8:00 时段输入 ¥1.50 / 输出 ¥4.50 / 缓存命中 ¥0.15；其余时段输入 ¥3.00 / 输出 ¥9.00 / 缓存命中 ¥0.30；
- 其他参考价（元/百万 token）：DeepSeek-V4-Pro ¥12.00 / ¥24.00 / ¥1.00；DeepSeek-V3.2 ¥4.00 / ¥6.00 / ¥0.40；
- 语音/视频按次或按个计费：Wan2.2-I2V-A14B 输出 ¥2.00/个；部分 ASR 模型免费。

**模式判断**：【推断】自建算力池的国产平台：人民币计价 + 闲时折扣暗示自营 GPU 集群与成本调度；"缓存命中"单独计价说明推理栈采用 KV Cache 缓存（与 vLLM/SGLang 类引擎的 prefix caching 能力吻合）。

#### 火山方舟（仅摘要，未核实）

- 定位为字节跳动旗下模型服务平台，提供模型推理 API 与 TPM 保障包等预留型计费【摘要，页面读取失败：docs.volcengine.com 相关文档页未读正文】；
- 结论要点中提及"火山方舟 TPM 保障包"与 Together Provisioned Throughput 同类，属预留型计费【推断】。

#### 智谱开放平台 / DeepSeek 开放平台（仅提及）

- 具体计费细节未能在本次调研中核实。

### 3.2 第三方中转站：模式与风险

**实现模式**（来源：CSDN 智能体开发者社区《Token 中转站这门生意，比你想象的要大得多》等，已读）：
- 以开源网关（one-api、new-api、LiteLLM）为技术底座，实现"一个 API Key 接入多家上游"；
- **价格差套利**：聚合多家上游，以低于官方价转售或按订阅制收费；
- **故障转移**：多家上游互为备份，单家不可用时自动切换；
- 典型风险：API 密钥泄露与倒卖、违反上游 ToS、合规与生成式 AI 安全责任、服务质量不稳定（低价引流、token 掺假倒卖被媒体集中曝光）。

## 四、开源网关/中转实现

开源 LLM 网关分两类：**应用层网关**（LiteLLM、OneAPI、new-api）——"统一 OpenAI 兼容 API + 多渠道（上游）抽象 + 令牌/配额体系"，Docker 单机即可起步，适合中小团队自建中转或企业内部统一入口；**云原生网关**（Higress AI Gateway）——基于 Envoy/Istio 的七层网关，面向 K8s 大规模接入。

### 4.1 LiteLLM（已验证）

来源：LiteLLM 官方文档 docs.litellm.ai（虚拟密钥、负载均衡页面读取成功）。

**核心能力**：
- **虚拟密钥（Virtual Keys）**：通过代理跟踪花费、控制模型访问；提供 UI 生成/编辑/删除密钥（支持 SSO）；依赖 Postgres（如 Supabase、Neon），需设置 `DATABASE_URL`；主密钥必须以 `sk-` 开头，在 `config.yaml` 的 `general_settings:master_key` 或环境变量中配置；可通过 `POST /key/block` 禁用密钥；
- **负载均衡**：内置 Router 在多个同模型部署之间分发请求；
- **路由与可靠性**：跨多个部署（Azure/OpenAI 等）负载均衡、重要请求优先、冷却（cooldown）、回退、超时与重试（固定 + 指数退避）；生产环境用 Redis 跟踪冷却状态与用量（tpm/rpm 限额）【来源：https://docs.litellm.ai/docs/routing，已验证】；
- 定位：Python 编写的 LLM 代理/网关，对外提供 OpenAI 兼容 API。

### 4.2 OneAPI / new-api（部分已验证）

来源：one-api GitHub README 读取成功。

**核心能力**：
- one-api 的数据模型为"**渠道（channel）—模型（model）—能力（ability）**"三级抽象：渠道即上游供应商接入，模型即对外暴露的模型名，能力即渠道支持的模型能力集合——这是第三方中转站的标准底座；
- new-api 为 one-api 的社区衍生分支，功能相近（聚合渠道、令牌体系、额度管理）【摘要/一般认知】；
- 共同要点：对外统一暴露 OpenAI 兼容接口；额度扣减普遍采用批量更新以缓解数据库压力；README 普遍强调须遵守上游 ToS 与生成式 AI 合规要求。

### 4.3 Higress AI 网关（已验证）

来源：Higress GitHub README、产品页与多模型代理场景指南，读取成功。

**核心能力**：
- 基于 Envoy/Istio 的云原生七层网关，用 **Wasm 插件**实现 AI 代理、限流、密钥管理等能力；
- 支持 **100+ 主流模型的统一接入与协议转换**，提供模型负载均衡及 Fallback；控制台可为路由配置降级策略；
- 面向 K8s 大规模接入，并延伸出 **MCP Server 托管**能力。

## 五、核心技术机制

六大核心机制相互依赖：路由与负载均衡决定请求去向；健康检查与故障转移保证可用性；限流与配额防止过载；KV 缓存与推理加速降低单位成本；价格与成本核算、计费与对账把用量转化为收入。

### 5.1 多模型路由与负载均衡

**实现要点**：统一协议层（各家厂商 API 转换为 OpenAI 兼容格式）；路由策略（轮询、加权、基于成本/延迟/可用性的智能路由）；优先级调度；冷却机制（某部署连续失败后暂时摘除）。

**案例**：
- LiteLLM Router：跨多部署负载均衡、重要请求优先、冷却、回退、超时重试（来源：docs.litellm.ai/docs/routing，已验证）；
- Higress AI 网关：模型负载均衡 + Fallback 降级（来源：Higress 文档，已验证）；
- OpenRouter：Provider Routing 按成本/可用性选供应商（来源：openrouter.ai 文档索引，已验证）。

### 5.2 健康检查与故障转移

**实现要点**：探活（心跳/健康端点）、失败计数与冷却摘除、模型级与供应商级两级回退、重试策略（固定 + 指数退避）。

**案例**：OpenRouter Model Fallbacks（模型间自动故障转移，已验证）；LiteLLM 的冷却 + 指数退避重试（已验证）；第三方中转站以多家上游互为备份做故障转移。

### 5.3 限流与配额管理

**实现要点**：按 API Key / 租户 / 模型维度限流；tpm（token 每分钟）与 rpm（请求每分钟）配额；配额扣减批量更新以缓解数据库压力。

**案例**：LiteLLM 生产环境用 Redis 跟踪 tpm/rpm 限额（已验证）；one-api 系列令牌体系承载配额与额度扣减（已验证数据模型，批量更新机制为一般认知）。

### 5.4 KV 缓存与推理加速

**实现要点**：前缀缓存（prefix caching）复用公共前缀的 KV Cache 降低 TTFT 与成本；PagedAttention 类分页显存管理；连续批处理提升吞吐；冷启动优化（近 GPU 存储预加载、分层缓存）。

**案例**：
- 硅基流动定价页"缓存命中"单独计价，是 KV Cache 缓存进入商业定价的直接证据（已验证）；
- vLLM 前缀缓存（prefix cache）显著降低重复前缀请求 TTFT；压测需区分缓存命中与冷启动基线【摘要：discuss.vllm.ai】；
- ServerlessLLM（arXiv 2401.14351，已读）：利用"近 GPU"存储与内存、模型加载调度器降低 serverless 推理冷启动延迟；
- 寒武纪 vllm-mlu 支持 Chunk Prefill、Prefix Caching、Spec Decode、Graph Mode、Sleep Mode 等 vLLM 原生特性（已验证）。

### 5.5 计费与对账

**实现要点**：按 token（输入/输出/缓存命中分别计价）、按 GPU 秒/小时、按次/按张（图像）多维度计量；阶梯价、分时价、批量价、预留价（TPM 保障/Provisioned Throughput）等精细化定价；密钥级花费跟踪与用量对账。

**案例**：Fireworks 按 GPU 秒计费（已验证）；阿里云百炼阶梯计费 + 缓存折扣（已验证）；硅基流动分时定价（已验证）；LiteLLM 虚拟密钥跟踪花费（已验证）；OpenRouter Stripe Projects 面向应用内嵌计费（已验证）。

### 5.6 算力池化与调度层（补充）

**实现要点**：K8s 上以扩展资源暴露 GPU（如 `nvidia.com/gpu`）【一般认知，未验证】；常驻算力池 + 弹性伸缩（RayCluster 一次创建多次复用、Autoscaler 按逻辑资源请求扩缩、空闲缩容 idleTimeoutSeconds 默认 60s）【来源：docs.ray.io，已验证】；引擎级多卡配置（TGI 的 MASTER_PORT 等环境变量）【来源：HF TGI 文档，已验证】；异构算力统一调度（openEuler 25.09 的 prefill 在 GPU / decode 在 CPU 协同）【摘要】。

**关键研究证据**（arXiv 2508.20274《Predictable LLM Serving on GPU Clusters》，Harvard/MIT/Northeastern/UCSD，已读）：共享集群"噪声邻居"争用 PCIe 带宽导致推理尾延迟膨胀；动态 MIG 重配置 + PCIe 感知放置 + 轻量护栏方案使 SLO miss-rate 降低约 32%、p99 延迟改善约 15%、吞吐代价 ≤5%。

**国产化进展**（已验证）：寒武纪 vllm-mlu（Apache-2.0，基于 vLLM 插件系统，仅支持 MLU370 及以上，依赖寒武纪 SDK）；2026-04-24 完成 DeepSeek-V4（285B flash / 1.6T pro）day0 适配并开源【来源：新浪财经，已读】。

## 六、商业模式与市场现状

### 6.1 典型模式（来源：CSDN《Token 中转站这门生意》等，已读）

| 模式 | 代表 | 价值主张 | 目标客群 |
|---|---|---|---|
| 开发者优先的统一路由 | OpenRouter | 一个 API Key 访问数百个模型，按用量付费 | 开发者、独立应用 |
| 企业级托管/合规路线 | Azure OpenAI Service | 数据主权、SLA、合规认证、私有网络 | 合规敏感的大型企业 |
| 本地推理 | Ollama | 零 Token 成本、数据不出本地、OpenAI 兼容接口 | 实验/开发、数据敏感场景 |
| 灰色第三方中转 | 各类个人中转站 | 超低价引流（低至 1 元）、"比官方便宜 100 倍" | 个人用户、中小开发者 |

### 6.2 定价机制

- 按 token 为主流（输入/输出/缓存命中分离计价），叠加阶梯、分时、批量、预留等多维价格工具；
- 裸算力层按 GPU 秒/小时（Fireworks 明码标价 H100/B200/B300）；
- 市场正从"价格战"走向"价格分层 + 价值定价"【推断，基于多平台定价结构对比】。

### 6.3 风险与合规

- **合规与安全**：生成式 AI 内容合规责任、数据出境与隐私、模型权重与 KV Cache 的数据安全；
- **平台侧**：第三方中转站密钥泄露/倒卖、token 掺假、违反上游 ToS、服务质量不稳定；
- **基础设施侧**：多租户共享的性能隔离（噪声邻居）与安全隔离均需满足，公开资料多聚焦性能隔离，安全隔离工程实践披露较少【推断】。

### 6.4 市场趋势（2025–2026）

- 赛道升温：OpenRouter 完成 1.13 亿美元 B 轮融资、估值达 13 亿美元【来源：新闻报道，已读】；国内猎豹移动、网易有道等相继入局【摘要】；
- 灰色中转站乱象被媒体集中曝光，监管与平台治理压力上升；
- 企业级需求从"便宜"转向"可预测 + 合规 + SLA"，预留吞吐/专享推理/裸算力分层供给出现（Together、Fireworks、火山方舟 TPM 保障包）；
- 推理加速与缓存（KV Cache、前缀缓存、连续批处理）成为降本核心杠杆，缓存命中计价进入主流定价体系。

## 七、总结与趋势判断

**总结**：

1. **算力池两种实现路线并存**：纯聚合中转型（OpenRouter）轻资产、靠路由与计费聚合获利；自建算力型（Together、Fireworks、DeepInfra、硅基流动等）重资产、靠 GPU 集群 + Serverless 层赚取推理毛利。国内官方平台与第三方中转站叠加开源网关形成三层生态。
2. **技术栈已趋同**：统一 OpenAI 兼容 API + 渠道抽象 + 令牌配额 + 按量计费 + 路由/回退/冷却，是网关层的标准配置；引擎层以前缀缓存、连续批处理、分页显存管理为核心降本手段。
3. **计费体系精细化**：按 token（含缓存命中价、分时价、阶梯价）→ 预留吞吐/TPM 保障 → 按 GPU 秒/小时，形成从开发者到重负载客户的分层定价。
4. **可观测性与合规成为分水岭**：trace 广播、密钥级花费跟踪、企业级 SLA 与数据主权，正在把"中转生意"区分为合规平台与灰色中转。

**趋势判断**：

1. **从价格战走向价值分层**：单纯差价套利空间被官方降价与缓存折扣压缩，平台将更多以路由质量、可观测性、SLA、合规能力竞争【推断】。
2. **缓存与推理加速是下一轮降本主战场**：前缀缓存、分页 KV Cache、连续批处理、异构协同（GPU/NPU、prefill/decode 分流）将决定单位成本线【基于已验证事实的推断】。
3. **可预测性成为企业采用门槛**：共享集群噪声邻居、尾延迟抖动是可预测性研究的核心痛点（arXiv 2508.20274），预留型与专享型供给会持续增长【已验证 + 推断】。
4. **国产算力池加速成熟**：寒武纪 vllm-mlu 已完成 DeepSeek-V4 系列 day0 适配并开源，昇腾、摩尔线程适配仍在推进，国产化方案将从"能跑"走向"可调度、可计量、可计费"【已验证 + 推断】。
5. **监管趋严，灰色中转承压**：低价引流、token 掺假、密钥倒卖被集中曝光后，合规成本上升，生态将向官方平台、合规网关与开源自建收敛【推断】。
