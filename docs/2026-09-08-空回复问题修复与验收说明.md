# Eva 空回复问题修复与验收说明

日期：2026-09-08  
版本：0.1.190

## 1. 本次现象

使用 `deepseek-v4-flash` 进行普通对话或多智能体任务时，界面可能先显示已有对话内容，随后提示：

> Model deepseek-v4-flash returned an empty response.

在多智能体场景中，还可能出现工具已经执行，但最终汇总没有正文的情况。

## 2. 确认的根因

问题不是简单的工具权限错误，也不是所有工具都执行失败，而是 Agent 与 OpenAI 兼容网关之间存在两个协议边界问题：

1. 思考模式下，模型的 `reasoning_content` 和可见回答共用输出额度。原先固定的 2048 输出上限可能被推理内容消耗，导致最终 `content` 为空。
2. 工具完成后，Eva 把原生 `assistant.tool_calls + tool` 交易直接带入无工具的最终汇总请求。一些 DeepSeek 兼容网关在这个上下文切换处会返回空消息。
3. DeepSeek 思考模式的工具后续请求要求回传上一轮 assistant 的 `reasoning_content`，旧链路没有完整回传。

## 3. 修复内容

- 工具执行阶段继续使用原生结构化工具协议。
- 最终汇总阶段将已完成工具结果压平成明确的“已完成工具证据”文本，不再把原生工具协议交给无工具汇总请求。
- assistant 消息支持保存并回传 `reasoning_content`，兼容 DeepSeek 思考模式的多轮工具调用要求。
- 普通模型单次输出预算调整为 4096；支持思考的模型调整为 8192，避免推理耗尽可见回答额度。
- 最终汇总为空时只做受限的纯文本恢复，不会重复执行已完成工具。
- 增加回归测试，覆盖“工具成功、首次汇总为空、恢复回答成功”场景。

## 4. 验证结果

- 完整测试：70 个测试文件、324 项测试全部通过。
- 生产构建：`npm run build` 通过。
- 新增验证：最终汇总请求不再携带 `tool` 消息或 `tool_calls` 协议记录。

## 5. 使用注意

源码启动时需要完全退出旧的 Electron/Eva 进程，再重新运行 `npm run dev`，否则界面可能仍使用旧的主进程代码。

如果重启后仍然空回复，说明当前模型/网关连续没有返回可见正文，Eva 会保留工具证据并明确报错；这时应检查该连接的模型 ID、思考模式兼容性、网关额度和上游服务状态。
