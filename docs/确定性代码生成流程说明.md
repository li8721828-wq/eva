# Eva 确定性代码生成流程说明

## 1. 范围

本文描述 Eva 当前 `/coding` 命令实际执行的代码生成流程。

`/coding` 是 RMSD 流水线的最后阶段，只接受已经通过 `/dsl` 生成的最终领域 DSL 文件。进入本阶段后，不调用大模型、不请求模型供应商 API，也不读取对话内容作为业务输入；结果完全由固定的 DSL 文件、确定性转换脚本和本地工具链决定。

```text
/requirement -> /requirement-modeling -> /spec -> /dsl -> /coding
                                                   ^        ^
                                            最终 DSL 输入   无 AI
```

## 2. 前置条件

执行 `/coding` 前必须同时满足：

1. 当前对话已绑定具体项目工作区。
2. 当前工作区存在状态为 `ready-for-implementation` 的 RMSD 运行。
3. DSL 阶段状态为 `ready`，且存在最终文件 `dsl/output/domain-language.dsl`。
4. 项目根目录存在 `code-production-pipeline`。
5. 本机可以执行 `python.exe`（非 Windows 使用 `python3`）、所需 YAML 依赖、`javac` 和 `java`。

若 DSL 中不存在至少一个 `entity <Name> { ... }` 块，解析和生成会失败。未确认的业务事实必须在 DSL 中显式标记为 `OPEN`，不能在本阶段猜测补齐。

## 3. 调用链

主入口位于 `RequirementEngineeringService.buildCoding()`：

```text
buildCoding()
  -> 查找当前工作区已通过 Spec 且 DSL 已完成的运行
  -> 校验已有内容寻址生成包是否可复用
  -> buildCodingInternal()
       -> finalDslPath()
       -> parseDomainDsl()
       -> writeSemanticDslPackage()
       -> validate_semantic_dsl.py
       -> dsl_to_generation_ir.py
       -> validate_generation_ir.py
       -> generic_semantic_java_adapter.py
       -> verify_generic_semantic_java_output.py
```

代码位置：[requirement-engineering-service.ts](../src/main/services/requirement-engineering-service.ts)。

## 4. 输入与目录

每个需求拥有一个项目内 RMSD 包：

```text
<workspace>/.eva/RMSD/<需求名称>/
  dsl/
    output/
      domain-language.dsl
  coding/
    upstream/
    intermediate/
    output/
```

`/coding` 会首先将最终 DSL 精确复制到 `coding/upstream/domain-language.dsl`。该文件是代码生成的业务输入快照，用于审计，不会被生成过程修改。

## 5. 确定性转换步骤

### 5.1 DSL 哈希与幂等性

程序读取 `dsl/output/domain-language.dsl` 后，计算其 SHA-256：

```text
<DSL 文本> -> SHA-256 -> <dslHash>
```

相同的 DSL 文本始终使用同一个 `<dslHash>`。若相同哈希目录下的 `codegen-manifest.json` 状态为 `completed`，并且记录的输入哈希一致，`/coding` 不重新生成，直接复用已验证产物。

### 5.2 语义 DSL 包

`parseDomainDsl()` 将稳定 DSL 语法解析为领域、聚合、字段与规则。`writeSemanticDslPackage()` 产出语义 DSL 包，供后续校验和 IR 转换使用。

主要内容包括：

- `dsl-manifest.yaml`：输入哈希、版本和追溯信息。
- `domain.yaml`：领域与聚合定义。
- `state-machine.yaml`、`rules.yaml`：状态与规则信息。
- `authorization.yaml`、`integration.yaml`：确定性生成边界。
- `generation-map.yaml`：DSL 标识与生成目标的映射。

随后执行 `validate_semantic_dsl.py`。校验不通过时流程终止，不产生“成功”的代码输出。

### 5.3 生成 IR

`dsl_to_generation_ir.py` 将语义 DSL 转换为 `generation-ir.yaml`，随后由 `validate_generation_ir.py` 校验。IR 明确记录目标模型、输入追溯和生成意图，是 Java 适配器的唯一结构化输入。

### 5.4 Java 参考代码生成与验证

`generic_semantic_java_adapter.py` 从已校验的 IR 生成隔离 Java 包。之后 `verify_generic_semantic_java_output.py` 对生成结果执行结构检查、编译和生成的契约测试验证。

当前适配器输出的是参考性、隔离的 Java 包，不会直接写入或覆盖业务模块。生产合入仍需要已审批的物理目标模型和独立交付流程。

## 6. 产物规范

```text
<workspace>/.eva/RMSD/<需求名称>/coding/
  ARTIFACT-CONTRACT.md
  upstream/
    domain-language.dsl
  intermediate/
    runs/<dslHash>/
      00-input/domain-language.dsl
      01-semantic-dsl/
        dsl-manifest.yaml
        domain.yaml
        state-machine.yaml
        rules.yaml
        authorization.yaml
        integration.yaml
        generation-map.yaml
      02-generation-ir/
        target-model.yaml
        generation-ir.yaml
  output/
    runs/<dslHash>/
      codegen-manifest.json
      03-generated-code/
        generation-result.yaml
        src/main/java/...
        src/test/java/...
      04-verification/
        verification.md
```

目录职责：

| 目录 | 内容 | 下游使用规则 |
| --- | --- | --- |
| `upstream` | 来自 DSL 阶段最终输出的不可变快照 | 审计与重现输入。 |
| `intermediate` | 解析结果、语义 DSL、目标模型与生成 IR | 仅供当前代码生成步骤和调试使用。 |
| `output` | 生成代码、最终清单和验证报告 | 对外可交付产物；相同 DSL 可直接复用。 |

所有 Markdown、JSON、YAML 与 DSL 文件使用 UTF-8。`codegen-manifest.json` 至少记录输入 DSL 路径、SHA-256、输出目录、使用的适配器及完成状态；验证报告必须记录每个本地校验命令的结果。

## 7. 失败与恢复

失败时，已经写入的 `upstream` 和 `intermediate` 文件会保留，用于定位问题；`codingStatus` 标记为 `failed`。修正 DSL 后再次执行 `/coding` 会生成新的哈希目录，不覆盖旧运行。

常见问题：

| 现象 | 处理方式 |
| --- | --- |
| 没有已完成 DSL | 回到 `/dsl`，确认 `dsl/output/domain-language.dsl` 已生成。 |
| 找不到 Python、JDK 或管线脚本 | 检查项目 `code-production-pipeline` 以及本地 Python、YAML 依赖、`javac`、`java`。 |
| 语义 DSL 或 IR 校验失败 | 查看 `coding/intermediate/runs/<dslHash>/` 中的输入与 IR，修正上游 DSL 后重新生成。 |
| Java 验证失败 | 查看 `coding/output/runs/<dslHash>/04-verification/verification.md` 和 `generation-result.yaml`。 |

## 8. 不变性保证

1. DSL 相同，输入哈希相同，输出目录相同。
2. 已完成且哈希一致的生成包不会被重写。
3. DSL 改动会产生新的哈希目录，旧产物保留可审计。
4. `/coding` 后不存在模型调用，代码内容不由模型随机输出决定。
5. 代码生成只写入 `.eva/RMSD/<需求名称>/coding/`，不会直接改动业务源码目录。
