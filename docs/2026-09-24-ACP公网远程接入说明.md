# ACP 公网远程接入与 Cloudflare Tunnel

Eva 的 ACP 远程模式使用 HTTPS/WSS。你可以让 Eva 自己终止 HTTPS，也可以让 Cloudflare Tunnel/反向代理终止 HTTPS。后者保持 Eva 监听 `127.0.0.1`，不需要在电脑上配置证书。

## Eva 设置

在“设置 → App Server”中填写（Cloudflare Tunnel 推荐这一组）：

- 监听地址：`127.0.0.1`。
- 固定端口：建议 `8787`。
- 公网 HTTPS 基址：例如 `https://eva.example.com`，不要加 `/acp`。
- TLS 证书路径、TLS 私钥路径：留空。Cloudflare Tunnel 在公网侧终止 TLS。
- ACP Bearer Token：保持开启。远程模式会强制开启。
- Eva 启动时自动启动 App Server：开启。

Cloudflare Tunnel 的 Public Hostname 服务指向：

```text
http://127.0.0.1:8787
```

如果不使用隧道而让 Eva 自己直接监听公网，则改用 `0.0.0.0`，并填写证书和私钥。

本项目当前使用的域名示例是 `www.broccolitrue.cloud`。对应配置为：

```text
公网 HTTPS 基址：https://www.broccolitrue.cloud
手机 ACP 地址：wss://www.broccolitrue.cloud/acp
Tunnel Service URL：http://127.0.0.1:8787
```

保存后重启 App Server。运行状态中的 ACP 地址应显示为：

```text
wss://eva.example.com/acp
```

## 公网网络配置

在路由器、防火墙或云主机反向代理中，将公网 HTTPS 端口转发到 Eva 所在电脑的 App Server 端口。域名证书必须覆盖手机使用的域名；公网端口可以是 `443`，转发到本机的 `8787`。

不要把明文 `ws://` 直接暴露到互联网。远程模式没有证书时会拒绝启动。

## 手机 ACP 客户端

选择 WebSocket/ACP 连接，填写：

- 地址：`wss://eva.example.com/acp`
- Bearer Token：Eva 设置页显示的 Token 原文；如果客户端要求请求头，使用 `Authorization: Bearer <token>`。
- 工作区：电脑上的路径，例如 `D:\\桌面\\agent_teams\\eva`。

`session/new`、`session/prompt`、工具执行和权限审批都由 Eva 处理。手机端不需要提供 `fs/*` 或 `terminal/*` 能力，也不需要配置 MCP server。

## 连通性测试

可以用仓库内的 ACP smoke client 测试公网地址：

```powershell
node scripts/acp-smoke.mjs --url wss://eva.example.com/acp --token YOUR_TOKEN --cwd D:\\桌面\\agent_teams\\eva --approve
```

公网入口必须同时满足路由器/防火墙转发、域名解析、TLS 证书和 Bearer Token 四项条件；ACP 协议本身不负责 NAT 穿透或公网中继。

Cloudflare 页面出现 `502 Host Error` 时，优先检查 Eva 的 App Server 是否正在运行，以及 Tunnel 的 Service URL 是否指向 `http://127.0.0.1:8787`。域名根路径不是 Eva 的网页首页；可以使用带 Token 的 `/health` 请求验证源服务：

```powershell
curl.exe -H "Authorization: Bearer 你的Token" https://www.broccolitrue.cloud/health
```
