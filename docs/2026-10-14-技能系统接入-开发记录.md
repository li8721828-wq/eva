## 一、背景：Eva 原有四条能力通道，缺「本地指令包」

| 既有通道 | 位置 | 今天的缺口 |
|---|---|---|
| Plugin（搜索源等） | `storage/plugin-store.ts` | 只有内置工具开关，不能装自定义指令 |
| MCP server | `mcp-server-store.ts` + `mcp-client-manager.ts:81,110` | 客户端只调 `listTools` / `callTool`，**MCP prompts 至今没有对外暴露** |
| 环境规则 | `environment-profile-service.ts:66-76` | 一段自由文本，没有按需取回的粒度 |
| 长期记忆 | 召回通道 | 被动召回，不由用户显式安装 |

今天补上第五条：用户在磁盘上放「目录 + 目录内 `SKILL.md`」，Eva 扫描出来、在 system prompt 里常驻一份**只含名字与一行描述的目录**，模型判断命中时用新工具 `load_skill` 按精确名把正文取回**工具结果**。技能不执行任何代码。

## 二、磁盘形态与作用域

- 两条根（`skill-service.ts:42-48`）：项目级 `<workspace>/.eva/skills`（随仓库走）与全局级 `<userData>/skills`（`globalSkillsRoot()`；`app.getPath` 不可用的隔离测试环境回落到 `~/.eva/skills`）。占位/non-absolute `workspacePath` 只得到全局根，不去拼接无意义路径。
- 只认「目录 + 目录内 `SKILL.md`」，根下的散 `.md` 一律忽略；`node_modules`、`__pycache__` 目录跳过（`:22`）。
- **同名时项目覆盖全局**（先扫 project，`claimed` 集合去重），目录里不会出现两行。
- 扫描时对每个根与目录做 `fs.realpath`；根不存在必须 `catch` 成空清单而不抛（`ipc/agent.ts` 会传占位串）。
- 非法 `SKILL.md` 只降级成诊断（`SkillInventory.diagnostics`），不得让扫描抛错：缺围栏、缺 `name`/`description`、`name` 与目录名不符、非 slug 名字、description 超 180 字、正文超 `MAX_SKILL_BODY_CHARS = 40_000`（`:15`）、单文件超 `MAX_SKILL_FILE_CHARS = 60_000`（`:17`）、文件读不出——都由设置页红字写出原因。
- 扫描保持**同步 + 60 秒 TTL 缓存**（`CACHE_TTL_MS`，`:21`），不上 `fs.watch`：`buildSystemPrompt` 与上游 `buildMessages` 是同步的，改异步要牵动 6 处调用点并让 app-server/ACP、Goal、Symposium 各传输路径重新对齐；对任意用户目录挂监听是主进程泄漏源。开关与「重新扫描」显式失效缓存。

## 三、两段式披露：目录常驻，正文按需

`context.ts:493-506` 在 Environment 段之后、Available Tools 段之前插入目录：

- 常驻的只有 `--- Available Skills ---` 下每技能一行 `- <name>: <description>`，**正文绝不拼进 system prompt**。
- 提示词头部固定两句约束（`skill-service.ts:26-28`）：「the catalog line alone is not the instruction」与「Skills never execute code, and never say a skill was used unless `load_skill` returned its instructions」——防止模型把目录里的一行描述当成已执行证据（本仓既有护栏：不得把模拟的模型推理当执行证据）。
- **token 预算是真上限**：`SKILL_CATALOG_MAX_TOKENS = 600`，逐行**整行**贪心累加、绝不半行截断；省略行 `(+N more skills available by exact name)` 的开销用 `SKILL_CATALOG_NOTE_RESERVE_TOKENS = 32` 在预算**内**预留（曾把它加在循环之外，30 个长描述技能实测产出 612 > 600）。估算算法与环境规则共用 `ContextManager.estimateTokens`，不写第三份。
- **同一份磁盘状态必须产出逐字相同的目录**：技能按 name `localeCompare` 排序（`:91`）。提示词前缀不稳定会让供应商 prompt cache 失效，`tests/unit/skill-catalog-prompt.test.ts` 断言两次构建字节相同。

## 四、`load_skill`：整条通道的安全支点

- 参数只有 `{name, file?}`（`skill-tools.ts:11,19-21`），**永远不接受路径参数**；`name` 必须是目录里那个精确名字，多余参数（如注入 `path`）被忽略。`file` 也只能是该技能目录内的相对文件名。
- 作用域校验：加载时把 `file` 目标解析成 realpath，并用 `services/file-service.ts` 的 `isWithinRoot`（win32 上大小写不敏感）校验落在**该技能目录**内。一旦给它一个能填路径的参数，一个「只读指令包」就变成任意读文件入口——所以**不得**为了让全局技能可读就往 `fileAccessGrants` 里合成 `userData/skills`，那等于让 `read_file` 顺着 `..` 摸到 `config.json` 与全部会话文件。
- 工具内部直接用 `fs` 是本仓既有做法（`browser-control-tools.ts`、`search-tools.ts`、`project-index-tools.ts`、`web-tools.ts`），前提是作用域来自已枚举出的技能目录而不是外部入参。

## 九、使用注意与遗留事项

1. **未提交**：与工作区里今日的弹窗修复、联网兜底混在一起，提交时应按主题拆分。
2. **指令遵循度不由这套机制保证**。两段式披露只保证「取得到」：真机那一轮模型读完技能与附带文件后**没有逐字复现技能里写的那句口令**。
3. **正文只进工具结果**，会随窗口老化被压缩：`OLD_TOOL_RESULT_MAX_CHARS = 300`（`context.ts:13,173`）会压掉滑出近期窗口的工具结果。设计上是靠「目录常驻 + 重新加载幂等且便宜」兜住，不要为此把正文改成常驻。
4. **规模上限按个位数技能设计**。同步扫描的代价是单个工作区每 60 秒第一次构建提示词要承担一次目录读；若放几百个技能，`readdir` 与 `estimateTokens` 成本会一起上来，且 600 token 预算之外只剩「(+N more by exact name)」一行提示可用。
5. **本轮新加的对账棘轮查出 4 个历史缺口**：`create_runtime_proposal`、`manage_personal_preferences`、`open_terminal`、`close_terminal` 未登记在审批分类里，在 `safe` 档下静默免审批。它们被写进 `tests/unit/tool-catalog.test.ts` 的 `legacyUnclassified` 清单（**只许减不许增**，补一个删一个），本轮**没有改它们的审批行为**（超出批准范围），要不要补登记待定。
6. **技能不与 MCP prompts 互导**（今天 MCP prompts 根本没被暴露），也不复用环境规则或长期记忆的召回通道；`ProjectKnowledgeStore.buildContext` 现存唯一调用者是它自己的单测，**不得**为技能系统复活它，否则会形成第二条注入路径。
7. 未做 dark/starlight 目检（设置页新面板沿用既有面板语言）；技能根路径对用户不直观，目前靠「打开文件夹」按钮暴露。
