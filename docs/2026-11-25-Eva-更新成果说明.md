## 二、聊天与工具展示

助手回复采用文档式排版，保留 Eva 原有画布。用户消息恢复原有透光渐变气泡、圆角和字重。聊天默认使用平台无衬线字体，显式字体及字号设置继续生效。

等待时显示灰色转圈和“正在回复…”。正文下方移除用量、耗时和费用入口；相关原始统计仍保存，其他统计与诊断页面继续使用。已完成回复提供复制、重新生成、引用和收藏图标，重新生成仍仅针对最新回复。

思考区只展示模型接口实际返回、由主进程标记来源的内容。接口没有返回时不补写内容，也不虚构思考耗时。旧的无来源材料与 SDK 内部推理不进入该展示区。明确选择的模型思考档位仍然优先。

工具按照“公开说明 → 相邻工具组 → 公开说明”的原始顺序呈现。每组默认折叠，可查看完整参数和反馈；报错、运行中、结果未确认均以真实状态为准。生成的图片保持可见。聊天中的原生会话接入、续接提示已隐藏。

代码框保留原始换行、语法高亮与复制。长代码默认按 24 行高度展示，可展开至 48 行高度后内部滚动。超长回复仍完整显示，但停用字级动画；系统启用减少动态效果时关闭淡入。

## 三、需求流程的修复与使用方式

### 1. 缺材料时先制作草稿

当前需求运行等待材料时，可以点击“模拟缺失材料，继续生成规格草稿”。在同一会话输入“材料你先进行模拟”“那你先模拟”等有限范围语句，也可进入这一操作。

系统只针对当前缺口生成一份模拟材料与规格草稿，不为此另开普通工具任务编写验算脚本。草稿登记到当前运行，卡片提供折叠查看入口。输入一致且文件校验通过时，可以复用已有草稿。

**模拟草稿与正式验收分开管理。**草稿不是业务方真实交付材料，不会自动清除真实待补项，也不会据此放行正式代码生成。补充真实资料后，原预览入口清除，按正式材料重新评测。

### 2. 已通过阶段的继续入口

- 需求已通过后，可点击“继续建模并生成规格”。
- 规格已通过后，可点击“继续生成 DSL 与代码”。
- 关键业务规则确认及上游产物校验继续保留，系统不会自动替用户确认。

本次提供的是明确的继续入口，尚未实现上传文件后无条件自动跑完整条生产流水线。

### 3. 减少等待与重复展示

初轮需求分析移除了一次对相同中间输入的无条件重复评测，最终需求仍进行独立放行审计。这减少了一次模型往返，不代表首轮分析已合并为单次请求，也没有给出固定耗时承诺。

完整中间文档继续落盘，聊天显示文档索引，进行中的文档默认收起。模拟请求失败时，错误保留在聊天提示区。

## 四、Harness 会话恢复修复

此前导入历史聊天时，用户参考消息可能先于 Harness 必须建立的系统首节点写入日志。首次运行可能正常，下一次恢复时出现 `SessionFormatError` 或 `protected first surface head` 错误。

修复后由 SDK 消息队列导入历史。旧导入协议的日志不改写、不删除，后续请求创建兼容的新代次，并使用完整 Eva 聊天作为明确标注的历史参考。旧代次的 SDK 内部检查点不被当成已经恢复，也不自动重跑过去的工具操作。

这次故障与需求草稿是否生成是两件独立的事情。遇到该旧格式问题，应先加载新版，再在原会话继续发送消息。

## 五、尚需继续改进的内容

用户进一步指出：需求输入阶段不应展开大量 DDL、SQL、接口、错误码和 JSON 契约工作。**这一阶段边界尚未完成下一轮代码调整。**当前模拟按钮仍将“模拟缺失材料”和“生成规格草稿”放在一起，容易让用户混淆当前所处阶段。

后续应优先处理：

1. 将业务需求确认、项目技术基线读取、技术设计和代码实现明确分层。
2. 将业务方必须决定的事项、AI 可从代码取得的资料、正式验收时才需交付的材料分别处理。
3. 进一步合并重复分析、细化按变更项复评及检查点恢复。
4. 统一流程状态卡和当前阶段指引，并核对右侧工作区的会话归属提示。
5. 将实际运行窗口是否加载新版纳入交付检查，避免源码已更新而旧窗口仍显示旧组件。

上述内容属于后续优化方向，不计为今天已经实现的能力。
