## 一、审查口径

1. 缺陷只收**有证据**的：复现测试、真机取证记录、或工程记忆里自认的边界；不收猜测性问题。
2. 数字一律当日重跑，不引用会话或旧文档里的快照。
3. 「已修」以 CHANGELOG 条目 + 回归守卫同时存在为准；只有 CHANGELOG 自述而没有守卫的，标为「已修但无钉」。

## 二、功能面逐项审查

### 1. 对话与回复链路

**现状**：流式逐字（自适应排空）、贴底跟随只能由用户手势解除、`done` 按 messageId 对账不重复追加、失败轮次落盘「未完成」提示并可原地重试、空回复带 `finish_reason` 与隐藏推理字符数可诊断、空回复重试与失败请求机械不同。

**强项**：9-21 至 9-24 的批量修复全部钉了回归守卫（REGRESSION-GUARDS「消息和滚动」节 20 余条），是全部功能面里守卫最密的一块。

**边界**：未发现活缺陷。

### 2. 执行过程可见性

**现状**：`plan`/`step` 结构化汇报是唯一传输方式；计划有门槛（≥3 个彼此独立的步骤才开）；打勾必须有据（`item="N"` 优先，越界计入 `overflowStepCount`）；无汇报的清单显示「未逐项汇报」而非 `0/N`；气泡与右侧便签渲染同一份派生清单；生命周期备注是瞬态行、不落盘；不展示模型私有思维链。

**强项**：「不伪造执行证据」是写进守卫的设计原则（禁止按工具调用条数自动打勾）。

**缺陷（设计层面，非 bug）**：计划状态是**荣誉制**——打勾靠模型自觉汇报，没有权威状态源；模型不汇报时清单静止，界面只能说「未逐项汇报」。这正是 Wave 2「计划形态」议题的动因（见改进计划 P1-1）。

### 3. 工具、审批与沙箱

**现状**：工具目录登记 29 个工具（`tool-catalog.ts` 当日实数）；沙箱按 run 隔离、无模块级单例；审批卡同会话串行、可豁免（按会话+类别记账）、取消信号贯通到在途命令；`execution-policy.ts` 统一装配，桌面/Goal/团队/App-Server/QQ 全入口显式注入。

**已证实缺陷**：

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 4 个历史工具不在审批名单，`safe` 档下静默免审批（`create_runtime_proposal`、`manage_personal_preferences`、`open_terminal`、`close_terminal`） | `tool-catalog.test.ts` 的 `legacyUnclassified` 棘轮清单 | 未修，棘轮只减不增 |
| 审批/选择卡的 `isStreaming` 守卫缺陷**同类发生两次**（10-15 ask_user、10-16 tool_approval） | 两处复现测试 + 真机取证 | 已修并钉守卫；**其余 live 事件分支未逐个审计** |
| Windows 沙箱是 policy-only，无 AppContainer/操作系统级强隔离 | 10-19 CHANGELOG 自认边界 | 设计现状，未加固 |

### 4. 技能（Skill）系统

**现状**：目录常驻（名字+一行描述，600 token 真上限）+ `load_skill` 按名取回的两段披露；写盘只有 `write_skill_file` 一条通道，围栏逐字复用扫描器；「写得出的一定扫得到」（`checkSkillMarkdown` 共用）；`FileService` 沙箱刻意不为技能放宽。

**强项**：从「计划执行一步就不走」这条真机故障反推出的根因（技能正文把模型引向沙箱外的路径）已写成通用守卫：技能正文点名的工具必须是那条路径上真能用的工具。

**已证实缺陷**：`write_skill_file` 端到端**最后一环未真机验证**——「点批准 → 文件真落盘」被网关限流挡住（429 是整条连接冷却，报文 `Resets in 143h5m3s`）。前四环（模型改口调新工具、计划第一步不再撞墙、审批事件送达、60 秒自动拒绝）已证。

### 5. 任务主线与交接（10-21 新增）

**现状**：主线存项目内 `.eva/purposes/<uuid>.json`，可随 Git 移交；AI 起草只填表单草稿、不动工具不落盘；里程碑完成必须人工填验证依据；交接带代码指纹，接手复检 revision；公开进度由受审批的 `record_purpose_progress` 写入。

**强项**：边界画得清楚——交接不含原始聊天、思维链、个人记忆与本地授权；AI 不能替人验收。

**未验收边界**：真实双人 Git 交接未演练；无在线同步、跨机器任务租约、补丁移交；本机写锁不代表跨机器租约（均为 10-21 文档自认）。

### 6. 界面与设置

**现状**：三档表面语言（悬浮/描边分组/贴边）已成文并铺满 Settings；`eva-lift` 只在 hover 时应答；Dialog/Select 统一 floating-layer 且 portal 到 body；三套主题；`npm run verify:ui` 用隔离 Electron 用户目录跑真实组件截图。

**强项**：多轮截图反馈闭环沉淀成了可执行的 CSS 守卫（特异性、出血、portal 都有守测），这类「目检判负」缺陷的复发成本高。

**边界**：历史页面仍有未迁移文案与英文残留（10-21 自认）；`verify:ui` 是夹具验证，不等于真实模型驱动的端到端。

### 7. 模型连接与对外接口

**现状**：模型连接支持手填精确模型 ID（不依赖 `/models` 列表）；能不能收图由能力档案 `supportsImageInput` 判定、不写模型名白名单；App-Server 默认只绑 127.0.0.1，远程模式强制 HTTPS + Bearer，`Origin` 头判别浏览器客户端；ACP v1 门面（手机终端可驱动）；QQ 机器人接入；联网搜索主源为原生 Windows 版 SearXNG + DDG 无密钥兜底。

**已证实缺陷/边界**：

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 网关 429 的 `retryAfterMs` 可以是天数级（实测约 6 天），Eva 原样遵守 → 「限流后自动重试」在这类供应商上等于不可用 | 10-16 真机 dev 日志 | 未修，策略议题 |
| QQ 连接整改后未用真实账号验收 | 10-20/10-21 文档自认 | 未验收 |
| `bing-*` 搜索源返回降级内容，不能当唯一兜底 | 10-14 实测 | 已隔离出候选链 |
| `filterSearchResultsForRelevance` 对短查询是空操作 | REGRESSION-GUARDS 自认 | 设计现状 |
| 原生 SearXNG 依赖一个**未推送的本地提交**（`28381ce`，`valkeydb.py` 的 `pwd` 容错），重克隆/`git clean -fdx` 会毁掉运行环境 | 10-14 CHANGELOG 维护要点 | 脆弱点在位 |

### 8. 存储与长运行稳定性

**现状**：任务、运行内核、长期记忆、记忆队列、活动计划等 JSON 全部走临时文件+重命名的原子写入，Windows 文件锁有界重试；退出统一清理（含 `stopAppServer`）；自动启动与检查点齐备。

**已证实缺陷**：dev 日志复现 `MaxListenersExceededWarning: 11 abort listeners added to [AbortSignal]`——有 listener 泄漏，未定位（10-16 CHANGELOG 剩余风险④，当日仍未修）。

## 三、汇总：活故障 / 未验收 / 已修无钉

**活故障（有证据、未修）**：
1. `write_skill_file` 批准→落盘一环未验（被环境挡住，代码路径+14 项单测已绿）。
2. 4 个历史工具游离在审批名单外。
3. `MaxListenersExceededWarning` 泄漏未定位。

**未验收（功能在、没验过真环境）**：QQ 真实账号、真实双人主线交接、macOS/Linux 终端路径、真实模型账号下的 AI 起草质量。

**已修但靠自觉（无守卫或守卫不全）**：其余 live 事件分支是否还残留 `isStreaming` 类闸门未逐个审计；429 退避策略未动。

**总体评价**：回复链路与界面两块经过 9 月至今的多轮修复，守卫密度高、复发成本高；执行层（工具/审批/终端）在 10-19/20 一轮整改后结构性问题基本清零，剩下的是「名单缺口」和「环境未验」这类可枚举的收尾项；真正的开放设计议题只剩两个——计划的权威状态源、跨机器的主线协作。
