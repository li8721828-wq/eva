# Eva 统一长期记忆架构

## 目标

Eva 将长期记忆统一为一个本地 Store，同时保留两种作用域：

- `user`：跨项目的用户偏好、沟通方式和工作习惯。
- `project`：当前工作区的架构决策、工程事实、缺陷、约束和回归守则。

会话原文、工具历史和运行过程仍然属于短期上下文或运行记录，不会自动等同于长期记忆。

## 运行链路

```text
主 Agent
  -> 完成用户任务
  -> 生成受限 MemoryEvent
  -> 立即返回用户

MemoryAgentService
  -> 写入本地持久化队列
  -> 后台串行消费事件
  -> 调用无工具的记忆模型
  -> 判断是否值得保存
  -> 判断 user/project 作用域
  -> 去重、补充证据或标记旧记忆 superseded
  -> 写入 long-term-memory.json，成功后移除队列记录
```

主 Agent 不等待 Memory Agent，也不承担记忆整理职责。记忆写入失败只记录警告并保留队列记录，不影响用户任务结果；应用重启后会恢复未完成事件，最多重试三次。

## 数据模型

统一记录位于 `LongTermMemoryStore`，每条记录包含：

- `scope` / `scopeId`：作用域和隔离边界。
- `kind`：偏好、决策、事实、缺陷、工作流或约束。
- `confidence` / `importance`：召回和治理时使用的质量信号。
- `evidence`：来源会话、消息和简短证据。
- `status`：自动发现的候选默认为 `pending`，用户确认后变为 `active`，也可标记为 `rejected`、`superseded` 或 `archived`。

存储文件：

```text
Electron userData/long-term-memory.json
Electron userData/memory-agent-queue.json
```

## 召回规则

主 Agent 在普通聊天、Goal/Team、QQ 远程和本地 App Server 请求前，按当前请求检索：

1. 默认用户作用域 `user:default`。
2. 当前工作区的 `workspace:<id>` 或 `workspace-path:<path>`。
3. 关键词命中、标题加权、作用域优先级、置信度、重要性和最近使用情况排序。
4. 仅注入有限条数和有限字符数。

召回内容被标记为参考资料，不能覆盖当前用户请求，也不能作为授权或未经验证的当前事实。

## 兼容与迁移

首次启动时，Eva 会把旧的个人偏好和项目工程知识迁移到统一 Store。现有设置面板和显式偏好工具继续保留，以兼容旧数据和用户操作；新的自动长期记忆由 `MemoryAgentService` 统一负责。

`RuntimeMemoryStore` 继续承担运行结果和短期任务记录，但不再作为普通聊天的长期记忆注入来源。

## 当前边界

- 召回目前是本地关键词检索，不是 embedding 向量检索。
- Memory Agent 使用当前有效模型连接，不调用工具。
- 普通回合会自动产生 MemoryEvent；后续可把独立 Goal/Team 最终结果也统一提交为 MemoryEvent。
- 自动学习候选需要在记忆仪表盘中确认后才会参与召回；显式用户偏好仍可直接写入 active 状态。
