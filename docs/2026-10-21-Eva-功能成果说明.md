## 一、项目任务主线：让工作可以接着做

新增任务主线（Purpose）。一条主线保存一个长期目标，可以关联项目中的多个会话，不随单次聊天结束而丢失。

主线包含以下内容：

| 内容 | 用途 |
| --- | --- |
| 目标、范围与约束 | 明确要解决什么问题、哪些内容属于本次任务 |
| 验收标准与里程碑 | 拆分阶段工作，明确完成依据 |
| 决策与发现 | 保留关键选择、限制和待确认事项 |
| 公开进度与执行记录 | 记录工作进展、工具结果状态和步骤状态 |
| 交接记录与下一步 | 帮助另一位同事或新的 AI 会话继续推进 |

可以从项目名称旁的主线图标、聊天标题栏的「项目主线」，或右侧辅助栏的「主线」进入。主线支持展开到主工作区，查看和编辑长内容更方便。

主线文件保存在项目的 `.eva/purposes/` 中，可以随代码通过 Git 移交。接手者不需要拥有原来的本地会话记录，也能读取目标和交接信息。

### 推荐使用流程

1. 为项目新建主线，填写目标、验收标准和里程碑。
2. 将当前项目会话关联到主线，在会话中正常开展工作。
3. 持续记录公开进度、关键发现、阻塞和下一步；核实后填写里程碑验证依据。
4. 交接前停止相关任务，记录已完成内容、待核实事项和后续行动。
5. 将代码和主线 JSON 一起提交、推送，或完整移交给接手者。
6. 接手者打开项目，检查交接条件，核对代码状态，再选择「在新会话继续」。

继续工作会使用接手者本地的模型配置，下一步先进入输入框，由接手者发送。代码状态变化或无法核实时，界面会提示复核。

AI 可以记录公开进度和待核实结论；里程碑完成和整条主线验收仍需人工填写依据。工具执行成功本身不代表业务已经验收通过。

## 二、AI 可以辅助填写新主线

新建主线时，点击「让 AI 起草」，输入简短需求，再点击「AI 分析并填入」，即可生成名称、目标、范围、验收标准和里程碑。

- 使用当前选择的模型；「参考当前会话」默认关闭，勾选后仅引用同项目会话的有限公开文本。
- 生成内容可以直接修改，也可以「撤回填入」恢复原表单。
- 假设和待确认问题单独列为规划备注，用户保存后进入主线的「决策与发现」。
- 失败、取消或超时保留原表单，取消后的迟到回复不会覆盖已有内容。
- 用户点击保存后才建立主线，生成过程本身不执行工具或改写已有主线。

这项能力用于起草计划。它使用的缓存索引信息不等于已经阅读完整源码，生成的范围、步骤和验收标准仍需结合实际项目核对。

## 三、工作台和设置界面统一

本轮以清晰、简洁、柔和、便于操作为方向，保留既有三套主题，沿用成本中心和长期记忆页面中已认可的分组方式。

| 区域 | 调整后的表现 |
| --- | --- |
| 项目与聊天 | 聊天标题显示项目上下文，主线入口更容易找到 |
| 主线工作区 | 支持展开和收回；窗口缩放、切换展示方式时保留表单草稿和用户尺寸偏好 |
| 设置导航 | 分为「偏好与模型」「扩展与连接」「用量与诊断」，减少同时展示的项目 |
| 技能与服务 | 技能、插件、MCP 分区查看，内部调用链按需展开 |
| 布尔设置 | 统一开关样式，保留键盘、焦点和禁用操作语义 |
| 模型配置 | 突出当前连接，模型标签靠近名称；保存失败显示原因并保留修改 |
| 主题与文案 | 统一输入框、按钮、选中态和主要标题，修正深色主题下的部分底色和文字问题 |

工作台同时补齐了加载、失败、空记录三种状态。读取失败可以重试；切换项目或会话后，旧请求的迟到结果不会覆盖当前记录。所选项目与当前会话不一致时，会引导选择项目会话，避免混淆资料。

## 四、连接、费用和运行状态更准确

- **QQ 远程控制**：连接前检查项目和智能体是否仍然可用；失效选择显示重新选择提示，检查清单可以定位到对应字段。已知令牌缺失错误提供中文核对方向。
- **成本中心**：区分「尚未计价」和「真实零费用」。缺少价格时不再绘制虚假的零费用趋势；部分计价时说明覆盖范围和已知费用下限。
- **运行状态**：区分配置数量、当前执行和历史异常。「已启用连接」不再被表达为已经通过连通性检查。

QQ 的配置提示和连接前检查已经整改，但本轮未使用真实 QQ 账号验证连接，不能据此判断外部服务故障已修复。
