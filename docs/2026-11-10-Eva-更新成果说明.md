## 怎么使用新版流水线

1. 在项目会话执行 `/requirement`、`/requirement-modeling` 和 `/spec`。规格草稿通过检查后，在对话中确认关键规则与例外。金额门槛、双签或审批角色等关键条件会分别进入验收契约。
2. 执行 `/dsl java-domain`。例如，规格要求金额达到 10 万元即可提交，DSL 写成必须超过 10 万元时，Eva 会在发布 DSL 前给出错误。
3. 执行 `/coding`，生成 Java 17 Maven 领域模块。Eva 使用真实 JDK 编译并验证规则、状态变化和事件。已有旧版 Spec 的运行，可从 `/spec` 开始重新确认规则。
4. 如需接入现有 Maven 项目，在需求运行目录配置 `coding/host-target.json`。可以先用 `/verify-host preflight` 检查环境。生成通过后，用 `/verify-host` 预览补丁，再用 `/verify-host run` 在隔离副本中验证。补丁可从需求工作区打开。[配置示例与操作说明](确定性代码生成流程说明.md#宿主-maven-集成验收)

## 实际验证结果

- **订单审批宿主联测通过。** 两项宿主业务测试验证未双签订单会被拒绝、正常订单会把事件中的编号传给原保存入口。一项生成模块验收也通过。
- **PAC 领域模块通过，宿主验证受阻。** 物料属性调整的防重复审批规则已生成领域模块，通过 JDK 和独立 Maven 测试。PAC 项目仍缺 `fsm-sdk:1.0.0` 和 `xcerp-app-pac-index-builder:1.0.3`，私有仓库连接超时。PAC 自身的审批与持久化测试还需在依赖可用后执行。
- **Windows 源码启动复测通过。** 原快捷方式复测成功。0.1.217 使用独立数据目录实际打开窗口，也验证了配置加载失败会显示具体报错。用户最初遇到的退出未复现，现有 npm 日志只能确认退出码为 `1`。
