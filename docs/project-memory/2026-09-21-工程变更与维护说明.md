# 2026-09-21 工程变更与维护说明

## 1. 目的

本文件给后续维护 Agent 使用，记录本次工作区变更涉及的代码边界、验证结果和已知风险。它属于仓库工程记忆，不属于 Eva 运行时长期记忆。

## 2. 关键架构变化

### 对话执行链路

核心链路位于：

- `src/main/ipc/conversation.ts`
- `src/main/agent-engine/agent-runner.ts`
- `src/renderer/components/chat/MessageList.tsx`
- `src/renderer/components/chat/MessageBubble.tsx`
- `src/renderer/stores/use-chat-store.ts`

当前必须保持以下分层：

```text
持久化消息集合
  != 流式中的临时消息
  != MessageList 的虚拟滚动状态
  != 工具执行时间线
```

用户消息先持久化；AgentRunner 产生真实事件；renderer 在流式期间维护临时状态；最终 `done` 后再形成稳定的 assistant 消息。新请求通过 run token 使旧请求失效，旧请求不得继续写入新一轮结果。

### 输出展示链路

`MessageList` 负责消息和滚动，`MessageBubble` 负责单轮消息内容和工具活动展示，`markdown-display.ts` 负责 Markdown 清理和展示边界。

不可回退的约束：

- 工具活动区不能绑定最终回复正文的高度。
- 工具事件必须来自真实 `tool_call`/`tool_result` 或受限公开进展。
- 普通问题不能强制使用工程执行报告格式。
- 有工具执行时，未完成的最终 Markdown 必须隐藏到 `done`。
- 不能把模型私有思维链当作执行记录展示。

### 统一长期记忆链路

核心文件：

- `src/main/storage/long-term-memory-store.ts`
- `src/main/storage/memory-agent-queue-store.ts`
- `src/main/services/memory-agent-service.ts`
- `src/main/services/memory-sanitizer.ts`
- `src/main/ipc/long-term-memory.ts`
- `src/shared/types/long-term-memory.ts`
- `src/renderer/components/settings/LongTermMemoryPanel.tsx`

数据流：

```text
Chat/Task/App Server/QQ
  -> MemoryEvent
  -> memory-agent-queue.json
  -> MemoryAgentService 后台串行消费
  -> 无工具 Memory Agent
  -> long-term-memory.json
  -> 记忆仪表盘和下一轮上下文召回
```

用户级和项目级记忆共用 schema，但必须按 `scope` 和 `scopeId` 隔离。没有当前项目时，项目统计和项目召回都必须为空，不能回退为全库统计。

### 仓库工程记忆边界

`PROJECT_MEMORY.md`、`docs/project-memory/` 和运行时的 `long-term-memory.json` 是三类不同概念：

- 仓库工程记忆：给开发 Agent 读取，记录代码约束和回归风险。
- 用户长期记忆：跨项目的用户偏好和工作习惯。
- 项目长期记忆：当前工作区的架构、决策、缺陷和工作流。

不要把完整对话、密钥、模型私有思维链或原始工具日志写入仓库工程记忆。

## 5. 已知待处理风险

### 高优先级：终端权限边界

`src/main/tools/terminal-tools.ts` 当前以 `conversationId` 存在作为会话终端入口条件。需要继续确认并修正：

- workspace 和 granted-folders 会话不能因此获得任意 shell 能力。
- `cwd` 必须使用与文件工具相同的授权和 canonical path 校验。
- QQ/App Server 等无 renderer 入口也必须继承相同权限边界。
- “用户批准一次”只能代表批准当前具体操作，不能替代目录授权。

### 高优先级：跨会话 sandbox 上下文

`AgentRunner` 会在运行开始和结束时设置共享 `FileService`/`TerminalService` 的 sandbox context。多个会话并行时可能出现上下文覆盖或提前清理。后续应改为按调用或按会话传递上下文，不能依赖进程级可变全局状态。

### 中高优先级：搜索路径和链接

`src/main/tools/search-tools.ts` 的授权检查目前主要基于词法路径。需要与 `FileService` 的 canonical path 规则统一，并明确是否禁止遍历 symlink/junction，尤其是 Windows reparse point。

### 中高优先级：PTY 命令完成与超时

`src/main/services/terminal-service.ts` 的 Windows PTY 完成标记当前更接近“看到提示符即完成”，未可靠携带命令退出码；超时后也可能留下仍在运行的 shell 命令。后续需要增加唯一完成标记、真实退出码、同一会话命令互斥，以及超时后的中断或重建策略。

## 6. 维护规则

1. 改动前先读取 `PROJECT_MEMORY.md`、架构、回归防护和最新变更记录。
2. 改动后更新 `docs/project-memory/CHANGELOG.md`。
3. 发现新的稳定约束时更新 `REGRESSION-GUARDS.md`。
4. 不要通过增加统一模板来解决所有输出问题，回复结构应按任务类型自适应。
5. 不要用模拟的“思考步骤”替代真实工具事件；需要展示中间过程时，只展示公开且可验证的进展。
6. 修改滚动、流式状态或消息刷新时，必须同时检查持久化集合、pending 合并和虚拟滚动状态。
