# Eva 工具审批与本地应用服务接入

日期：2026-09-15  
发布版本：待定（沿用 0.1.206）  
目标平台：跨平台

## 更新背景

随着 Eva 的能力从单轮对话延伸到多轮 Agent 运行（goal / team / run），需要补齐两件事：

1. **工具调用的审批治理**：Agent 在工作区写入、终端命令、浏览器控制、MCP 调用等高风险操作需要分级审批策略，而不是全部一刀切默认允许。
2. **本地应用服务（App-Server）**：让同机编辑器、IDE 或脚本在不打开 Eva UI 的情况下也能驱动会话——通过 `127.0.0.1` 的 JSON-RPC + SSE 暴露受 token 保护的控制平面。

与此同时，Agent 运行过程的"恢复/重启"能力需要可靠的事件流，因此新增了 AgentRunEventStore 作为追加式事件日志。

最后，在 Windows 上 `conversation-store` 的原子写入会偶发 EPERM（Defender/索引器短暂持有目标文件句柄），需要让 `writeJsonAtomic` 重试 EPERM/EBUSY/EACCES。

本次变更涉及 IPC 契约、shared 类型、若干 main service、两个新的 renderer 面板（AppServerPanel、ToolApprovalCard），以及 chat store 的接线。

## 一、工具审批策略（Tool Approval Policy）

### 设计目标

- 区分工具的风险类别，而不是按工具名硬编码 yes/no。
- 同一类工具在不同运行模式下（normal / expert / goal）可有不同默认策略。
- 策略可由用户在 settings 里整体覆盖；个别请求也可以在 UI 临时决策。

### 风险分类

新增 `ApprovalCategory`：

| 类别 | 工具 | 默认策略（normal） |
| --- | --- | --- |
| `read-only` | `read_file` / `list_directory` / `search_files` / `web_search` / `read_web_page` / `read_terminal` / `project_search` / `delegate_to_*` / `run_task` / `run_goal` / `manage_goal` / `create_execution_plan` / `apply_spec_template` | always-allow |
| `workspace-write` | `write_file` / `edit_file` / `spreadsheet` | allow-once / always-allow |
| `terminal-command` | `execute_command` / `write_terminal` | always-ask |
| `mcp-call` | `mcp__*` | always-ask |
| `browser-control` | `browser_*` / `close_browser` | always-ask |
| `other` | 兜底 | always-ask |

策略枚举 `ToolApprovalPolicy`：

- `always-allow`：直接放行，不弹卡。
- `allow-session`：本次会话内放行（不持久化到磁盘）。
- `allow-once`：本次调用放行。
- `always-ask`：每次都走 UI。

### 设置面板

`SettingsDialog` 中加入"工具审批"区块，用户可针对每一类分别设置策略。修改即时落盘 `electron-store`。

### 渲染侧

`ToolApprovalCard` 是新的聊天内嵌卡片：

- 显示工具名、参数摘要、风险类别与默认策略原因。
- 提供 "仅本次" / "本会话" / "始终" / "拒绝" 四个按钮。
- 决策通过 IPC 回传主进程；不允许决策后再回放（防重入）。

### 接入点

`agent-runner` 在每个工具调用前调用 `evaluateToolApproval(toolName, config)`，拿到决策后：

- `allow*` 直接调用工具。
- `ask` 阻塞等待 UI 回包；超时则拒绝。
- `deny` 直接拒绝并写一条拒绝事件到 `AgentRunEventStore`。

`tests/unit/tool-approval-policy.test.ts` 覆盖 8 个用例：分类正确、策略默认、覆盖生效、IPC 决策路径。

## 二、Agent 运行事件日志（AgentRunEventStore）

### 目标

Agent 长时间运行（goal / team）可能在任意点被中断（应用关闭、用户取消、进程崩溃）。重启后需要知道上一次停在哪一步、哪些 item 已经完成、哪些还没收尾。

### 数据形态

追加式 JSONL 文件 `agent-run-events.jsonl`，每行一个 `AgentRunEvent`：

```ts
{
  id: string
  sequence: number
  timestamp: number
  runId: string
  turnId: string
  type: 'run_started' | 'turn_started' | 'turn_interrupted' | 'item_started' | 'item_completed' | 'run_completed' | 'run_failed' | ...
  item?: { id, kind, name, status }
  metadata?: Record<string, unknown>
}
```

### API

- `append({ runId, turnId, type, item?, metadata? })`：自动填 id / sequence / timestamp。
- `list(runId?, turnId?)`：按 run / turn 过滤。
- `recoverySummary(runId)`：把"item_started 但没有 item_completed"作为 incomplete items 返回，供 `RunLifecycleCoordinator` 决定是否需要 retry。

### 接入位置

- `agent-os-scheduler` 在 run / turn / item 的关键生命周期点写事件。
- `RunLifecycleCoordinator` 启动时调用 `recoverySummary`，与 `RuntimeRunStore` 中的 `RuntimeRunDescriptor` 对账。

`tests/unit/agent-run-event-store.test.ts`（2 用例）：append 后 sequence 单调、recovery 正确识别 incomplete items。

## 三、本地应用服务（App-Server）

### 目标

让同机外部进程（编辑器插件、CI 脚本、个人 CLI）可以：

1. 列出 / 创建 / 打开会话；
2. 往会话里发消息并订阅流式回复；
3. 查询 Agent 运行状态、审批工具调用。

而**不需要**打开 Eva UI，也不暴露公网。

### 传输

- HTTP + JSON-RPC：`127.0.0.1`，随机空闲端口（启动时探测，失败则抛错）；
- SSE（Server-Sent Events）：事件流 `event: <type>\ndata: <json>\n\n`；
- Bearer token：每次 `startAppServer` 重新生成 32 字节随机 token，仅通过 `AppServerPanel` 一次性展示给用户，不会写入磁盘。

### 模块结构

```
src/main/services/app-server/
  index.ts       # 启停 + 状态查询
  server.ts      # http.createServer + 路由分发
  protocol.ts    # JSON-RPC 方法表 + 入参校验
  sse-hub.ts     # 订阅器维护、事件广播、断开清理
```

### IPC 入口

`src/main/ipc/app-server.ts`：

- `APP_SERVER_GET_STATUS`
- `APP_SERVER_START` —— 需要 `ApplicationServices` 已经组合（renderer 端的服务 bundle），由 `ipc/index.ts` 注入；
- `APP_SERVER_STOP`

### 渲染面板

`src/renderer/components/settings/AppServerPanel.tsx`：

- 显示当前状态（未启动 / 监听中：`port`、`startedAt`、`pid`）；
- "启动"按钮 → 启动后展示一次 token + URL，提供复制按钮；
- "停止"按钮；
- 服务状态每 2s 自动刷新。

> **本次有意不实现 CLI 客户端**：CLI 与应用服务是独立的两个项目，CLI 何时启动、何时分发、与谁解耦都还不清晰；先把控制平面落地，后续可以单独再做 CLI。

`tests/unit/app-server.test.ts`（4 用例）：HTTP transport 通过 `createServer` 打开端口、JSON-RPC 派发、SSE 订阅与取消订阅、token 鉴权。

## 四、ConversationStore 写入可靠性

`writeJsonAtomic` 在 Windows 上偶发 EPERM（Defender / Windows Search 短暂锁住目标文件，导致 `fs.renameSync` 失败）。改为：

```ts
private renameWithRetry(src: string, dest: string): void {
  const maxAttempts = 5
  for (let attempt = 1; attempt <= maxAttempts; attempt += 1) {
    try { fs.renameSync(src, dest); return }
    catch (error) {
      const code = (error as NodeJS.ErrnoException)?.code
      if (!(code === 'EPERM' || code === 'EBUSY' || code === 'EACCES') || attempt === maxAttempts) throw error
      const sleepMs = 10 * attempt
      const until = Date.now() + sleepMs
      while (Date.now() < until) { /* spin */ }
    }
  }
}
```

覆盖所有原子写入路径（meta.json / message-pages/*.json / message-pages.json）。`tests/unit/storage.test.ts` 23 用例全绿。

## 五、IPC 契约变更（节选）

### 新通道

```ts
IPC.APP_SERVER_GET_STATUS     = 'app-server:get-status'
IPC.APP_SERVER_START          = 'app-server:start'
IPC.APP_SERVER_STOP           = 'app-server:stop'
IPC.TOOL_APPROVAL_DECIDE      = 'tool-approval:decide'   // renderer -> main
```

### preload 暴露

```ts
window.eva.appServer = { getStatus, start, stop }
window.eva.toolApproval = { decide(requestId, decision) }
```

### trusted IPC

所有新 handler 通过 `trustedIpcMain` 注册，`verify:ipc-boundary` 检查通过。
