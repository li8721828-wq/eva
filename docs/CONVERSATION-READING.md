# 对话阅读规范

Eva、Pi、DeepSeek Harness 共用展示规范，执行调度、原始回复、提示词和工具结果仍属于各自引擎。

## 内容边界

- 前端按现有 Markdown 结构展示，不根据关键词猜测结论、补标题、添加加粗或改写正文。
- 单个 `~` 按字面显示，避免多个数字范围之间被误认作删除线；只有明确的双波浪线删除标记产生删除线，源文及代码不改写。聊天流式/历史与文档预览沿用相同 GFM 配置。
- 原生公开事件的内容、顺序、消息边界和工具来源保持完整；复制答复返回原始 Markdown。
- 正文里的操作命令属于答案，继续显示。执行记录里的命令、参数、反馈默认收起，展开可查。
- 原答案本身冗长或随意使用强调时，展示层只能统一其样式，不能保证得到简洁、结构化的业务总结。

## 阅读层级

| 元素 | 规则 |
| --- | --- |
| 正文 | 默认 15px，13/14/15/16/17/18/20px 档位与设置标注一致；行高 1.8，阅读宽度最多 78ch |
| 标题 | 一至三级分别约为正文的 1.333、1.2、1.067 倍，字重 500；标题和段落的间距参考 New API 的自然文档排版 |
| 强调 | 字重 500，沿用柔和阅读文字色；无艺术字、阴影和浮动动画 |
| 分隔线 | 中性色 1px 细线，间距固定 |
| 引用 | 次要文字色与中性左边线，无额外卡片 |
| 列表与表格 | 保留语义与顺序；统一缩进、行距和表头层级，表格可横向滚动 |
| 代码 | 等宽字体，主题背景与文字配色，中性边框；长代码限高滚动，复制保留 |

聊天在三种历史 Markdown 渲染偏好下均使用同一套 Streamdown 增量解析器，生成中与完成后共用以上层级；背景、边线和链接沿用 Eva 主题，正文采用柔和的阅读墨色。文档预览及其独立渲染偏好不受聊天作用域覆盖。旧版装饰偏好继续保存，当前聊天以统一规范为准。

2026-11-25 起，聊天参考 New API 的增量文字呈现：收到的正文以 16ms 批次提交，新增正文与接口思考内容使用 500ms 透明度渐显和短暂柔光，结束后恢复清晰无阴影字形；不额外逐字排队，不添加文字模糊或位移。每个 Markdown 块独立追踪字素与未完成的淡入，新包到达不取消先前文字的渐显，已稳定文字不重播。历史消息静态显示，系统启用减少动态效果时禁用淡入。可见前台回复结束前仅保留固定的淡入收尾时间，后台及重复回复直接收尾。工具、SDK 事件、取消与选择卡仍按原顺序处理。

不完整加粗、列表和围栏由增量解析器处理，不为动画删改 Markdown 标记。聊天代码组件保留原始换行、语法高亮与复制；没有语言的围栏不做猜测高亮。正文及代码的原始数据不因视觉效果改变。

单条文字超过 20,000 个 UTF-16 字符时继续解析 Markdown，但停用字级淡入，避免为超长回复创建大量动画节点；此上限不截断或改写内容。

回复正文下方不显示用量、耗时、费用或对应折叠入口，也不追加时间戳/响应耗时行。已完成的持久化回复提供常显的复制、重新生成（仅最新回复）、引用与收藏小图标；操作名称通过悬停提示及无障碍标签呈现。流式和停止留存副本不提供针对持久化消息的操作。用量与耗时原始记录继续保留，供既有统计与诊断使用。

默认聊天字体使用与参考 New API 同类的平台无衬线轴：Segoe UI/系统字体及 Microsoft YaHei 等 CJK 回退，不再优先映射本地 HarmonyOS 字体。应用导航与设置等 UI 继续保留原字体。衬线、等宽及 macOS 字体偏好继续保留。正文采用清晰的中性深墨色/雾白色，关闭合成加粗，不使用模糊或阴影修饰字形。字体文件未随应用分发，其他机器的实际字形会受已安装字体影响。

字号只作用于对话正文，应用根字号保持 14px，避免工作区布局跟随放大。字号标签和正文由 `lib/reading-typography.ts` 提供同一份数值。

## 真实页面与预览

浅色 `--conversation-canvas` 淡紫蓝渐变只在最外层 App 画一次。真实聊天、工作区和桌面右栏底层透明，不能各自重新绘制渐变或用近白底遮盖；展开工作区也透出同一画布。输入框/紧凑便签保留独立表面，窄屏模态抽屉保留遮罩与可读底色；消息气泡继续透明、无嵌套卡片。深色/星空仍由外壳拥有主题背景。

浅色画布以淡紫透光、冰蓝过渡和明亮珠光为配色方向，光色场在整张画布平滑相融；不能因修接缝退成均匀灰蓝底。桌面尺寸下检查阅读区边缘和右栏空白的实际颜色与亮度，不能只校验 CSS 名称或小尺寸预览；字形保持清晰，不使用文字模糊或图片纹理伪造水晶质感。

字体和排版验收包含真实 `App → ChatPanel → MessageList → MessageBubble` 链路，并与独立消息预览使用相同演示 Markdown 对比。截图仅表示演示内容的显示效果，不能代表真实模型产出；字体、字号偏好及引擎原始内容继续保留。

没有标注语言的代码围栏仍属于代码块，不能套用行内代码灰底、小字或文件路径标签。代码复制与行内路径点击各自保持原本语义。

## 执行记录

- 按“公开说明 → 连续工具列表 → 公开说明 → 新工具列表”的顺序展示。说明文字始终在列表外，不能把整轮内容包进一个执行记录面板。
- 只合并相邻工具，保留原时间顺序，每组仅一个紧凑工具/命令调用入口，详情默认折叠并在该组原位置展开。2026-11-25 用户要求移除底部重复“操作记录”，不再添加总入口或跨位置隐藏已结束的批次。数量与报错/未确认提示仅来自该组已有工具状态，生成的图片始终留在可见区。
- 工具与命令采用无卡片边框的轻量行式展示；行内提供名称和文件/命令摘要，展开保留完整参数、原始反馈、SDK 展示内容与真实来源。
- 不根据工具次数或流结束推断整个任务成功，不把工具报错宣称为最终任务失败。
- 运行中的答复持续显示；折叠不停止事件接收，也不改变执行或授权。
- 每个工具列表独立限高、内部滚动并跟随新增工具；用户向上阅读时停止跟随。说明文字使用正常对话布局。
- 任务侧栏的原生目标、待办与会话诊断保持直接显示；聊天不显示原生 session 接入/续接提示，也不显示用量与耗时。原始事件继续保留。
- 展开与滚动状态只在前端存在，不写入会话、配置或 SDK 日志。

原生内容沿用 SDK 的消息/工具顺序；Eva 的公开汇报与工具依据已有时间戳合并，时间戳相同时保持汇报优先、各流内部原顺序。历史记录没有更细顺序时，不伪造新的执行证据。

实现入口：`chat/MessageBubble.tsx`、`chat/ConversationActivity.tsx`、`chat/ToolActivityList.tsx`、`chat/ExecutionDetails.tsx`、`chat/NativeAgentView.tsx`、`lib/execution-activity.ts`、`lib/ink-reveal.ts` 与 `styles/conversation-reading.css`。浏览器夹具以受控公开事件验证展示，不代表真实账号任务验收。

## 2026-11-25 参考图的加载与思考区

等待回复时统一显示一条灰色转圈和“正在回复…”；模型开始返回正文后移除。思考区只接收 API 明确返回且标有 provider-response 来源的内容，位于正文上方、独立于工具记录；生成时展开，正文开始后收起一次，支持重新展开。OpenAI 兼容接口接受字符串 reasoning_content 或 reasoning，不解析不透明对象。未选思考档位时跟随模型默认值，旧显示开关不再显式发送关闭；用户明确关闭或选择其他档位仍优先。无来源的旧记录与 SDK 内部推理继续隐藏，不伪造思考内容或耗时。

回复按无头像、无紫色作者标签的文档列排版。代码框采用语言栏与图标复制，超过 24 行可展开至 48 行高度并独立滚动；表格、行内代码与引用统一中性边界和主题配色。复制始终返回原始文字。基础画布和应用导航不改变。

用户消息恢复 Eva 原有透光渐变气泡、圆角和字重，不套用助手回复的字体或外观覆盖。消息之间及活动列表的垂直间距收紧；不改动虚拟列表滚动容器的内边距。
