# Eva 2026-09-21 改动说明

## 一、改动范围

本次改动集中在两个方向：

1. 对话执行过程和最终回复的展示稳定性。
2. 用户长期记忆、项目长期记忆和仓库工程记忆的边界整理。

本文件描述当前工作区中已经落地的代码和文档变化，不代表所有后续规划都已经完成。

## 二、对话与执行展示

### 1. 执行过程和最终回复分离

- 工具调用、工具结果、公开进展和最终 Markdown 回复使用独立的展示区域。
- 工具区域有独立的最大高度和内部滚动，不会随着最终回答变长而一起无限拉伸。
- 工具详情默认收起，避免原始命令输出直接铺满对话。
- 只有真实收到的工具事件才能进入执行时间线，不再由模型文字伪造“已执行”的过程。
- 有工具执行时，最终 Markdown 在执行期间不展示未完成的半成品；等收到稳定的 `done` 事件后再展示最终答案。

### 2. 回复结构改为按任务自适应

- 普通问答保持简洁，不强制输出“结论、已完成、问题与风险、下一步”等工程报告段落。
- 解释、分析、代码审查、执行、规划和混合任务使用不同的最小结构。
- 最终汇总要求去重、压缩，并且只能总结已经获得的证据。
- 不展示模型私有思维链，只展示有限的、可验证的公开进展和真实工具活动。

### 3. 流式消息和滚动稳定性

- 用户消息在发送时立即持久化，避免刷新或重新挂载时只剩流式临时状态。
- 当前会话的流式状态与持久化消息集合分离。
- 新一轮请求会使同一会话的旧请求失效，旧请求不能继续覆盖新请求的消息和状态。
- 自动滚到底部时，同时更新真实滚动容器和虚拟列表的 `scrollTop`，减少流式过程中历史消息暂时消失或出现空白占位的问题。
- 执行中的不完整最终 Markdown 不会被刷新快照覆盖或提前保存为最终回答。

## 三、统一长期记忆

### 1. 统一数据模型

运行时长期记忆统一使用一个 Store，但保留两种作用域：

- `user`：跨项目的用户偏好、沟通方式和工作习惯。
- `project`：当前工作区的架构决策、工程事实、缺陷、约束和工作流。

长期记忆记录包含作用域、类型、内容、置信度、重要性、证据和状态。自动发现的记录默认进入 `pending`，确认后才进入 `active` 召回范围。

### 2. Memory Agent 后台写入

- 主 Agent 负责完成当前用户任务，不等待长期记忆整理。
- 主 Agent 完成一轮后提交受限的 `MemoryEvent`。
- `MemoryAgentService` 将事件写入持久化队列，再由后台串行处理。
- Memory Agent 不使用工具，只负责判断是否值得保存、作用域、去重、更新和归档。
- 写入失败不会阻塞用户任务，队列记录会保留并在应用重启后恢复；超过重试上限的记录仍保留，便于诊断。

### 3. 记忆召回

普通聊天、Goal/Team、QQ 远程和本地 App Server 请求会根据当前用户请求召回：

- 默认用户作用域 `user:default`。
- 当前工作区的 `workspace:<id>` 或路径作用域。
- 召回数量和注入字符数均受限制。
- 召回内容只是参考资料，不能覆盖当前用户请求，也不能作为授权依据。

### 4. 记忆管理界面

设置中增加长期记忆面板，用于查看和管理：

- 用户记忆和项目记忆。
- 记忆类型、状态、置信度和重要性。
- 来源会话和证据。
- 记忆 Agent 的队列状态、重试次数和失败原因。
- 启用/停用召回、确认、归档、拒绝和删除等操作。

## 四、仓库工程记忆

新增仓库级工程记忆，与 Eva 运行时长期记忆完全分离：

- `AGENTS.md`：后续代码 Agent 的读取和更新规则。
- `PROJECT_MEMORY.md`：项目工程记忆入口。
- `docs/project-memory/ARCHITECTURE.md`：架构边界。
- `docs/project-memory/REGRESSION-GUARDS.md`：已修复问题对应的回归约束。
- `docs/project-memory/CHANGELOG.md`：工程变更记录。

仓库工程记忆不注入用户对话，不参与运行时召回，也不由 Memory Agent 自动改写。

## 五、验证情况

本次相关改动已进行以下验证：

- `npm run typecheck`

- IPC 边界和打包文件检查

## 六、当前仍需继续关注

以下内容属于后续风险，不应视为本次已经完成：

- 终端工具的 workspace/granted-folders 权限是否真正限制了命令的工作目录和 shell 能力。
- 搜索工具对 Windows junction/symlink 的路径授权是否与文件工具保持一致。
- 多个会话并行运行时，终端和文件服务上的 sandbox 上下文是否会互相覆盖。
- PTY 命令超时、退出码和同一会话并发写入是否会污染后续命令结果。
- Memory Agent 当前默认使用 `default` 用户作用域，未来多用户场景需要接入真实用户身份。
