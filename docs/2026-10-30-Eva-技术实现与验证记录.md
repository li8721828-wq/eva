## 三、执行循环与重复操作

### 1. 保留模型驱动的普通聊天循环

基线提交已经移除 `MAX_NORMAL_TOOL_CYCLES = 4`，普通聊天使用配置的 `maxIterations` 作为防失控上限。本轮继续保留这一行为，同时移除成功单次读取后的 `LONE_READ_CHECKPOINT_PROMPT` 及无工具完成检查。

下一轮模型请求继续携带已授权工具，允许直接操作或作答。Goal 的阶段预算检查及详细步骤模式每个模型回合最多一个工具操作的约束保留。

工具执行后若模型返回空内容，进入已有的扁平化证据汇总恢复路径，避免反复发送相同的原生工具事务。协议修复、空回复恢复和截断续写仍保留相应保护。

### 2. 在派发前识别重复

调用签名由工具名称和规范化参数生成：对象键递归排序、数组顺序保留，参数序列化后取 SHA-256。改变对象键顺序不能使同一调用逃过重复检测，签名本身也不保留完整参数正文。

普通批次在实际执行前，与之前批次的执行后工作区 revision 比较。未发生后续工作区变化的原样重复批次进入汇总，不再先执行第二次副作用。

当前运行还维护已处理的操作调用 ID：相同 ID、相同签名复用原结果；相同 ID、不同签名返回错误。实时只读观察不采用操作 ID 防重放缓存。

这些机制有明确范围：不同运行之间不共享该调用结果表；工具调用 ID 和签名也不能代替外部服务的事务或幂等键。

### 3. 区分失败观察与失败操作

失败观察不缓存，同一工作区状态下相同失败读批次最多尝试两次。失败操作可能已经产生部分修改，因此同状态原样重复的操作批次也会被执行前保护拦住。

结构化协议的 `failed` / `rejected` 状态会归一化为工具错误，避免只看文字内容就缓存失败或推断操作成功。

## 四、只读调度与缓存

| 策略 | 实现 |
| --- | --- |
| 同时在途读取 | 默认最多 4 项，仅适用于整批均可并行的调用 |
| 结果交付 | 哪项先完成就先发出工具结果，模型工具事务仍按调用 ID 匹配 |
| 缓存容量与时效 | 最多 128 项，30 秒失效，按访问顺序淘汰 |
| 结果准入 | 只保存成功、可复用的观察 |
| 文件类观察 | 缓存键包含工作区 revision |
| 实时观察 | 终端输出、运行状态等不缓存，不因同参数读取而直接结束任务 |
| 潜在工作区修改 | 命令、写入、Skill、未知/MCP 操作等保守失效文件缓存，失败时也失效 |
| 参数相关工具 | 如 `spreadsheet` 的 `inspect` 与写入操作分别判定；inspect 保持串行 |

停止后不再启动排队读取。消费者提前关闭输出迭代器时，先向运行发出中止，再关闭内部迭代器并等待已启动操作退出；未启动的读取返回明确取消结果，不冒充成功。

混合写入批次继续保持串行。缓存过期允许重新观察，但不能以缓存失效为由重新执行同一个含写入的重复批次。

## 五、生命周期、日志与恢复

### 1. 统一运行身份与终态

桌面主聊天通过 `RunParams.runId` 使用调度器 process ID。队列执行回调接收该持久化 ID；Goal/Team 的子 runner 各自保留独立运行 ID，通过 `parentRunId` 关联到父任务。

`AgentRunner.run()` 包装实际循环并统一调用 `RunJournal`：成功写入 `turn_completed` 与 `run_completed`；失败写入 `run_failed`；取消或消费者关闭写入 `turn_interrupted`。同一 journal 至多尝试一次终态收尾。

收尾日志失败会记录诊断，不会把已成功应用的工具操作转成可重试失败。工具开始事件记录调用 ID、签名和观察/操作类别，不额外保存原始工具参数。

### 2. 异步追加事件日志

JSONL 文件格式保留，写队列改用异步文件操作。首次追加读取历史并恢复最大有效序号，后续成功追加后在内存递增；追加失败会重新恢复序号，且不会使队列永久失败。

末尾没有换行时先补分隔符，使破损尾记录不吞掉下一条有效事件。测试验证了 100 次并发追加只读取一次历史、序号有序以及重启后继续递增。

日志仍由单个进程拥有写入权。首次载入和查询/恢复仍读取历史，尚未提供分段归档、数据库迁移或跨进程写锁。

### 3. 恢复与重试的实际规则

恢复摘要沿父子关系收集运行证据。已中断任务存在操作记录，或缺少可核实日志时，标记需要人工复核，保留检查点供手动继续；具备只读证据时仍可走自动恢复。尚未启动的排队任务不受这一中断操作检查阻挡。

失败整任务的重试会检查子运行日志；无法读取证据时也不授权自动重放。Goal/Team 步骤在已请求操作后不再因后续网络或模型错误自动整步重跑。这里采取保守判定，请求被拒或实际未生效的操作也可能需要复核。

另修正两条状态路径：Team 的不可重试错误必须退出重试循环；Goal 只有在存在步骤且全部步骤完成时才标为完成。

## 六、工作参考与上下文边界

旧工具事务压缩后，`RunWorkingState` 生成新的工作参考，替换上一次生成的参考，避免每轮无限追加。它作为明确标注的参考数据加入模型请求，不作为新的用户指令或验收依据。

当前上限为：

- 请求参考约 2000 字符预算，超长时保留头尾并注明缩短。
- 最近 8 条工具观察，调用 ID、工具名和目标路径均单独限长。
- 展示最近 8 个待回读文件，并记录被省略数量。
- 大输入测试中的整段参考文本小于 7000 字符。

观察来自真实工具结果。写入后回读成功可移出待回读列表，但不推导为测试通过。旧事务证据另外保留调用 ID 与路径/URL，完整结果仍以既有执行记录为准。

工作参考只属于本次运行，结束后释放；不落盘为用户消息，不写入 Purpose、长期记忆或仓库工程记忆。它是有界确定性整理，不能保证保留任意长度的全部原始要求，也不是新增的模型语义总结系统。

## 八、交接与剩余事项

1. 当前优化尚未形成 Git 提交，也未推送、发布标签或生成安装包；构建成功不等于用户已安装的新版本。
2. 真实模型长任务的完成率、延迟和 Token 成本仍待对照验证；模拟场景的五次请求降为四次，只说明该流程减少了一次往返。
3. 跨进程或外部系统的副作用仍需外部幂等键、事务或状态核对。本轮没有承诺 exactly-once，恢复路径以保留检查点供人工核实为保护。
4. 日志归档、跨进程锁和独立执行进程尚未实现；历史日志很大时，首次加载与恢复查询仍有成本。
5. 工作区外部编辑或其他执行者的变化不等于当前运行的 revision 通知，观察缓存也不提供事务隔离。
