## 一、今天完成了什么

今天围绕 Eva 现有运行引擎进行了可靠性和效率改进，重点是减少重复操作、多余模型请求、状态误报，以及中断后不确定的自动重跑。

本次继续使用 Eva 自身的运行引擎。Pi、Qoder 属于此前讨论的技术候选，本轮没有将其接入或替换为默认引擎。

| 改进方向 | 此前的问题 | 本轮变化 |
| --- | --- | --- |
| 重复执行 | 普通循环在工具执行后才检查重复批次，第二次写入可能已经发生 | 在执行前判断重复；同一运行内的操作调用 ID 不能再次生效或换参数复用 |
| 模型往返 | 单次读取后，可能单独请求模型判断是否继续，再请求下一步操作 | 下一轮直接保留工具，让模型继续操作或作答 |
| 完成状态 | Goal 含失败步骤仍可能标为完成；Team 的不可重试错误仍可能进入下一次尝试 | 失败状态如实保留，不再把部分失败表达为整体完成 |
| 进度与停止 | 并行读取通常等待整批返回，较快的结果也要等慢操作；关闭输出流时可能未先取消读取 | 读取完成即回传，最多四项同时进行；停止后不再启动排队读取 |
| 观察缓存 | 失败结果、实时终端输出或修改前的文件内容可能被不合适地复用 | 只缓存成功的可复用观察；实时状态不缓存；可能修改文件的操作使文件缓存失效 |
| 长任务上下文 | 旧工具结果压缩后，任务要求和文件验证线索容易分散 | 增加有界工作参考，保留请求参考、真实观察、待回读文件和证据定位 |
| 执行日志 | 每追加一条日志都同步读取整份历史，运行与子任务 ID 也缺少关联 | 日志改为异步串行追加，恢复序号后继续写入；调度任务与子运行建立关联 |

## 二、普通任务可以更直接地连续执行

以“读取文件、修改内容、重新读取验证、给出答复”为例，模型现在可以根据上一步工具结果直接决定下一步操作，不必在读取后先回答一次内部的“是否继续”。

受控模型测试中的这一流程，从原来的五次模型请求减少为四次。这个结果证明该场景少了一次模型往返，尚不能据此推导所有任务的实际耗时或费用降幅。

模型仍然需要遵守工具授权、审批和沙箱设置；写入后的回读要求继续保留。Goal 的阶段预算检查也继续保留。

## 三、重复操作和失败处理更谨慎

本轮重点处理两类重复：

1. 模型或网关原样重复同一个工具批次时，在派发前停止，避免先重复写入再发现重复。
2. 同一运行内重复出现已经处理的操作调用 ID 时，复用原结果；如果换参数复用同一 ID，则拒绝新增操作。

失败读取可以在有限范围内重新尝试。失败命令或写入可能已经产生部分结果，因此不能仅因返回错误就原样重跑。

Goal 和 Team 的步骤若已经请求过操作，之后再出现网络或模型错误，不会自动整步执行第二次。任务队列也会检查相关执行日志，避免整任务重试再次触发已经发生的操作。

这项保护覆盖已识别的重复批次和当前运行内的调用身份，不代表外部服务在进程崩溃后仍能保证“永远只执行一次”。

## 四、中断后的继续方式更明确

恢复时会结合父任务和子运行的实际日志判断，而不是仅凭“任务未完成”就重新开始。

| 任务情况 | 处理方式 |
| --- | --- |
| 尚未启动的排队任务 | 保留自动调度能力 |
| 已中断，且能核实只发生过只读观察 | 可以进入原有自动恢复流程 |
| 已中断，存在操作记录，或无法取得完整执行证据 | 保留检查点，先核对实际结果，再通过现有任务流程手动继续 |

例如，命令可能已经修改文件，而后续模型请求因网络问题失败。此时应先检查文件和命令结果，避免为恢复对话而重复执行整个步骤。

运行结束、失败、用户停止或输出消费者关闭时，统一记录对应终态。收尾日志保存失败也不会把已经生效的工具操作改成可重试失败。

## 五、长任务保留更多可追溯线索

旧工具事务被压缩后，工作参考会保留以下信息：

- 当前请求的有界参考文本。
- 近期工具观察、目标文件及成功或失败状态。
- 已写入但仍待回读的文件，以及超出展示上限的数量。
- 旧证据对应的调用 ID、文件路径或网页 URL。

这些信息只在运行期辅助模型继续当前任务，不会建立另一套长期记忆，也不会自动修改项目主线的验收结果。文件回读成功只说明取回了内容，不能代替编译、测试或业务验收。
