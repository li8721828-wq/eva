# Eva 长时间运行稳定性更新

日期：2026-09-24

这次更新围绕“电脑重启后还能接入、状态文件不容易损坏、命令超时后不残留后台进程、Cloudflare Tunnel 能正确转发”四个问题展开。

## 已完成

### App Server 自动启动和退出清理

在“设置 → App Server”中新增“Eva 启动时自动启动 App Server”。开启后，Eva 完成主进程初始化和 IPC 注册后，会按已保存的监听地址、端口、公网基址和鉴权设置启动 App Server。

Eva 退出时会主动关闭 App Server、ACP WebSocket、SSE 连接和进行中的 App Server turn，避免端口或连接残留。

自动启动默认关闭，以保留原有行为。需要远程控制时建议开启。

### Cloudflare Tunnel 模式

Eva 现在支持“本机 HTTP + Cloudflare 公网 HTTPS/WSS”的组合：

```text
手机 -> wss://你的域名/acp -> Cloudflare Tunnel -> http://127.0.0.1:8787 -> Eva
```

在这种模式下，TLS 证书由 Cloudflare 处理，Eva 不需要填写 TLS 证书和私钥。Eva 设置页填写公网基址后，会直接显示手机应使用的 `wss://` 地址，并强制启用 Bearer Token。

### 状态文件原子写入

任务检查点、Agent OS 运行目录、运行内核、长期记忆和记忆队列现在都通过“临时文件写入 → 重命名替换”的方式保存，并对 Windows Defender 或索引器造成的短暂文件锁进行重试。

这样即使 Eva 在写文件时崩溃，读取方也更可能保留上一份完整状态，而不是读取到半截 JSON。

### PTY 超时真正中断命令

终端命令达到超时时间后，Eva 会先向共享 PTY 发送 Ctrl+C，再结束本次调用。原命令不会继续在后台运行并和下一条命令交错输出。

## 你的 Cloudflare 配置

针对 `www.broccolitrue.cloud`，Eva 设置建议如下：

```text
监听地址：127.0.0.1
固定端口：8787
公网 HTTPS 基址：https://www.broccolitrue.cloud
TLS 证书路径：留空
TLS 私钥路径：留空
ACP Bearer Token：开启
Eva 启动时自动启动 App Server：开启
```

Cloudflare Tunnel 的 Public Hostname 服务地址应为：

```text
http://127.0.0.1:8787
```

保存配置后启动 App Server。Eva 面板应显示：

```text
wss://www.broccolitrue.cloud/acp
```

手机 ACP 客户端填写这个地址和 Eva 面板显示的 Bearer Token。每次 App Server 重启都会生成新 Token，重启后需要重新复制。

## 诊断方法

### Cloudflare 显示 502 Host Error

这表示 Cloudflare 本身在线，但无法连接 Eva 的本地源服务。按以下顺序检查：

1. Eva 的 App Server 是否显示“正在运行”。
2. Eva 是否使用固定端口 `8787`。
3. Tunnel 的 Service URL 是否为 `http://127.0.0.1:8787`。
4. `cloudflared` 是否仍在运行，且运行在这台电脑上。
5. Windows 防火墙或安全软件是否拦截了本机连接。

域名根路径不是 Eva 的网页首页。根路径返回 404 或未携带 Token 时返回 401，都不代表 ACP 失败。可以用 Token 测试健康接口：

```powershell
curl.exe -H "Authorization: Bearer 你的Token" https://www.broccolitrue.cloud/health
```

正常应返回包含 `"ok":true` 的 JSON。

## 当前剩余限制

- `autoStart` 默认关闭，需要在设置页手动开启。
- ACP 连接断开后没有事件重放能力，手机端需要重新建立 session。
- Eva 进程异常退出时，进行中的远程 turn 会被标记为中断，暂时不会自动从远程 turn 的中间位置继续执行。
- Windows 睡眠或休眠期间，桌面进程和 Tunnel 都会暂停；长期运行的电脑应关闭自动睡眠。
- `cloudflared` 需要作为系统服务或其他守护进程运行，Eva 本身不会替它自动拉起。
