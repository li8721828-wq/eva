# Eva 2026-08-31 功能与工具更新

## 1. 更新范围

本次更新集中处理对话能力、文件附件、工具边界和代码生成流程。目标是让用户可以在对话中直接管理偏好、处理表格文件，并让系统工具保持明确、可审计的职责边界。

## 2. 主动偏好管理

Eva 已提供 `manage_personal_preferences` 工具。模型可以根据用户在对话中的明确要求，执行偏好添加、更新、删除和查询。

偏好操作遵循以下原则：

- 用户明确表达“以后都这样”“删除这条偏好”等意图时，才执行写入或删除。
- 普通对话中的行为倾向仍可作为被动归纳素材，但不会自动把一次偶然表达写入长期偏好。
- 偏好写入结果会回到当前对话上下文，后续回答可以立即使用。
- 偏好系统与主题皮肤设置分离，视觉主题不是个人审美偏好的替代品。

## 3. 主题系统

主题使用统一设计令牌承载颜色、背景、边框、阴影、圆角、间距、字体和动效。主题切换只替换主题令牌，组件结构和交互语义保持一致。

当前兼容方案包括：

- 浅色主题：保留原有系统字体和主要交互习惯。
- 深色主题：调整背景层级、文字对比度、边框和控件状态。
- 星空主题：使用克制的深色层次和星光点缀，不改变信息架构，也不使用高噪音装饰。

主题切换应保持短暂、克制的过渡，不阻塞输入、提交和导航操作。

## 4. 表格文件能力

Eva 内置 `spreadsheet` 工具，支持：

- `.xlsx`
- `.xls`
- `.ods`

工具操作包括：

- `inspect`：读取工作簿、工作表、范围和单元格内容。
- `create`：按结构化数据创建新的 `.xlsx` 文件。
- `update`：按 A1 单元格操作更新已有工作簿。

处理规则：

1. 检测到表格附件时，优先调用 `spreadsheet`。
2. 默认先用一次不指定工作表的 `inspect` 获取工作簿概览。
3. 只有在确有必要时才读取单独工作表。
4. 只有用户明确要求生成或修改文件时，才调用 `create` 或 `update`。
5. `spreadsheet` 报错或明确不支持目标操作后，才允许使用脚本作为兜底，并且应说明前一步失败原因。

表格附件会在本地解析后提供给模型；模型不会直接接收原始二进制文件。

## 5. 附件展示与解析边界

用户消息中的附件现在会作为消息卡片展示，显示文件名和加入消息状态，避免用户无法确认文件是否上传成功。

本地附件解析规则：

- 文本和代码文件：读取文本。
- PDF：提取文本。
- DOCX：提取正文。
- XLSX/XLS/ODS：提取工作表文本并提供路径给 `spreadsheet`。
- 单文件解析上限：32 MB。
- 所有附件进入模型上下文的文本总量上限：80,000 字符。
- 超出总量的内容会截断；不支持的格式只提供转换提示，不猜测文件内容。

## 6. 工具边界调整

已移除 Blender 和桌面控制相关工具及其配套服务，包括 Blender 场景检查、脚本运行、渲染、鼠标控制、键盘控制、桌面观察和表单填充等能力。工具目录、插件目录和系统提示同步清理，避免模型继续选择已不存在的工具。

代码生成不再依赖外部 `code-product-pipeline`。`/coding` 使用 Eva 内置 TypeScript 确定性生成器，并保留 DSL 哈希、语义包、IR 校验、产物校验和编译验证流程。

## 7. 维护注意事项

- 新增文件能力时，应优先提供结构化工具，再考虑脚本兜底。
- 任何会写入文件的工具都必须在描述和系统提示中明确用户授权边界。
- 新工具加入或删除后，需要同步工具注册表、工具目录、系统提示和测试。
- 附件文本预解析与工具按需读取会同时增加请求上下文，处理大型工作簿时应优先按工作表或范围读取。
