# 聊天区排版系统化设计与落地

日期：2026-09-09
版本：0.1.205

## 背景

用户反馈聊天界面"字体有粗有细、没有系统化、很多地方粗糙"。盘点确认的问题：

- **零 token**：Tailwind v4 无 `@theme` 排版 token；`prose prose-sm` 是无效类（未装 typography 插件）。
- **字号混乱**：11px / 12px / 14px / 16px 四层无规则混用，同类语义不同字号。
- **字重无规则**：同级元素 medium 与 normal 互换（元信息 11px+medium，操作按钮反而 12px+normal）。
- **markdown 标题层级被拉平**：h1–h4 全部同字号同字重，靠边框装饰凑层级。
- **颜色手写**：元信息 zinc-400/500 混用、正文 zinc-600/700/900 混用、品牌紫 violet-600/700/800 混用；个别 CSS 类与 utility 双重定义颜色。
- **字体栈引用了未加载的 MiSans / HarmonyOS Sans**（静默回退），body 基础栈反而没含它们。

范围确定为**聊天区优先**（消息流、过程面板、输入框、会话侧栏），元信息统一 12px。

## 排版规范（已写入代码的规则）

| 角色 | 规格 | 用途 |
|---|---|---|
| 消息正文 | 0.9375rem / 1.76 / 400（`--font-size-*` 用户档位不动） | `.chat-message-markdown` |
| UI 文本 | `text-sm`(14px) + `font-medium` + `text-zinc-700` | 工具行/组行标题、输入框、按钮、列表项 |
| UI 辅助 | `text-xs`(12px) + 400 + `text-zinc-500` | 工具 detail、展开区说明 |
| 元信息 | `text-xs`(12px) + 400 + `text-zinc-400` + `tabular-nums` | usage / timing / actions / 时间戳 |
| 标签徽标 | `text-xs` + `font-medium`（Badge 默认，不再覆写） | agent 名等 |
| 卡片标题 | `text-sm` + `font-semibold` | 卡片类标题（聊天区上限 600，不用 bold） |

补充规则：

- 字重只允许 400 / 500 / 600 三档。
- 品牌紫文字统一 violet-600；violet-100 等浅底上的文字/图标允许 violet-700。
- markdown 标题真实层级：h1 1.2em → h2 1.1em → h3 1em → h4 0.94em，统一 weight 600、行高 1.5；`strong` 统一 600。
- 保留判断：输入框正文 zinc-900、下拉选中态、页面级 `h1` 标题、欢迎页 hero 不在本次统一范围。

## 改动清单

### index.css

- 顶部新增 `@theme { --font-sans: ... }`，字体栈含 MiSans / HarmonyOS Sans SC（已安装的机器自动生效，未安装回退系统字体，不打包字体文件）；body 基础栈同步。
- `.chat-message-markdown` h1–h4 改为真实层级；border-left 装饰仅保留 h1。
- `strong` 统一 600（含 claude 变体的 500 → 600）。
- 删除 `.chat-usage-summary` 的重复颜色定义；清理 hljs 注释、工具详情等处与基础栈重复的字体引用；遗留的 550 字重归位 500。

### 组件（9 个文件）

- **MessageBubble.tsx**：usage/timing 元信息 → 12px/400/zinc-400；过程面板组标题 → 14px/500（工具组 zinc-700、思考组 violet-600）；agent 名 Badge 用默认规格；移除无效 `prose prose-sm`；ReasoningPanel 与时间线思考组样式对齐。
- **InputBar.tsx**：所有 `text-[11px]` → `text-xs`（引用标签、命令菜单、设置弹层等 8 处）；引用标签 violet-700 → violet-600。
- **GoalExecutionCard.tsx**：三个 uppercase 眉题统一 `text-xs + medium + zinc-400`；卡片标题 zinc-800 → zinc-700；状态/链接文字 violet-600。
- **RequirementClarificationCard.tsx**：标题 `text-base/900` → `text-sm/600/zinc-700`；题干与 legend zinc-900/600 → zinc-700；"推荐"徽标 12px + violet-600。
- **MessageList.tsx**：需求工程进度标题 zinc-900 → zinc-700；violet-800 → violet-600。
- **ToolCallView.tsx**：结果数小徽标 11px → 12px。
- **TeamCollaborationPanel.tsx**：成员名 zinc-900 → zinc-700；Context 按钮 violet-600。
- **ChatPanel.tsx**：Symposium 栏 / Expert Team 条 violet-800 → violet-600；能力抽屉标题 zinc-900 → zinc-700；席位小字与工具 chips 11px → 12px。

## 明确不做（scope 之外）

- 不动 `--format-*` / `--style-*` / `--font-size-*` 用户偏好档与 classic/streamdown renderer 变量体系——它们是用户偏好层，优先级更高。
- 不动聊天区以外页面；不引入 typography 插件；不打包字体文件。

## 验证结果

- `npx tsc --noEmit -p tsconfig.web.json` 无错误。
- 完整测试：70 个测试文件、328 项测试全部通过，无回归。
- dev server 抓取编译产物确认：`--font-sans` token、标题层级 CSS、组件新类名均已生效（HMR 自动刷新）。

## 后续可选项

- 若觉得某档视觉上不合适（如元信息 zinc-400 偏浅），按规范表单独微调对应角色即可，不要单独改某一处。
- 排版规范后续可推广到设置页、任务中心等聊天区以外的界面。
