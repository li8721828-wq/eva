# 任务主线与交接

任务主线（Purpose）属于项目，独立于一次会话。一个项目可以有多条主线，一条主线可以关联多个会话。第一版使用项目文件持久化，不需要协作服务器。

## 开始工作

1. 选择项目，点击项目名称旁的主线图标，或聊天标题栏的「项目主线」，在主工作区管理目标。也可以从右侧辅助栏的「主线」进入。展开、收回和缩放窗口不会重建当前表单；Escape 先返回辅助栏。
2. 「新建主线」：可以手工填写，也可以在「让 AI 起草」写一句需求，点击「AI 分析并填入」，自动填写名称、目标、范围、验收标准和里程碑。可选勾选「参考当前会话」，只使用当前项目会话的有限公开文本；默认不勾选。
3. 选择项目中的会话，点击「关联当前会话」。已有工作不会被重放，也不会自动导出原来的聊天。
4. 在会话中正常工作，或使用 Goal / 团队执行。后续模型调用读取当前主线；执行结束后自动记录工具名称、真实结果状态、步骤状态和记录时的代码快照。桌面、Goal / 团队、App Server 和 QQ 的已有会话执行入口均接入主线上下文。
5. Coding Assistant 可以通过 `record_purpose_progress` 保存公开进展、验证位置、阻塞和下一步。自定义智能体需要在工具设置中启用它；工具仍受写操作审批策略约束。AI 报告明确标记为待核实，只能将里程碑标为进行中或受阻，不能改变目标或代替人工验收。
6. 点击刷新查看最新记录。点击里程碑展开状态和验证依据；标记完成时必须填写依据。目标、范围、验收标准变化需填写原因，并保留原基线。整条主线验收需全部里程碑完成，并填写验收说明。

执行结束不代表功能验收通过。工具返回成功只说明该调用返回成功，不证明业务正确；记录时的代码快照也不证明前面的每个检查都运行于同一版本。请在验证依据中注明检查命令、结果、日志位置和对应代码版本。

### AI 起草的边界

- 使用设置中当前选择的模型连接；输入是需求说明、明确选择的同项目会话公开文本，以及已有项目索引的有限文件路径/符号元数据。不会读取整个代码库或宣称已验证实现；其他工作树的索引不当作当前代码依据。常见凭据模式在输入、输出中脱敏。
- 结果直接填入可编辑表单，可以「撤回填入」。假设与待确认问题单独列为可修改的规划备注，保存后留在「决策与发现」，不会被静默丢弃。检查并修正这些事项，再点击「保存」建立主线。
- 生成本身不保存文件、不执行工具、不更改已有主线进度或验收状态。解析失败、输出截断、取消或超时保留原表单；取消后的迟到回复不会覆盖表单。
- 同一窗口只允许一项起草请求；可取消分析，60 秒后超时。窗口关闭会取消所属请求。无可用模型时仍可手工填写。

## 中途交接

1. 停止主线下正在运行的任务或会话（暂停的可恢复任务也要先停止）。
2. 「记录交接」：核实并填写已完成工作、阻塞与待核实事项、下一步行动。Eva 记录当时的 Git 分支、提交和工作区指纹。
3. 把代码和 `.eva/purposes/*.json` 一起提交、推送到团队使用的仓库，或复制到接手方的项目目录。本功能不会自动提交、推送或发送资料。项目若忽略 `.eva`，需为主线 JSON 设置例外；Eva 仓库已设置该例外。
4. 接手方在 Eva 中添加该项目，打开「主线」，选择对应目标。
5. 点击「检查接手条件」，核对当前代码与交接记录。代码变化、未提交修改、Git 不可用都会明确提示；检查后代码或主线再次变化则必须重新检查。
6. 确认核对后点击「在新会话继续」。新会话使用接手方自己的模型配置、项目权限与空的目录授权。下一步放入输入框，由接手方发送；不会自动调用模型、切换分支、执行命令或恢复旧工具调用。

交接资料不包含代码补丁，未提交文件必须另行移交。Git 指纹排除 `.eva/purposes` 自身，包含已暂存、未暂存和未跟踪代码；过大、越界或无法读取的文件会导致状态显示为无法核实，不会被当作一致。检查是时点观测，不能阻止外部编辑器在随后修改代码。

## 存储与边界

- 主线文件：`<project>/.eva/purposes/<purpose-id>.json`。ID 随文件移动，不依赖接手方的本地项目 ID；历史会话 ID 仅作为来源引用，不要求另一台机器存在原会话。
- 原子写入、版本冲突检测和写锁保护文件；无效 JSON、Git 合并冲突、未知 schema 或越界目录会报错，不会覆盖成空状态。保存失败保留表单草稿。
- 一个文档上限 2 MB；执行记录每条最多保留 100 个工具元数据和 50 个步骤，模型上下文最多注入 24,000 字符，界面默认只展示最近部分记录。完整文档仍在项目中，需要时读取。它不替代完整本机执行日志或 CI 日志。
- 自动执行记录不复制原始提示词、聊天全文、命令参数、工具原始输出或私有思维链。人工填写和 AI 公开报告仍需避免放入凭据、个人信息或不适合团队共享的内容。
- 这是项目工作状态，不是个人偏好同步，也不是仓库的 `PROJECT_MEMORY.md` 工程记忆。两类记忆继续独立。
- 当前不提供在线同步、跨机器认领租约、分支自动合并、补丁打包、自动环境安装或 CI 验收。多人修改同一主线应通过 Git 审查和合并；本机写锁不能代替分布式协作锁。
- 意外退出可能留下 `.eva/purposes/.write-lock`。确认没有 Eva 进程正在写该项目后，可以移除这个锁文件并重试；不要删除主线 JSON。锁和临时文件不应纳入版本管理。

## 验证

`tests/unit/purpose-*.test.ts` 覆盖真实存储、另一个项目目录/应用存储中的接手、权限隔离、冲突和代码指纹，以及模拟模型的起草、输入范围、脱敏、取消/超时/格式错误；`npm run verify:ui` 使用隔离的界面夹具检查 AI 填入/撤回/迟到响应/规划备注保存、创建、关联、交接、继续、失败草稿及三主题窄布局。界面夹具不调用真实模型，不代表真实账号或多人网络协作的端到端验证。
