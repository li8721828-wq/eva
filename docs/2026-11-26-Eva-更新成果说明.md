## 二、工具调用与运行时边界

### 1. 让权限变更真正作用于新一轮执行

此前，任务启动时会保存权限配置。运行途中即使把会话切到完全访问，旧任务仍可能沿用启动时的审批方式。

现在，权限或目录授权成功变化后，系统会结束使用旧配置的执行及等待，保留已完成工具记录和已显示正文。用户发送“继续”后，新一轮采用新权限。已经执行过的写入不会因此自动重跑。

审批卡固定在输入框上方。切换会话、重新渲染或滚动消息不会重新计算审批期限；超时由主进程统一处理。同一轮中，同一目标的审批超时或拒绝不会因为换了调用 ID 就不断弹出。

### 2. 运行时各自使用自己的工具

| 选择的运行时 | 模型使用的工具 | 目录与搜索方式 |
| --- | --- | --- |
| Eva | Eva 注册的工具和已启用扩展 | Eva 的目录、搜索与命令工具 |
| Pi | Pi SDK 的读、写、编辑、目录与平台终端 | 原生目录工具及已启用终端 |
| DeepSeek Harness | DSH 的读、图像读取、写、编辑、平台终端及已启用原生能力 | 通过已启用的原生终端完成目录与搜索 |

原生工具失败时，不会悄悄回退到 Eva 工具执行。Eva 仍负责界面、模型连接、授权、沙箱和日志。详细说明见[运行时工具边界](运行时工具边界.md)。

旧聊天中的工具记录保留原貌；更新后，旧原生会话会采用新的工具配置代次继续。工具隔离解决执行归属问题，不保证模型永远不会请求无效工具。

## 三、聊天阅读与视觉调整

最终方案采用轻薄的透明玻璃质感。表格与代码块共享低遮盖底色、细边框、高光和很轻的阴影，保留底层画布的颜色，不采用厚重的 3D 卡片效果。

底层画布沿用淡紫与冰蓝的配色，提亮基础色并增加中央白色柔光。各栏共用同一画布，避免多层灰色遮罩导致界面发暗。

聊天默认内置 Noto Sans SC Variable 中文可变字体，正文适度加重，标题和强调更清晰，文字颜色调整为稍浅的灰色。字体随应用提供，运行时不需要从远程下载；用户原有气泡样式、字号和显式字体选择继续有效。

复制、重新生成、引用、收藏四个回复图标由 17px 缩到 15px，保留 30px 按钮点击区域及键盘操作。表格滚动、代码高亮、复制和折叠功能继续保留。

## 四、长需求文档可以完整导入

此前的 24,000 字符门槛来自 Eva 的附件处理逻辑，不是模型的固有能力上限。需求后续还有一层 48,000 字符检查，单纯提高附件限制仍会在下一步被拦截。

本次将导入与分析分开处理：

1. 完整保存原始需求和可解析的附件正文。
2. 根据所选模型的上下文窗口、输出预算及安全余量，决定直接读取或分段处理。
3. 长文档按段落、行边界分段，显示读取序号和原文位置；全部分段处理完成后再汇总分析。
4. 分段笔记保存为中间产物。读取失败时停止本轮，已经完成且校验通过的读取记录可以复用。

不再因为旧的 24,000/48,000 字符门槛拒绝正常长需求。当前仍保留本地资源边界：**单文件 32 MB、最多 40 个文件、单次需求正文导入 2,000,000 字符**。这与模型单次能接收多少 Token 是不同的限制。

普通聊天附件仍采用有界摘录。空正文、解析失败和导入超限会分别提示；扫描图片文档仍需先取得可读取正文，本次没有新增 OCR。

长需求在分段读取期间失败后，可在同一会话发送不带新材料的 `/requirement` 重试，沿用存档与有效读取记录。分段摘要不是逐字原文，重要规则仍应对照原始材料核对。

## 五、模拟材料后可以继续起草

此前的模拟功能只生成一份材料与规格预览，未连接后续步骤，因此卡片仍要求补材料，容易让用户误以为要重新提交需求。

现在一次模拟操作会沿用当前运行的需求、已有决定和待补清单，依次生成：

**模拟材料与假设 → 业务建模草稿 → 实施规格草稿。**

旧会话中已经生成模拟预览的，可以从原卡片点击“基于模拟材料，继续生成建模与规格草稿”。已经完成的产物通过校验后可复用；下游起草中断后可继续，不要求重新上传原需求。

卡片显示已推进的阶段，并提供草稿折叠查看入口。真实待补材料清单默认折叠，避免把“正式验收仍待材料”误读为“起草工作完全不能继续”。

模拟产物保留假设标记，不会自动成为真实材料、清除待补项或产生正式发布回执。真实材料到位后，仍可在同一会话通过 `/requirement` 补充并复核。正式 DSL 与生产代码生成继续使用已放行的上游产物。
