# 逐步执行与模型思考模式开发记录

日期：2026-09-30

## 1. 目标

修复用户看到的执行过程不符合 ReAct 直觉的问题：界面长时间显示连续的模型思考，工具调用批量出现，用户无法稳定观察“判断 → 工具 → 结果 → 再判断”的闭环。

本次采用公开执行事件和真实工具事件表达过程，不展示模型私有 chain-of-thought。

## 2. 问题定位

### 2.1 详细模式误用了慢思考开关

此前 `processOutput: 'detailed'` 与 `showThinking: true` 绑定。AgentRunner 会在供应商支持时发送：

```ts
reasoning: { enabled: true, budgetTokens: 1024 }
```

这会让 DeepSeek 或兼容网关花费较长时间产出 `reasoningContent`。部分中转站在 reasoning 字段缺省时也会默认开启思考，因此只删除 UI 展示不够，还需要显式关闭。

### 2.2 一个模型回合可能返回多个工具调用

正常模式为了效率允许完全只读的工具批次并行执行。详细模式下这会破坏公开的逐步节奏：多个读取操作会在模型重新观察结果之前全部开始，界面只能看到一组工具行。

## 3. 实现变化

### 3.1 AgentRunner

影响文件：

- `src/main/agent-engine/agent-runner.ts`
- `src/main/agent-engine/context.ts`

主要规则：

1. `processOutput: 'detailed'` 被视为公开逐步模式。
2. 逐步模式每个模型响应最多保留一个工具调用。
3. 如果模型返回多个调用，只执行第一个；其余调用明确作为“尚未执行”信息写回下一轮上下文。
4. 下一轮模型调用必须根据第一个结果重新判断，不得假设其余操作已经完成。
5. 逐步模式请求 `reasoning: { enabled: false }`，覆盖中转站缺省开启思考的行为。
6. 没有 `processOutput` 的 legacy 直接调用仍可以通过显式 `showThinking` 请求供应商 reasoning，避免破坏测试和内部兼容调用。

AgentRunner 仍然保留 reasoning 字符计数，用于空回复诊断和运行日志；“不展示”不等于“不记录诊断事实”。

### 3.2 Agent 配置和 UI

影响文件：

- `src/renderer/components/agents/OutputFormatPanel.tsx`
- `src/renderer/components/agents/AgentEditor.tsx`
- `src/renderer/components/agents/AgentManagementWorkspace.tsx`
- `src/main/storage/agent-store.ts`
- `src/main/ipc/agent.ts`
- `src/shared/types/agent.ts`

“详细”在界面中改名为“逐步”，描述改为公开的判断、操作、结果和下一步。保存带 `processOutput` 的 Agent 时，旧 `showThinking` 字段不再被置为 true；读取旧配置时，已有过程模式优先，避免再次把逐步模式迁移成慢思考模式。

### 3.3 执行过程渲染和公开阶段

影响文件：

- `src/renderer/components/chat/MessageBubble.tsx`
- `src/renderer/lib/process-report.ts`
- `src/main/ipc/public-execution-trace.ts`

聊天过程区不再渲染供应商原始 reasoning 面板。可见内容来自：

- AgentRunner 的固定生命周期阶段；
- 真实 `tool_call` 和 `tool_result` 事件；
- 模型主动发出的、经过协议剥离的 `plan`/`step` 公开汇报。

新增单步阶段映射“本轮只执行一个工具操作，结果返回后重新判断”，但它只说明 Eva 的实际调度行为，不冒充模型私有推理。

桌面 IPC 和 app-server/ACP 继续共用 `toPublicExecutionNote()`，因此远程手机端与桌面端保持同一公开阶段语义。

## 4. 用户可见行为

逐步模式下，一个典型回合应按以下顺序出现：

```text
正在判断是否需要调用工具
读取/编辑/执行一个工具
已收到工具结果，正在判断下一步
读取/编辑/执行下一个工具
正在汇总已验证的结果
```

工具结果失败时，失败状态仍来自真实工具结果；不会用“正在思考”或模型自由文本掩盖失败。

## 6. 剩余风险

- 逐步模式牺牲了独立只读调用的并行速度，复杂任务会增加模型往返次数。
- `<eva-progress>` 的 plan/step 仍由模型决定是否发送；未发送时只能依靠真实工具时间线和固定阶段，不能为了让清单好看而自动伪造步骤。
- 如果某个中转站完全忽略 `reasoning: { enabled: false }`，仍可能产生供应商侧私有思考；Eva 不会把它展示为执行证据，但供应商行为需要通过连接测试或实际请求继续确认。
- 旧会话中已经落盘的 reasoning 内容不会被重新改写；当前 renderer 不再把它作为新的过程区主内容展示。
