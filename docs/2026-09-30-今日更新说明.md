# Eva 今日更新说明

日期：2026-09-30

今天主要修复了执行过程看起来“持续思考一大段”、但没有清晰逐步推进的问题。

## 一、详细模式改为“逐步”模式

原来的“详细”模式会请求供应商的慢思考内容。部分 API 中转站在没有明确关闭参数时，还会自行开启思考，因此界面可能长时间停在“模型原始思考中”。

现在该模式在界面中显示为“逐步”，它展示的是公开、可验证的执行进度，不展示模型私有思考。公开过程会尽量保持下面的节奏：

```text
判断是否需要工具
→ 执行一个工具操作
→ 收到工具结果
→ 根据结果判断下一步
→ 汇总已验证结果
```

## 二、每个模型回合只推进一个工具操作

如果模型一次返回多个工具调用，逐步模式只执行第一个操作。其余操作不会被静默执行，也不会被当作已经完成；Eva 会把“其余操作尚未执行”的事实带回下一轮，让模型先查看当前结果，再重新决定下一步。

这样用户看到的工具行和公开阶段是一一对应的，避免多个文件读取同时出现、但用户不知道模型是否已经看过结果的问题。

## 三、如何启用

1. 重启 Eva 主进程或开发窗口，让主进程加载最新代码。
2. 打开 Agent 设置。
3. 在“过程输出”中选择“逐步”。
4. 保存 Agent 后，再发送需要读取、修改或验证文件的任务。

普通对话不需要打开逐步模式。关闭过程输出仍然只保留最终回复；简洁模式继续保留少量阶段变化，但不保证每个工具调用都单独展开。

## 四、手机 ACP 端的行为

手机 ACP 端使用同一个 AgentRunner 和同一套工具执行规则，不需要额外配置 ReAct 参数。只要手机连接到当前 Eva Agent，逐步模式的公开阶段和单工具节奏也会通过 ACP 的进展更新传递到手机端。

## 五、显示边界

- 显示真实工具调用、真实工具结果和 Eva 已知的固定阶段。
- 不把模型原始 reasoning 文本当作执行证据。
- 不把模型一次返回但尚未执行的工具调用显示成已完成。
- 逐步模式的清晰度优先于独立只读操作的并行速度，因此复杂任务可能比简洁模式多几次模型往返。
