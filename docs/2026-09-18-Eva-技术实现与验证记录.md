## 二、核心实现

### 1. 统一工具执行边界

新增 `src/main/services/tool-dispatcher.ts`，将以下逻辑集中到一个执行入口：

- 工具是否存在。
- Agent 是否拥有该工具权限。
- 工具参数 schema 校验。
- 写入路径白名单校验。
- 用户审批回调。
- 工具执行和异常归一化。
- `ExecutionEnvelope` 协议状态和耗时记录。

`AgentRunner` 不再直接拼接这些判断，而是通过 `ToolDispatcher.dispatch()` 执行工具，降低新增工具绕过安全控制的风险。

### 2. 工具审批策略

`tool-approval-policy.ts` 按工具类别计算是否需要审批，并维护待处理审批请求：

- 读操作。
- 工作区写入。
- 终端命令。
- MCP 调用。
- 浏览器控制。
- 其他工具。

审批请求通过聊天流事件发送到 renderer；主进程通过 approval id 等待一次性决策，并在新请求替换、超时或会话结束时清理挂起请求。App Server 也提供 `approval/decide` 入口。

### 3. 沙箱层和 Rust 原生模块

新增 `src/main/services/sandbox/`，包含：

- 策略组合：合并审批策略、沙箱等级和 Agent 模式。
- 后端选择与状态探测。
- 命令和路径决策。
- macOS `sandbox-exec` profile 生成。
- Linux `bubblewrap` 参数生成。
- Windows v1 策略检查后端。
- No-op 后端。

新增 Rust crate `crates/eva-sandbox`，提供纯策略函数、profile 构造、路径/命令决策和 N-API 导出。TypeScript 通过 `src/main/services/sandbox/native.ts` 使用 native 模块，调用方仍保持原有沙箱服务接口。

Agent 运行开始时将沙箱上下文绑定到 `TerminalService` 和 `FileService`，运行结束时在 `finally` 中清理，避免同一主进程中的后续运行继承旧上下文。

### 4. App Server

新增本地 HTTP 服务模块：

- `thread/list`
- `thread/get`
- `thread/start`
- `turn/start`
- `turn/interrupt`
- `approval/decide`
- `server/status`
- `server/shutdown`

服务仅绑定 `127.0.0.1`，请求通过 Bearer Token 鉴权，事件通过 `SseHub` 广播。IPC 层提供启动、停止和状态查询，renderer 的 `AppServerPanel` 展示端口、endpoint 和一次性 token。

### 5. 项目知识存储

新增 `ProjectKnowledgeStore` 和对应 IPC：

- 记录 `bug`、`change`、`direction` 三类工程知识。
- 以 workspace id/path 作为作用域。
- 对字段、标签、路径和记录数量做长度及数量限制。
- 支持关键词搜索、上下文摘要、状态更新和删除。
- 从一次工程回合的用户请求、助手回复和工具调用中提取候选知识。

### 6. 运行可靠性和界面状态

本次同时补充：

- Agent run event 的工具执行协议字段。
- 会话存储的 Windows 原子写入重试。
- 聊天消息加载序列保护。
- 发送中的本地消息与服务器快照合并。
- 工具审批流状态、Toast 和错误边界。
- 文件路径展示、复制和滚动位置恢复。

## 五、已知限制与后续工作

1. Windows 后端目前返回原始进程参数，依靠路径检查、危险命令拦截和审批策略提供最佳努力保护；后续需要 native AppContainer 或受限 token 实现真正的 OS 级进程隔离。
2. `fileAccessGrants` 已进入沙箱上下文和类型定义，仍需继续审查所有后端路径决策，确保授权目录在各平台行为一致。
3. App Server 尚未提供独立 CLI 客户端，也未设计跨机器 mTLS 方案。
4. Agent 运行事件和沙箱诊断信息尚未完成日志轮转。
