## 二、P0：欠验的活链路

### P0-1 `write_skill_file`「点批准 → 文件真落盘」补验

- **动因**：端到端五环只证了四环，最后一环被网关限流挡住（429 为整条连接冷却）。
- **时机**：当时的报文是 `Resets in 143h5m3s`（10-16 傍晚），按推算**今天（10-22）傍晚前后冷却到期**；先跑一次小额探针确认连接恢复，再补验。
- **做法**：CDP 驱动 dev 实例，让模型对 `probe-skill-write` 发起 `write_skill_file`，在审批卡上点「允许（本次）」，核对 `%APPDATA%\eva\skills\probe-skill-write\SKILL.md` 真落盘且 `load_skill` 能回读；探针会话与探针技能用完即删。
- **验收标准**：文件真实出现在磁盘 + 回读命中 + 活动日志链路完整；随后删除 `tmp/plan-stall/` 并把两份 10-16 开发记录与 CHANGELOG 的「未证」改写为已证。
- **依赖**：`gemini代出` 连接恢复，或他自己在卡片上点一次。

## 三、P1：已批范围未做

### P1-1 计划形态改造（Wave 2：权威状态源）

- **动因**：他的原话诉求——计划不该贴在转录顶上、要有可追溯的 `.md`、右侧便签打勾；现状是荣誉制 markup，模型不汇报清单就静止。
- **范围**：①计划写进可追溯的 `.md` 文件（`writeTextAtomic` 已在 `atomic-file.ts:41`，直接复用）；②右侧便签从该文件派生打勾状态；③顶部清单一行化。以 `.md` 为唯一真源，渲染层不再各自计算。
- **边界**：先不动界面以外的部分；`active-plans.json` 已在 10-19 改为原子写入，不重复。
- **验收标准**：计划落盘文件存在且随步骤更新；便签打勾与文件一致；重开会话后状态可重建；全量测试 + 真机目检。

### P1-2 `ask_user` Wave 2：app-server/ACP 通道

- **硬边界（先讲清再动手）**：ACP 的 `session/request_permission` 选项集合是协议侧写死的，自定义选项只能塞 `_meta`；不读 `_meta` 的标准客户端只会看到「允许/拒绝」。**这条路做不到桌面一样的点选体验**，形态上只能是降级映射，别按桌面效果承诺。
- **验收标准**：ACP 客户端能收到问题并作答、答案正确归会话；降级形态在文档里写明。

### P1-3 `ask_user` Wave 3：专家团（Symposium）

- **硬边界**：专家团 worker 今天没有用户决策通道，**不是复用审批那一层**，要新起管道。
- **建议**：范围比 Wave 2 大，放在 Wave 2 之后单独估。

### P1-4 `execute_command` 返回真 stdout

- **动因**：现在回给模型的是终端屏幕缓冲（含控制序列），`exitCode` 恒 0、`stderr` 恒空的问题已在 10-19/20 修掉退出码与队列部分，但 **stdout/stderr 合流、输出带终端格式**仍在（10-19 自认边界）。
- **范围**：为工具调用路径取真实 stdout（与交互面板共用 shell 的现状兼容），不动用户手敲的终端体验。
- **验收标准**：多行脚本、非零退出、取消三类实测 + 工具结果不含传输回显；Windows 真机 node-pty 验证。

## 六、已有结论否决、不再提议的方向

1. **不放宽 `FileService` 沙箱**去够 `%APPDATA%\eva\skills`（`read_file` 会顺 `..` 摸到 `config.json`）——写技能只走 `write_skill_file`。
2. **不用关键词/正则门控工具选择**——工具清单整体给模型，授权边界在 `agentConfig.tools` 与审批策略。
3. **不给技能目录上 `fs.watch`**——同步扫描 + 60s TTL 是刻意的。
4. **不把所有技能正文拼进系统提示词**——两段披露是设计，预算问题靠重载幂等兜。
5. **不让 Bing 系搜索源当唯一兜底**——实测返回降级内容。
6. **审批与选择类 live 事件分支不再加 `isStreaming` 守卫**——已咬两次，写进了守卫。

## 七、建议顺序

1. **今天可做**：P0-1（先看网关冷却是否到期，到期即补验，半小时量级）。
2. **下一个完整批次**：P1-1 计划形态（他的原始诉求里唯一还没动的部分）+ P2-4 顺带审计（同为渲染层事件分支，一次审计两个目的）。
3. **再往后**：P1-2/P1-3（ask_user 外扩，先讲清 ACP 硬边界再动手）、P1-4（execute_command）。
4. **P2 其余**穿插进行；**P3** 等他点名。
