## 二、流式呈现与 Markdown

### 1. 流式提交与字素动画

[stream-reveal-queue.ts](../src/renderer/lib/stream-reveal-queue.ts) 按会话进行 16ms 批处理，只合并相邻正文增量，保持工具、原生事件、重置和终态的边界。取消、新轮次及选择卡保留原有清理规则。

[ink-reveal.ts](../src/renderer/lib/ink-reveal.ts) 为每个 Markdown 块建立独立的增量状态与处理器缓存身份。使用字素分段处理组合字符，代码区域不插入字级动画。当前淡入参数为 500ms，并带短暂柔光；静态历史不播放动画，reduced-motion 禁用淡入。

单条内容超过 20,000 个 UTF-16 字符时停用字级动画，但不截断 Markdown。可见前台流结束有固定动画收尾窗口，后台及重复结束不额外等待。

### 2. 渲染与语法边界

[MessageBubble.tsx](../src/renderer/components/chat/MessageBubble.tsx) 的聊天流式与完成态统一使用 Streamdown，避免结束时切换解析器。非聊天预览保留原渲染选择。

Streamdown 与 ReactMarkdown 的 GFM 均配置 `singleTilde: false`。数字范围里的单波浪线按字面显示，显式双波浪线删除语义保留；Streamdown 的其他默认插件继续启用。没有通过隐藏全部删除线或改写源文规避问题。

代码组件保留原始换行、无语言围栏文本、复制及有语言围栏高亮。高亮 HTML 仅使用库的转义输出。长代码折叠、内部滚动和思考展开属于 renderer 状态，不进入会话持久化。

阅读规则见[对话阅读规范](CONVERSATION-READING.md)。

## 三、接口思考与工具活动

主进程只为模型 API 实际返回的思考增量标记 `reasoningSource: provider-response`。标记经 AgentEvent、IPC、流式 store 和消息落盘保留。兼容接口接受字符串 `reasoning_content` 或 `reasoning`，忽略不透明对象。

原生引擎经 host-only 队列转发该响应内容，worker 不能伪造同名方法；SDK 内部推理及 compaction 内容不进入思考展示。未选择档位时不因旧显示开关显式关闭思考，用户明确选择和原有空回复重试策略仍优先。

[ConversationActivity.tsx](../src/renderer/components/chat/ConversationActivity.tsx) 最终为无状态的顺序容器。0.1.229 曾加入底部总记录入口，0.1.231 按用户反馈删除；**最终版本没有该入口或跨位置隐藏逻辑**。

[ToolActivityList.tsx](../src/renderer/components/chat/ToolActivityList.tsx) 与 [ExecutionDetails.tsx](../src/renderer/components/chat/ExecutionDetails.tsx) 保留每组唯一入口、完整反馈、限高滚动和用户上滑优先。公开说明与生成图片不随工具详情折叠。报错及未确认数量只反映工具状态，不推断整个业务任务成功。

## 四、需求模拟与阶段继续

### 1. 模拟入口

[RequirementEngineeringService](../src/main/services/requirement-engineering-service.ts) 在既有 typed submit 中增加：

```ts
{ conversationId, runId, action: 'simulate-materials' }
```

操作仅接受当前会话归属的等待材料运行，验证运行 ID 与工作树，并沿用运行互斥、取消和模型输出完整性校验。一次模型请求生成缺失材料与规格草稿，不提供通用工具执行通道。

草稿保存为 `modeling/material-preview`，通过 `materialPreviewDocumentId` 关联当前运行。检查点绑定输入、模型和有效预算，并验证产物摘要与磁盘内容；相同输入可复用。

草稿不会成为 `source/supplement` 的真实交付证据，不清除 `pendingMaterials`，不生成正式 requirement 发布回执。真实材料复评时清除旧预览入口。UI 表述为“草稿已生成，正式验收材料待补”，而不是“正式需求已放行”。

[requirement-intent.ts](../src/renderer/lib/requirement-intent.ts) 只匹配有限范围的材料模拟语句。仅在会话存在等待材料的运行、且没有附加文件或图片时自动路由；普通模拟话题和否定句不改路由。

### 2. 阶段继续与错误处理

[MessageList.tsx](../src/renderer/components/chat/MessageList.tsx) 为已通过阶段提供继续按钮：需求后连续调用建模与规格接口，规格后连续调用 DSL 与代码接口。各次调用绑定同一运行，仍依赖后端上游回执、工作树及关键规则确认校验。

模拟时等待卡会临时卸载，因此失败信息写入聊天 store，避免只保存在卡片的局部状态里。生成结果在流程卡中默认折叠查看。

### 3. 减少重复评测与聊天膨胀

初轮顺利路径从原有 7 次模型生成减少为 6 次：移除相同中间输入的无条件第二次评测，保留初轮检查及最终需求独立放行审计。发生阻塞时仍按真实问题停住，不以分数覆盖材料缺口。

阶段完整文档继续保存在原产物目录。`persistDocuments` 改为每批发送一条文档索引；进度区文档不再默认全部展开，且使用统一阅读作用域。既有历史消息没有批量删除或重写。

## 五、Harness 持久会话修复

### 1. 故障路径

旧导入路径直接向 SDK session 追加历史 `user/message`，可能抢先占用 surface 首节点。SDK 随后追加 `system/message` 时，日志中缺少受保护的系统首节点，持久化恢复因此可能报：

```text
SessionFormatError: system/message requires a protected first surface head
```

首轮能返回内容并不证明下一次日志恢复一定有效，因此单轮测试不足以发现该问题。

### 2. 修正与旧格式隔离

[harness.mjs](../resources/execution-engines/harness.mjs) 改用 `agent.inject` 暂存历史参考，再通过当前请求的 `followup` 唤醒。由 SDK 按正常执行顺序建立系统首节点和用户消息，不手工构造 SDK 系统事件。

[native-session.ts](../src/main/agent-engine/native-session.ts) 为 Harness 游标增加 `harnessImportVersion: 2`。旧协议不再直接恢复原代次，而是创建新代次、导入完整 Eva 聊天参考。原始日志和聊天保留；新协议仍使用 SDK 原生续接。Pi 的游标行为不变。

这不是对损坏压缩日志的原地修补，也不恢复旧 SDK 内部检查点。历史工具以参考形式保留，不作为新任务自动重放。

[assistant-turn-content.ts](../src/main/services/assistant-turn-content.ts) 对本地会话格式错误提供专门中文说明，避免一律提示检查模型供应商。
