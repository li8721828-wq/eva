## 二、真实页面与连续画布

### 1. 问题与修正

最初的独立消息预览使用外壳渐变，实际 ChatPanel 却有近白色底层。0.1.207 对齐聊天背景后，workspace 的独立渐变与右栏底色仍然造成割裂。即便各列使用相同渐变参数，各自的坐标起点也会不同。

最终实现将背景所有权收敛到 `.eva-app-shell`：

| 区域 | 背景职责 |
| --- | --- |
| `.eva-app-shell` | 绘制唯一的整页画布；深色与星空仍由外壳提供主题背景 |
| `.eva-workspace`、`.eva-chat-surface` | 透明，透出共同画布 |
| 桌面 `.eva-utility-rail` | 透明，使聊天与右栏空白连续 |
| 展开工作区及其便签容器 | 透明，展开与还原不重启背景 |
| 输入框、紧凑便签 | 保留功能表面 |
| 窄屏 `.eva-utility-drawer` | 使用主题表面，保留模态遮罩与可读性 |

同时移除了深色/星空在 workspace、聊天和右栏重复叠加的半透明底色，防止列边界因多层混色重新出现。

### 2. 最终浅色配色

0.1.209 的 `--conversation-canvas` 使用两个宽幅径向光色场与一层线性底色，全部由共同外壳绘制：

```css
--conversation-canvas:
  radial-gradient(ellipse at 18% 12%, rgba(225, 218, 255, 0.42), transparent 58%),
  radial-gradient(ellipse at 84% 44%, rgba(216, 247, 255, 0.44), transparent 62%),
  linear-gradient(135deg, #f3efff, #f9fdff 48%, #eff3ff);
```

这次校准关注桌面尺度下的颜色分布，保留淡紫、冰蓝与明亮珠光的层次。没有新增图片纹理、文字模糊或字体阴影；已有字体/字号偏好不变。

颜色验收在真实 App 的背景空白取样，避开头像、文字、滚动条、便签阴影和输入框。1440px 窗口下，阅读边缘样本由 RGB 241/243/254 调整为 235/232/254，右栏样本为 237/247/255；1680px 场景也已检查。数值用于防止颜色层次退化，不能证明主观质感完全一致。

## 三、未标语言代码围栏修复

原静态渲染器依据代码元素是否存在 language class 判断行内代码，导致未标语言的围栏落入行内分支，出现额外灰底、小字，路径还可能被转换为文件标签。

修正采用 `MarkdownBlockCodeContext`：`MarkdownCodeBlock` 在 `pre` 内提供块级上下文，`code` 渲染器优先检查该上下文，再决定是否应用行内代码或路径标签。真正的行内路径继续可点击，围栏中的路径保持代码。

静态与 Streamdown 行内代码组件还剥离了 HAST `node` 属性，避免将解析对象写入 DOM。原始 Markdown、代码内容与复制语义不变。回归测试先复现未标语言围栏错误，再验证其不包含行内代码或文件标签样式。

## 六、构建与打包调用方式

本次在 Windows / Node.js 24.22.1 环境执行。正常 npm 环境可使用对应项目脚本；本机使用忽略目录中的 npm CLI 绕过既有系统 npm 启动问题。以下记录本次采用的调用方式，均在仓库根目录运行：

```powershell
node node_modules/vitest/vitest.mjs run tests/unit/application-version.test.ts tests/unit/conversation-reading.test.ts tests/unit/workspace-layout.test.ts --maxWorkers=1 --minWorkers=1
node tmp/engine-reference/npm/package/bin/npm-cli.js run typecheck
node scripts/verify-ui.mjs --reading
node node_modules/vitest/vitest.mjs run --maxWorkers=1 --minWorkers=1 --reporter=dot
node tmp/engine-reference/npm/package/bin/npm-cli.js run build
node scripts/verify-package-files.mjs
node node_modules/electron-builder/cli.js --win nsis --x64 --publish never --config.directories.output=dist/0.1.209-windows-x64
```

`tmp/engine-reference/` 是本机辅助工具，不是仓库依赖或安装包内容。生产构建与 NSIS 安装包生成是两个步骤；此前按要求暂停打包，直到用户确认 0.1.209 后才恢复。打包复用刚完成的同版本测试和构建，没有额外修改产品代码。

## 八、交接约束与剩余风险

- 背景只在共同外壳绘制；不能为了修颜色，再给每列或每条助手消息增加独立渐变。
- 颜色检查需要真实页面、桌面尺度与整页目检；像素断言只能防止已知退化，不能替代主观视觉验收。
- 围栏是否块级不能取决于是否标注语言；真正的行内路径与代码复制语义继续保留。
- 字体取本机安装，字体文件没有打包；其他机器的字形、颜色和低位深渐变需要实机检查。
- Pi/Harness 仍依赖外部 Node.js ≥22.19.0，安装包包含 SDK 资源，不包含 Node 运行时。
- 安装器沿用现有未签名配置及关闭旧 Eva、可选 Local Search 初始化逻辑。本轮没有执行安装器，没有验证安装升级、用户数据保留或 Docker 初始化流程。
- 之前记录的 Harness Windows `ReplaceFileW 1175` 间歇风险仍存在；这次全量与独立探测通过，不代表已根除该问题。
- 今天没有用真实模型账号验收长任务完成率、延迟或费用，也没有修改对应执行机制。

本次文档整理只归档已完成的 0.1.209 更新与交付，不引入新应用版本、不重建安装包，也不把此前已有能力重复计作今天新增。
