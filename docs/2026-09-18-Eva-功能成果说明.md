# Eva 今日功能成果说明

日期：2026-09-18  
项目：Eva AI Coding Agent Desktop Client  
当前版本：0.1.206  
变更状态：工作区改动，尚未提交

## 一、成果概览

本次更新围绕 Agent 执行安全、工具调用治理、外部集成和工程知识沉淀完成了一轮能力补齐。Eva 现在具备更明确的工具执行边界，能够在需要时请求用户确认，并为本地脚本、编辑器插件和后续自动化集成提供受保护的控制入口。

本次成果主要包括：

- 工具调用统一进入校验、授权、审批、执行和结果归一化链路。
- 新增 OS 层沙箱能力，覆盖命令执行和文件读写的策略检查。
- 新增 Rust `eva-sandbox` 原生模块及 N-API 接口，为跨平台沙箱能力提供基础。
- 新增本地 App Server，可通过 loopback HTTP、JSON-RPC 和 SSE 驱动 Eva。
- 新增项目知识记录、检索、状态管理和设置面板。
- 改善聊天流式消息、工具审批提示、文件路径展示和滚动恢复体验。
- 增加运行事件和执行协议元数据，便于诊断 Agent 运行过程。

## 二、用户可感知的功能

### 1. 工具审批更清晰

工具按照风险分为文件写入、终端命令、MCP、浏览器自动化和其他调用。设置中可以选择不同审批策略：

- `off`：不要求额外审批。
- `safe`：对写入、终端、浏览器和 MCP 等有副作用的调用进行确认。
- `strict`：在安全策略基础上扩大确认范围。
- `paranoid`：每次工具调用都要求确认。

聊天区新增工具审批卡片，展示工具类别、目标摘要、详细参数和超时倒计时。用户可以选择仅允许本次、在当前会话内允许，或拒绝调用；超时默认自动拒绝。

### 2. 沙箱设置可配置

自动化设置中新增 OS 层沙箱配置：

- `off`：关闭沙箱，继续使用既有审批机制。
- `permissive`：允许工作区和授权路径，拦截明显危险命令。
- `strict`：默认拒绝范围外操作，仅允许工作区、授权路径和必要系统资源。

沙箱与审批策略相互独立。启用沙箱后，即使审批策略设置为自动允许，沙箱限制仍然生效；计划模式会自动提升为更严格的沙箱和审批组合。

### 3. 本地 App Server

Eva 可在设置中启动仅监听 `127.0.0.1` 的本地应用服务，为同机工具提供控制入口：

- JSON-RPC：线程查询、线程创建、回合启动、回合中断和审批决策。
- SSE：流式文本、工具调用、工具结果、审批请求、完成和错误事件。
- Bearer Token：每次启动重新生成，不写入磁盘。

该能力面向本地脚本、编辑器插件、IDE 集成和后续 MCP 客户端，不开放公网监听。

### 4. 项目知识中心

新增按项目范围管理的工程记录，支持：

- 记录问题、变更和项目方向。
- 按关键词、类型和状态检索。
- 查看现象、根因、处理结果、验证结果、影响文件和回归守则。
- 更新记录状态或删除过时记录。
- 从工程回合中自动提取问题和变更线索。

### 5. 聊天与执行反馈

聊天链路新增或改进：

- 工具审批请求的流式事件和交互卡片。
- 用户消息在持久化完成前的本地保留，减少发送后短暂消失。
- 会话切换和异步加载的顺序保护，避免旧请求覆盖当前会话。
- 文件路径 chip 展示和路径复制体验。
- Toast 提示、错误边界和滚动位置恢复。
- 删除旧欢迎页，统一聊天工作区的入口和布局。

## 三、交付价值

本次更新把 Eva 从“能够调用工具”推进到“能够解释、约束和记录工具调用”：

1. 对高风险操作提供用户可见的决策点。
2. 对命令和文件写入增加运行时边界检查。
3. 对 Agent 运行过程保留事件和协议状态，便于定位失败原因。
4. 对外部自动化场景提供受认证的本地控制面。
5. 将修复经验和工程约定沉淀为可查询的项目知识。

## 四、当前边界

- Windows 当前沙箱后端仍以路径检查和危险命令拦截为主，尚未实现 AppContainer 级别的进程隔离。
- macOS 和 Linux 的强制包装依赖系统可用的 `sandbox-exec` 或 `bubblewrap`。
- App Server 当前只面向同机 loopback 场景，未提供跨机器访问能力。
- 项目知识以本地存储为主，尚未引入团队同步和冲突合并。
