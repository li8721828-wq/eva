# Eva 2026-08-31 运行时稳定性与上下文更新

## 1. 更新目标

本次运行时更新解决三个问题：兼容供应商非标准工具协议、减少重复工具调用、让连接错误能够定位到具体阶段和配置。

## 2. DSML 工具协议兼容

部分 DeepSeek/OpenAI 兼容网关不会返回标准 `tool_calls` 字段，而是把调用序列化为 DSML 文本，例如：

```text
< | DSML | tool_calls> ... < / | DSML | tool_calls>
```

Eva 现在会：

- 识别标准 DSML、双管道 DSML 和带空格的 DSML 标记。
- 将已验证的 DSML 调用转换为 Eva 的结构化工具调用。
- 只接受当前请求中实际提供、并且参数满足工具 schema 的调用。
- 解析失败时清除临时协议文本，并最多进行一次结构化工具协议重试。
- 不把 DSML、XML 或工具调用标记作为最终用户回答展示。

相关实现位于 `src/main/providers/openai.ts` 和 `src/main/agent-engine/agent-runner.ts`。

## 3. 重复调用控制

运行器在同一模型响应中为完全相同的工具名和参数生成签名，并只保留第一次调用。这样可以避免网关重复输出同一调用时，界面重复显示和工具重复执行。

只读工具还保留了运行内缓存和同批次 in-flight 复用。不同工作表、不同范围或不同参数的读取不会被错误合并。

对于表格任务，系统提示要求先进行一次工作簿级概览读取，减少模型按工作表逐个重复 `inspect` 的情况。

## 4. 供应商连接错误诊断

供应商请求失败信息现在包含：

- 请求来源：聊天、目标计划、目标步骤或模型池。
- 失败阶段：建立请求或读取流式响应。
- 供应商名称和连接 ID。
- 模型 ID。
- 脱敏后的 base URL。
- 错误分类。
- HTTP 状态（若供应商提供）。
- 是否允许重试。
- 对应的排查建议。

常见错误分类包括：认证失败、限流、超时、DNS 解析失败、连接拒绝、连接重置、连接关闭、模型不存在和无效请求。

`net::ERR_CONNECTION_CLOSED` 通常表示远端网关、代理或模型路由在返回完整响应前关闭连接。它不等于本地 XLSX 解析失败。对于自定义供应商，还需要检查模型 ID、工具参数、推理参数和供应商实际支持的上下文窗口。

## 5. 上下文预算

Eva 当前按模型 ID计算输入预算：

| 模型范围 | 总上下文识别 | Eva 输入预算 |
| --- | ---: | ---: |
| `deepseek-v4-flash` / `deepseek-v4-pro` | 1,000,000 tokens | 987,712 tokens |
| `deepseek-chat` / `deepseek-reasoner` | 1,000,000 tokens | 987,712 tokens |
| 其它未知或普通模型 | 128,000 tokens | 115,712 tokens |

输入预算计算会扣除：

- 4,096 tokens 的输出预留。
- 8,192 tokens 的安全缓冲。

模型 ID识别和本地预算不代表供应商网关一定开放同等大小的上下文。自定义网关可能对同一模型配置更小的限制，过大的请求可能表现为连接关闭而不是清晰的超限错误。

## 6. 上下文构建行为

每次模型请求会重新组合：

1. Eva 系统规则。
2. Agent 配置和工具 schema。
3. 历史消息。
4. 当前用户消息。
5. 已解析的附件文本和工具结果。

上下文管理器会估算 Token、压缩旧历史、保留工具调用与结果配对，并在发送前再次裁剪到输入预算。表格附件还会触发额外的 `spreadsheet` 优先策略，该策略在首轮上下文和后续轮次均会保留。

## 8. 后续排查建议

当自定义供应商再次出现连接关闭时，应优先记录完整的 `Request diagnostics`，然后按以下顺序检查：

1. base URL 是否可访问，代理和 DNS 是否正常。
2. 供应商是否真的支持当前模型 ID。
3. 供应商是否支持工具调用和当前推理参数。
4. 多附件解析后的请求是否超过网关的实际请求或上下文限制。
5. 仅该模型失败时，切换同供应商的兼容模型进行对照测试。
