# 执行状态与过程反馈修复开发记录

日期：2026-09-09
版本：0.1.205

## 变更范围

本次修改集中在会话执行状态回收、执行过程面板、以及协议重组中间态的可见性。不改变工具执行器本身的权限模型。

## 一、侧栏转圈不停（重启后残留 running 状态）

### 现象

任务结束后重启应用，侧栏会话项一直显示"进行中"转圈，实际没有任何任务在跑。

### 根因

会话的 `executionStatus` 持久化在 meta 中，但应用启动时没有任何回收逻辑：上次会话异常退出（或直接关闭窗口）留下的 `running` 状态会原样带入下一次启动。

### 修复

- `conversation-store.ts` 新增 `markRunningAsInterrupted()`：启动时把所有 `running` 会话标记为 `failed`，同时清空 `executionStatusAcknowledgedAt`，让侧栏显示红色 ✕，点击后才消失（用户确认机制）。
- `storage/index.ts` 的 `initialize()` 中，在任务运行时（taskRuns）、会话（conversations）、runtime kernel/runtime runs 上依次执行同样的回收。
- 设计原则：运行中的任务不可能在应用重启后存活，统一按"已中断"处理，而不是让 UI 永远等待。

## 二、执行过程闪现即消失（过程面板持久化）

### 现象

执行任务时"正在执行 / 思考中"只闪现一下就消失，完成后看不到任何过程记录。

### 根因

主过程其实已经在实时产出 `executionTimeline`（推理 + 工具条目），但渲染层把面板显示与否错误地绑定在 agent 的 `processOutput` 叙述设置上。测试用的 "Coding Assistant" 配置为 `processOutput: 'off'`，导致工具执行记录整体被隐藏。

### 修复

- 渲染层新增按时间顺序折叠的过程面板：
  - 相邻同类条目自动分组：工具组显示工具名或"执行工具 N 次"，带运行中/成功/失败状态图标；推理组显示"思考中"（流式时自动展开）或"思考过程 · N 段"。
  - 工具组展开后逐条渲染具体调用与结果。
- 最终消息与流式消息走同一渲染分支，过程随消息持久化，完成后仍可回看。
- **工具执行记录始终显示**；`processOutput` 只控制叙述性过程卡（thinking/finding/action/issue），不再影响工具记录可见性。

## 三、回复从半截开始（协议重组的中间态暴露）

### 现象

流式回复偶尔从句子中间开始（如"移提示，补一个 schema 版本号会更稳妥。"），文字在任意位置截断，底部一直显示"正在执行 . . ."；最终消息却又是完整正确的。

### 根因（完整链路）

1. deepseek-v4-flash 第一轮流式输出跑题（继续之前的话题），且正文混入未执行的工具协议标记（该模型已知怪癖）。
2. 两层保护各自"吞字"：
   - AgentRunner 协议门把疑似 `<tool_call` / DSML 标记之后的内容扣住不显示，确认是协议文本后永不显示；
   - 流转发层剥离 `<eva-progress>` 标签内容（`processOutput: 'off'` 时标签内文直接丢弃）。
3. 第一轮结束，Runner 检测到协议文本，发 `text_reset` 静默撤回已显示文字并自动重试；重试提示语被内部生命周期过滤器隐藏，用户全程无感知。
4. 第二轮产出正确回复并持久化。因此最终数据无损，截图只是第一轮被撤回前的瞬时状态。
5. "正在执行 . . ."指示器此前在纯文字流式时也常显，加重"卡住"的错觉。

### 修复

1. **静默重试透明化**：`text_reset` 事件增加 `reason: 'protocol-repair'`（Runner 五处协议修复点全部带上）；`ExecutionTimelineEntry` 新增 `note` 类型；收到协议重组时向执行时间线写入一条常显提示"检测到回复包含未执行的协议标记，已自动重组并重试。"
2. **修复指令强化**：两处协议修复重试指令追加"直接回答用户最新消息，不要继续之前无关的工作"，降低再次跑题的概率。
3. **空回复兜底**：最终内容剥离 `<eva-progress>` 标签后若为空但原文非空，回退为"去标签保留内文"的文本，避免模型把正式回答包进标签时产出空回复（与 09-08 空回复问题同源）。
4. **指示器真实化**："正在执行 . . ."改为仅在真的执行工具时显示（新增 `executingTools` 标志），纯文字流式只保留打字光标。

- 完整测试：70 个测试文件、328 项测试全部通过（含新增的"启动回收 running 会话"用例）。

## 使用注意

- 源码启动必须完全退出旧 Electron 进程再 `npm run dev`，否则主进程仍是旧代码。
- 若后续仍频繁触发协议重组，优先检查该连接的模型 ID / 网关兼容性，而不是继续加大重试次数。
