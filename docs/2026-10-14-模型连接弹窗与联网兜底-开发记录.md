## 二、抖动：真正的触发器是行为，不是样式

**现象与机制两层。** ①改动前的 `ui/Dialog.tsx:90`（加 portal 后同一条类名现在在 `:93`）只有 `max-h-[calc(100vh-2rem)] overflow-y-auto`，框高完全由内容撑：CDP 实测空态弹窗 721px、表单 564px、`field--models` 180px（其中虚线空态 48px）；按 CSS 常量推算满态约 932px，超上限后从「继续长高」切成「整块内滚」，标题与 Save 会跟着滚走。②更关键：改动前的 API Key handler（`SettingsDialog.tsx:892–895`，`invalidateModels()` 在 `:894`）与 Base URL handler（`:921–924`，在 `:923`）每次 `onChange` 都调 `invalidateModels()`，把 `availableModels` 与 `selectedModelIds` 一起清空——**在关键盘里每敲一个字，弹窗塌下去约 210px，已勾好的模型被静默清掉**；弹窗又 `items-center` 居中，高度一变整块上下平移，这就是「一会儿大一会儿小」。

**为什么清列表比看起来严重。** `availableModels` 是**唯一的能力存储**：每模型的上下文窗口覆盖值（`handleContextWindowChange`）与探测结果（`handleProbeModel` 写回的 `capabilities`）只活在这个数组里，主进程没有探测缓存，因此一次敲键盘连带销毁探测成果，只能重探。

**修复。** ①清空只允许由离散事件触发——`invalidateModels()` 仅保留在 Provider type 的 `onChange`（换供应商确实换模型命名空间），当前源码里它恰好 1 处调用（`SettingsDialog.tsx:878`），Key/Base URL 的 handler 变成纯 setter；守卫写在 `tests/unit/settings-provider-editor.test.ts`（源码文本断言计数 + 两个 handler 必须是纯 setter），**新增清空场景必须同步那条计数**。②过时改为「标记」而非「销毁」：新增 `computeModelStamp({type, baseUrl, apiKey})`（`provider-profile.ts:15`，FNV-1a 32 位不可逆摘要；仓内 `src/renderer`/`src/shared` 无现成 hash 已 grep 确认；选摘要而不是再存一份 apiKey，是为了**不把密钥复制进第二个 state 字段**），渲染期用 `getProviderTestConfig()` 现算比对得出 `modelsAreStale`（`SettingsDialog.tsx:174`），只在提示条上说明、不拦截保存。③抓取失败**保留旧列表**，只写消息；新增 `settings-dialog__models-notice`（`role="status"`）常显 `modelsMessage` 与过时提示——顺带修掉一个可见性缺陷：`modelsMessage` 以前只在 `availableModels.length === 0` 分支渲染，列表非空时失败原因与探测结果一个字都不显示。

**排版按 φ 落内部比例。** 四个身份字段两两成行（连接名 ⧸ Provider type、API Key ⧸ Base URL）用 `__field-row{grid-template-columns: minmax(0,1.618fr) minmax(0,1fr); gap:13px}`；间距取 φ 收敛刻度 **8（字段内）/13（行内）/21（组间）**；选项行改成 `grid-template-columns: 14px minmax(0,1.618fr) minmax(0,1fr)`，chip + 窗口下拉 + 探测按钮收进右对齐的 `__model-meta` 簇；列表槽 190→220px，使模型块（≈419px）对身份+定价块（≈259px）恰为 φ；框高 `58.5rem→56rem`。**φ 不套外框**是刻意的：736px 宽 × 1.618 = 1191px 高在常见窗口放不下，外框受 `100vh-2rem` 约束，所以比例只用在列分栏、块与块、间距刻度上。

## 三、闪烁与「可视性不好」：遮罩被祖先 transform 劫持

**取证。** Pillow 像素比对他的两张同日截图：弹窗几何逐像素一致（白框 ~802px 宽），唯一差别是页面明暗——一张背景 ≈(245,248,255) 未压暗、另一张 ≈(156–172) 已压暗。

**根因。** `ui/Dialog.tsx` 原本内联渲染（无 portal），模型连接弹窗住在 `.eva-lift` 卡片里（`SettingsDialog.tsx:804–1051` 那张卡一直包到弹窗），而 `:root .settings-page .eva-lift:hover { transform: translateY(-2px) }` 让卡片成为 `fixed inset-0` 包装层与 `bg-black/30` 遮罩的 containing block → 遮罩被约束回卡片盒子、绘在不透明白框之下；光标进出卡片触发 180ms transform 过渡 → 明暗来回切换。任何非 `none` 的 `transform`（`filter`/`backdrop-filter`/`will-change: transform` 同理）都会造成这个后果，`.agent-card` 带常驻 transform，住它里面的弹窗会永久错位。

**修复。** `ui/Dialog.tsx:85,98` 改为 `createPortal(…, document.body)`（先例 `ui/Select.tsx:121`）。全仓 6 个消费组件都只依赖标准零件（`DialogHeader/Title/Description/Close`）；`.settings-page` 类在弹窗自己的子树内、随子树一起移动，`:root` 主题变量不随 DOM 移动；`Select` 菜单与 Toast 的 `z-[100]` 本就高于弹窗 `z-50`。守卫 `tests/unit/ui-dialog-portal.test.ts`。**以后给祖先加 transform/hover 浮起前，先确认其子树内没有弹窗。**

## 四、框高：钉死 → 退回 → 随内容伸缩、只设上限

第二轮把框钉死 `height: min(56rem, calc(100vh - 2rem))` + `display:flex; flex-direction:column; overflow:hidden`，白洞没了，但空态被撑成 237px 大框，被第五轮退回。收敛后的标准写法三条（`.settings-dialog__provider-editor` / `-form`，与本页 `.settings-dialog__content` 同源，`index.css:2774-2810`）：

1. `max-height: min(56rem, calc(100vh - 2rem))` + flex 列 + `overflow:hidden`——**用 `max-height` 而不是 `height`**：框高 = 内容高，空态自然收短，列表把框撑到上限后超出部分由表单区自己滚。
2. 非滚动区一律 `flex: 0 0 auto`，否则夹取时页头与操作行会按基高比例被一起压扁（48px 的操作行会被压掉约 9px 而裁到按钮）。
3. 滚动区 `flex:1 1 auto; min-height:0; overflow-y:auto; scrollbar-gutter:stable`。给表单加 `overflow-y:auto` 的**前提**是 `ui/Select` 的下拉已 `createPortal` 到 `body`，换成内联渲染的下拉就会被滚动容器裁掉。

空态虚线框**不挂任何 `flex`**（`min-height: 48px` 自然高，守测断言该规则块内无 `flex:`）。`__model-options` 的 `max-height: 220px` 必须保留——它同时是收缩下限：候选迭代里实测掉两条错误路线，`max-height: none` 会让 30 行把 models 块撑到 1340px、表单滚动从 139px 涨到 1061px；给包裹层补 `min-height: 0` 会让列表溢出到操作行后 41px、只露 3 行。

另：`index.css` 未分层规则优先于全部 Tailwind 工具类，尺寸由 CSS 钉死后必须同步删掉 JSX 上已静默失效的 `max-w-*`（本轮删掉 `SettingsDialog.tsx` 改动前 `:849` 上的 `max-w-2xl`，那条 Dialog 现在在 `:855` 且已不带宽度工具类），留着只会误导后来人。根字号是 14px（`html, body, #root { font-size: 14px }`），`56rem` = 784px、`2rem` = 28px，**别按 16px 常识推算**（第三轮按 16px 写的「896px」有误）。

## 五、焦点辉光被裁成白边：给表单做 1.5rem 出血

**现象。** 他在 5 个字段上画红箭头：「我点击这些的时候，左边感觉有白色的东西在挡住阴影一样，有很强的割裂感」。

**机制。** 第四轮把 `-form` 固定为 `overflow-y: auto` 的滚动容器（`overflow-x` 随计算值变 auto），而 `overflow` 非 visible 的容器在自身 **padding box** 处裁剪全部后代阴影；字段又满宽贴着这条裁剪边，`eva-focus-float` 的 ±14px 横向扫描投影（模糊 15 减扩散 5，视觉触及约 24px）向左的一摆被整块裁掉。像素取证（真机 CDP + 动画冻结）：冻在 −14px 相位时字段左侧 css −1..−21 全是纯白 255,255,255，而右侧同帧有 197→228 的渐变。

**修复（只改一处）。** `index.css:2803-2804` 给 `.settings-dialog__provider-editor-form` 加 `padding-inline: 1.5rem; margin-inline: -1.5rem`（1.5rem 正是弹窗外层自己的 `p-6`，14px 根字号下 = 21px）：裁剪区扩进弹窗自身内边距，辉光落进这块「出血区」不再被裁，负外边距把内容拉回原位、字段位置逐像素不变。守测断言这两条声明成对出现在同一条规则块内。**给任何新的滚动容器放满宽控件前先核对这条。**

## 六、能力探测 `maxTokens` 64 → 512

`src/main/ipc/system.ts:419`（`eva_capability_probe` 单轮探测）从 `maxTokens: 64` 改为 `512`。64 的预算会被带 reasoning 的供应商整个吃掉——模型把 token 花在推理上，结构化调用根本没发出来，探测因此误判为「不支持工具调用」。同一处其余参数（`temperature: 0`、`stream: false`、20 秒超时、prompt 要求「Call this tool exactly once」）未动。

## 七、联网不可用：三层根因与零代码兜底

他报「虽然有联网的权限，但现在联网的功能很不好用」。诊断出三层，**本轮未改代码**，只动用户配置 `%APPDATA%\eva\plugins.json`：

1. **主源对 Docker 有硬依赖。** 唯一启用的搜索源是 `searxng-search`，Docker Desktop 未运行（其 `AutoStart=false`）→ `web_search` 全部 `ERR_CONNECTION_REFUSED`（一轮四次调用全灭）。
2. **容器出口到不了宿主代理。** 宿主侧本可出网（WinINET 系统代理 `127.0.0.1:7890`，Eva `network.mode=system`，Electron `resolveProxy` 实证 `PROXY 127.0.0.1:7890`），但 Clash 只监听回环，容器/WSL NAT 都到不了它（WSL 自己告警「NAT 模式下的 WSL 不支持 localhost 代理」）。本机直连矩阵 curl 实测：google 超时 / html.duckduckgo 拒绝 / brave 超时 / startpage 超时，**仅 Bing 可达**——正是他见过的「brave(超时), duckduckgo(超时), google cse(超时)」。
3. **兜底链薄弱且 Bing 内容已降级。** 原本只剩 `bing-rss`，而它在本机返回降级内容：RSS 与 HTML 都正确回声查询，但 RSS 10 条全是小红书登录页、HTML 7 条全是垃圾站；EN 查询的 RSS 10 条被相关性过滤全灭 → 终态 `[SEARCH_UNAVAILABLE]`。

**处置。** 先在同一份配置的**克隆副本**上用 esbuild bundle + Electron 探针复现同一 `SEARCH_UNAVAILABLE`，再用 `PluginStore.installMarketplace('duckduckgo-search')` 安装并 `setEnabled(false)`，让它作为 `lastResort` 无密钥兜底常驻候选链，同时恢复 SearXNG 的启用态。**坑：`installMarketplace` 对新插件默认 `enabled=true`，而搜索源互斥会把原主源顶成 disabled**——必须先记原状态、装完把主源恢复启用。

当前 `plugins.json` 实测状态（18:49 读取）：`searxng-search enabled=true`、`duckduckgo-search enabled=false`（装而不启用，作 lastResort）、`bing-rss-search enabled=false`、`tavily-search enabled=false` → 候选链 `["SearXNG Search", "DuckDuckGo Search (last resort)", "Bing RSS Search (last resort)"]`。该轮验证：EN「AI news this week」4.5s、zh「本周AI新闻」4.2s 均经 DDG 返回真实结果；Docker 关着也能搜，修复目标达成。`bing-web-search` 经代理直探虽报 8 条但内容不可信（直连抓取是垃圾页），**未**纳入兜底链。

护栏已进 `REGRESSION-GUARDS.md` 新增的「联网与搜索源」节：**不得删掉 DDG 这条安装记录**（删除即让搜索重新依赖 Docker）；诊断顺序为「看已启用源 → 看 Docker 是否在跑（容器 `eva-searxng`，127.0.0.1:8080）→ 用 `probeKeylessSearchProvider` 逐个探测无密钥源」；`filterSearchResultsForRelevance` 对短查询是**空操作**（`extractSearchAnchors` 只收 ≥4 字中文片段或 ≥3 字符拉丁词，「本周AI新闻」anchors 为空、整条过滤放行），不要把它当内容质量闸门。
