## 一、变更范围与背景

这条线从 10-12 的「其他部分太生硬，不如对话框的设计」开始，今天由他**逐轮收窄**到一套可执行标准。他今天的判断链（原话，按时间）：

1. 「感觉设置里面很多模块没必要做独立悬浮，很割裂」
2. 「这两页是不是扁平化过头了」
3. 「这个也恢复成原来样子吧」（针对长期记忆页）
4. 「这一页原来挺好，就改这一页」
5. 「按照这一页的感觉就是鼠标悬浮选择的时候会有浮空感觉，你把这个记忆系统页面做一下吧」
6. 「记忆系统的改造挺好的，你按照这个风格和标准去改造一下设置里面的其他模块」
7. 输入框：「这个本身点一次就可以选择权限了，结果点了一次还得再点一次，麻烦了，而且这个说明和图标也看不出来是选择权限的」→ 第一版交付后：「感觉有点复杂了弄得，而且应该考虑位置和布局都挤在左边不好，弄在右边弄一个权限的图标就可以。不用加什么文字」

结论：**「浮成独立卡片」被否，「完全压平」也被否**，他真正认可的是第三条——静止态用描边分组，只有光标指上去才给一次浮起应答。

## 二、收口后的三档表面语言

| 档 | 用于 | 静止态 | 交互态 |
|---|---|---|---|
| 悬浮 | 仅 composer 与右栏便签 `.task-workspace-note` | 透明 1px 边 + 三层阴影（环境辉光 / 接触阴影 / `inset 0 1px 0` 白色顶高光） | focus/hover 才换边色与更强的辉光 |
| 描边 + 光标才浮 | Settings 内所有分组卡（`.eva-lift`，当前 44 处、9 个面板文件） | 细线框 + `--ui-surface` 底色 + **零位移零阴影** | `:hover` 才 `translateY(-2px)` + `--ui-shadow-lift`，缓动与 `.agent-card` 同一条 `cubic-bezier(0.22,1.22,0.36,1)` |
| 贴边 | 骨架（页头、侧栏、列表行、工具条） | 不内缩、不描边、不浮 | — |

浮起用的那条投影**绝非常驻**：常驻就退回他否掉的「满屏互不相干的白块」。他认可的是应答，不是深度本身。

## 三、`.eva-lift` 的两处越界修正

铺到全部面板前，钩子本身有两处必须改，否则会波及 Settings 之外：

1. **作用域**：原写成全局 `.eva-lift`，而 `ProjectKnowledgePanel` 这类组件在右栏 `.task-workspace-note`（本来就是一张悬浮卡）里也会渲染，全局钩子会出现双重辉光。改为 `:root .settings-page .eva-lift`，成本面板同理不能挂类——`.cost-panel`/`.cost-metric` 同一组件既当独立页又在 Settings 里，用 `:root .settings-page .cost-panel` 的专属规则给同样的应答。
2. **hover 不许改 `border-color`**：记忆卡自带语义色边（`border-red-200`、`border-violet-100`），被 hover 覆盖会失去含义。钩子只动 `transform` 与 `box-shadow`。
3. 附带一条特异性坑：钉平分组阴影的规则是 `:root .settings-page .eva-panel:not(.agent-card)`（0,4,0），hover 规则必须写成 `:root .settings-page .eva-panel.eva-lift:hover`（0,5,0）才压得过它；只写 `.eva-lift:hover` 会与它打平并按源码顺序输掉——静止态看着对、hover 阴影被静默吃掉。
4. **被「框里不套框」压平的嵌套分组一律不挂钩子**（ModelPool 的选中池编辑器即因此摘掉），否则是一个永不应答的死类名。`divide-y` 成排条目由**容器**整体应答，不做逐行浮。

## 四、composer 的文件权限：图标即下拉

- **删掉的是弹层，不是功能**：旧路径「齿轮图标 → 弹层 → 嵌套下拉 → 选项」比下拉本身多一整跳。`isConversationSettingsOpen`、齿轮 `Button`、弹层容器与 `Settings2` 导入全部移除；`ui/Select` 本身是「点开—选中」两次，这已是下限。落盘路径 `setConversationPermissions(conversation.id, permission, fileAccessGrants)` 逐字保留。
- **第一版（左侧带标签的下拉）被他退回**，最终形态是底栏**右侧**一个纯图标触发器，可见文字为零，左侧只剩模型下拉。
- **档位由图标自己表达**：`workspace`→`FolderLock`、`granted-folders`→`FolderKey`、`full-access`→`HardDrive` 且染 `text-amber-600`（唯一的风险色）。控制名与当前值进 `title`：`文件权限 · 全部磁盘` + 换行 + `决定这个对话可以读写哪些文件。`
- **`ui/Select` 加两个可选 prop**：`triggerIcon`（替换标签文字与 chevron，并 `justify-center px-0`）与 `menuWidth`（固定菜单宽度并把菜单**右缘**贴触发器右缘——28px 的图标撑不出可读的下拉，左锚定会让菜单溢出窗口右边）。全仓 `ui/Select` 的消费者实测 13 个文件，除 `InputBar` 外 12 个都不传这两个 prop，行为逐字不变。
- **文案不再写死英文**：`ui-copy.ts` 新增 `composer` 段（控制名、说明、三档标签、`Shift+Enter` 提示），en·zh·ja 三语由 `satisfies` 强制齐全；`InputBar` 从 `useAppStore` 多取 `language`。他的 `config.json` 是 `language: "zh"`，界面直接出中文。

## 七、本轮新增的取证通道：CDP 截图 + 几何量测

界面类改动过去只能靠他目检，本轮打通了一条可自己取证的路（不改代码、不写数据）：

1. `npm run dev:debug`（= `electron-vite dev --remoteDebuggingPort=9222`），从 `http://127.0.0.1:9222/json/list` 取 `url` 含 5173 的 page target；
2. Node 24 全局 `WebSocket` 直连 `webSocketDebuggerUrl`，`Runtime.evaluate`（`returnByValue`）读 `getBoundingClientRect()` 与 `getComputedStyle()`，`Page.captureScreenshot({clip, scale:2})` 出局部图。

本轮量到：权限触发器 `x 1250 / 25×25`、`textContent` 为空、静止态 `backgroundColor`/`borderTopColor`/`boxShadow` **全透明**（裸图标，无底块）；菜单 `w 176`、右缘 1274 与触发器右缘逐像素对齐、向上弹（菜单 `y 671..764` 对触发器 `y 768`）、距窗口右边留 126px 不溢出、三项中文标签且当前档 `aria-selected=true` 带勾；`Escape` 后 `[role=option]` 归 0，档位未变（**没有误写他会话的权限**）。

三个必须记住的坑：

- **窗口一旦被最小化，`visibilityState` 变 `hidden`、视口塌成 640×100**，此后所有坐标都是塌缩态假读数，且带 `clip` 的 `captureScreenshot` 会**永不返回**（本轮两次挂死都是这个原因）。断言 `visible` + 记下 `innerWidth` 再继续。
- **探针自己的 `el.click()` 会给元素留下焦点态**。第一次截图里图标带了一块浅色底，实为 `:focus` 造成的，blur 后静止态透明。看静止观感要先 blur。
- 用无头 Chrome 直接打开 dev server 这条路走不通：`window.eva` 预加载桥不存在，且本机代理会让 `127.0.0.1` 直接连不上（需 `--no-proxy-server`，即便如此也只是空壳）。
