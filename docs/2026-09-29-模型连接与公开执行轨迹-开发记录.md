# 模型连接与公开执行轨迹开发记录

日期：2026-09-29

## 1. 本次目标

本次处理两个实际使用问题：

1. API 中转站不一定实现模型列表接口，连接配置不能把 `Fetch Models` 当成唯一入口。
2. AgentRunner 已经产生了工具周期和阶段事件，但 renderer 之前丢弃了 `thinking` 事件内容，用户看不到稳定的公开执行链路；ACP 远程通道也有独立的事件转发路径。

## 2. 模型连接改动

### 原有问题

`SettingsDialog` 的 `defaultModel` 来自 `selectedModelIds[0]`。当 provider 的 `listModels()` 不可用时：

- `availableModels` 为空；
- 没有模型可以勾选；
- 保存校验无法得到 `defaultModel`；
- 连接无法用于聊天和 Agent。

### 实现

影响文件：

- `src/renderer/components/settings/SettingsDialog.tsx`
- `src/renderer/lib/provider-profile.ts`
- `tests/unit/provider-profile.test.ts`

具体行为：

- 新增 `modelName` 状态和 `Model name` 输入框。
- `getProviderTestConfig()` 优先使用手动模型名，未填写时回退到已选模型的第一项。
- `buildProviderProfile()` 将手动模型名保存为 `defaultModel`。
- 当手动模型没有出现在 Fetch Models 返回结果或勾选列表中时，自动补入 `models`。
- 编辑已有连接时，从 `provider.defaultModel` 回填输入框；新建连接和切换 Provider 时清空，避免串用上一连接的模型。
- Fetch Models 仍然保留，用于能提供列表的中转站发现多个模型和探测能力。

数据形状示例：

```json
{
  "defaultModel": "gateway/model-x",
  "models": [
    { "id": "gateway/model-x", "name": "gateway/model-x" }
  ]
}
```

这里的模型 ID 原样保存并透传给 provider；Eva 不在保存阶段验证上游是否存在该模型。

## 3. 公开执行轨迹改动

### 公共映射边界

新增纯映射模块：

```text
src/main/ipc/public-execution-trace.ts
```

`toPublicExecutionNote()` 只允许已知的 runner 生命周期标记进入公开通道，例如工具结果复核、进度复核、结果汇总、协议重试和回复续写。任意未知的模型/provider `thinking` 文本返回 `null`，不会被当作执行证据。

### 桌面链路

`src/main/ipc/conversation.ts` 在消费 `AgentRunner` 事件时：

- 将允许的 `thinking` 阶段转换为 `executionTimeline` 的 `note`；
- 使用 `lastPublicExecutionNote` 对同一轮重复阶段去重；
- `processOutput: off` 时不新增公开备注；
- 工具调用和工具结果仍由真实 `tool_call` / `tool_result` 事件生成，不使用阶段备注替代工具证据。

这样流式期间和最终落盘的 assistant 消息使用同一份时间线数据。

### ACP 远程链路

`src/main/services/app-server/server.ts` 使用同一个 `toPublicExecutionNote()` 映射 `AgentRunner` 的阶段事件，并通过已有的 `turn/progress` 发布给 ACP。手机端继续使用 `session/update` 接收事件，不增加第二套执行器或协议。

### Renderer 展示

`src/renderer/components/chat/MessageBubble.tsx` 之前按 `kind` 分组后只渲染备注组第一条。现在同一组中的所有 `note` 都逐条渲染，连续阶段不会被吞掉。

## 4. 回归防护

新增和更新的约束：

- 模型连接不能依赖 `/models` 接口；手动模型名必须进入 `defaultModel`，且不能因为列表为空而丢失。
- 原始 `thinking` 文本不能直接成为公开执行证据。
- 桌面 `executionTimeline` 和 ACP `turn/progress` 必须使用同一白名单映射。
- 同一轮中的重复公开阶段需要去重。
- 连续时间线备注必须逐条渲染。

## 6. 剩余风险

- 手动模型名是否可用仍由中转站决定，Eva 只能在连接测试或实际请求时得到最终结果。
- provider 新增未被白名单识别的阶段文案时，公开轨迹会继续隐藏该文案，需要显式增加映射和测试。
- ACP 当前没有断线事件重放；这与本次模型配置和阶段显示改动无关。
