## 一、变更范围与背景

用户原话（18:27）：「目前 eva 的前端布局我感觉还有问题，我比较满意的是对话框这个 3D 阴影的效果和边框，对其他部分不太满意，其他部分太生硬，不如对话框的设计，你可以按照对话框匹配的风格，改造一下其他布局吗」。

现状确实割裂：只有输入框（composer，`InputBar.tsx:523`）是「软」的——8px 圆角 + 一条**始终存在的 1px 透明边框**（可见边缘来自阴影而非描边）+ 三层阴影（环境辉光 / 接触阴影 / `inset 0 1px 0` 白色顶部高光）+ 200ms 过渡。其余表面——顶栏、会话列、右侧 Workspace、Settings 各页、Artifacts/Symposium 整页——都是「硬」的：实色 1px 分隔线（`border-b`/`border-r`）、单层阴影或无阴影、平涂 `bg-white` 墙。

经确认的三个档位：**范围 = 全部页面**、**力度 = 每个区域浮成独立卡片**（区域之间留真实缝隙，不再用 1px 硬线拼接）、**主题 = 只改浅色**（dark/starlight 不重新设计，只防回归）。

## 二、沿用 composer 的规格（不发明新值）

| 档位 | 用于 | 值 |
|---|---|---|
| 圆角 | 区域卡片 | `--ui-radius-lg` = 8px |
| 圆角 | 控件（按钮/输入/下拉） | `rounded-md` = 6px，保持 |
| 圆角 | 芯片、卡片内段落 | `rounded` = 4px，保持 |
| 边框 | 卡片级表面 | `1px solid transparent`，hover/focus 才 `border-violet-100` |
| 阴影 | 区域卡片 | `--ui-shadow-float` = `0 0 30px -10px rgba(53,62,104,.22), 0 0 12px -4px rgba(53,62,104,.12), inset 0 1px 0 rgba(255,255,255,.96)` |
| 阴影 | 卡片内重复项（列表条目、小卡） | `--ui-shadow-control`（辉光半径收到约 9px，避免列表糊成一片光） |
| 阴影 | 浮层（Dialog / Select 菜单 / Toast） | `--ui-shadow-popover` |
| 过渡 | 以上全部 | `transition: border-color/box-shadow/background-color 200ms` |
| 缝隙 | 会话列 | 水平 32px / 垂直 20px，直接采用 composer 已在用的 `px-8 py-5`（`InputBar.tsx:516`） |
| 缝隙 | 右栏等窄区 | 保留既有 12/14/16px，不放大 |
| 卡内分段 | hairline（`border-zinc-100`/`divide-zinc-100`） | 沿用 composer 内部做法，**不叠第二层阴影** |

缝隙下限的由来：`--ui-shadow-float` 的环境辉光可达半径 = 30 − 10 = 20px。缝隙小于该值，两张卡片的辉光会在缝里互相糊掉——视觉后果正是本次要消除的「生硬」。

## 三、三条决定做法的前提

1. **必须 token-first，不能抄字面量。** composer 的阴影串在全仓**没有任何 dark/starlight 覆盖**；深色下只是靠 `index.css` 的 `!important` 把 `bg-white` 换成深色面板色。把字面量复制到 30 个表面，等于给每个深色表面加一条 `inset 0 1px 0 rgba(255,255,255,.96)` 白线。提到 `--ui-*` 变量后，`--ui-shadow-panel` 在 dark 与 starlight 各自已有覆盖，走 CSS 钩子的表面在深色下结构性零回归。
2. **阴影/圆角的字面量只写在未分层的 `:root`，`@theme` 里只放 `var()` 指针。** Tailwind v4 会把 `@theme` 中的阴影字面量内联进生成的工具类，那样 dark/starlight 的覆盖会静默失效。落地形态：`:root` 存真值，`@theme` 写 `--shadow-float: var(--ui-shadow-float);` 之类指针。同理，`src/renderer/index.css` 没有任何 `@layer`，`.eva-panel`、`.cost-panel` 这类未分层规则**优先于全部 Tailwind 工具类**——给元素加 `eva-panel` 时必须同时删掉同一元素上冲突的 `border-*`/`bg-*`/`rounded-*`，留着只会静默失效并误导后来人。
3. **正文气泡区不做卡片。** 该处代码注释早已写明「助手回复是一整块开放画布」，`.chat-message-surface`、`.tool-call-group`、`.message-action` 保持 `border:0; box-shadow:none; background:transparent`。「每个区域浮成卡片」在会话窗内**止步于正文容器**，气泡一律不动，层级仍由排版与节奏给出。
