# 业务实现流程改造方案

日期：2026-11-27。目标版本：0.1.240。

状态：本轮范围已在 0.1.240 落地。全量 150 个测试文件、1375 项通过，1 项可选 Maven 联测跳过；类型、完整界面及源码构建通过。尚未制作安装包。

## 目标与入口

将“实现现有项目功能”和“生成独立领域模块”作为两条明确路径。已确认的需求可以直接交给现有桌面 Agent，不要求先经过建模、Spec 和 DSL；原 `/coding` 的确定性生成及正式发布门禁继续保留。

业务实现链路：需求与验收依据 → 创建隔离工作树及输入快照 → 所选运行时读取代码、修改、补测、自测 → 查看差异及执行记录 → 人工业务验收。简单需求不增加新的一轮模型打分；有明确业务决定待确认时仍先澄清。缺正式材料但已有模拟规格时，用户显式选择按假设试验，产物不自动变成正式交付。

## 本轮落地范围

1. 需求卡新增优先的“实现现有项目功能”入口，原生成器入口明确标为生成模块/参考代码。
2. 后端校验需求运行、会话归属及来源完整性，保存原文、验收依据、假设和来源摘要。
3. Git 项目创建 `codex/implementation-<任务 ID>` 工作树。保留原工作树的已暂存、未暂存及未忽略的新文件作为实施起点，不切换原分支、不清理用户修改。无法可靠复制的链接、超量快照或复制时源目录发生变化明确停止。
4. 创建独立实现会话，复用现有桌面聊天执行入口。运行时、模型连接、原生工具目录、审批、取消、真实工具日志均复用；不新增另一套 SDK 循环，不把 Eva 工具挂进 Pi/Harness。
5. 启动任务幂等：重复点击打开原实现会话，不重放已经持久化的启动消息或已执行操作；失败后用户可以在实现会话明确继续。
6. 变更审查相对实施基线生成，包含 Agent 新增文件，使用独立 Git 索引，不改变原项目或实现会话的真实暂存区。保留完整补丁和摘要，长差异预览明确显示截断。
7. 状态区分“准备完成/Agent 执行/会话已返回/待业务验收”；不因 Agent 自述、一次回复结束或文件存在就标记功能已验收。

联测同时修复了原生 worker 缺少 Windows 命令解析环境、Pi 空环境覆盖导致外部命令未实际执行的问题；两种 SDK 已实际完成读文件、修改、执行外部测试及结果核对。无消息的已准备实现会话也保留任务与差异入口。

## 工作区与数据边界

实现会话使用工作树目录的项目权限与独立会话记录，不复制原会话的磁盘外写入授权。完整需求快照放在实现工作树的 Eva 元数据目录；开发记忆和用户长期记忆保持原边界。

新增实现任务记录关联需求输入摘要、基线提交、工作树、分支、实现会话及差异文件。上游变更创建新任务，旧任务保留供审查；不把旧代码自动算作新需求的实现。

本功能不自动合并、推送或部署。原目录中的依赖缓存和被 Git 忽略的本地文件不盲目复制；Agent 根据项目脚本运行检查，缺少环境时如实报告，禁止补写“已通过”。

## 生成器定位

`java-reference`、`java-maven` 等用于声明支持范围的参考模块；`java-domain` 等生产目标仍依赖正式规格与验收契约。生成器产物不再作为现有项目业务实现的唯一终点。

## 验收标准

- 能从已确认需求或明确采用假设的草稿创建真实实现会话，无需重输需求或先生成 DSL。
- 原分支、原工作区字节与暂存状态保持；实施起点包含用户当前修改。
- 同一输入重复操作复用任务；启动消息去重；历史有副作用时不自动重放。
- 修改来源、跨项目请求、目录链接、失败/取消及快照冲突不产生假成功。
- 变更预览包含未跟踪新文件，并保持真实 Git 索引不变。
- 实现会话走现有 AgentRunner 和运行时选择，保留审批与取消；评审界面不把回复完成当作业务验收。
- 完成定向、类型、完整界面、全量及编译检查；不调用用户真实网关验证。

## 后续扩展

独立业务样例库、可配置的独立验收执行器及验收通过后的合并入口可继续扩展。本轮提供真实 Agent 实现与差异交付，不宣称已自动完成所有业务验收；固定结构校验、哈希和既有生成器测试继续复用。
