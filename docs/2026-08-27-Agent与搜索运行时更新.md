# Agent 与搜索运行时更新

日期：2026-08-27  
版本：v0.1.131

## 本次目标

本次改动聚焦于让 Agent 在长任务中更稳定地调用工具、控制上下文增长，并让联网搜索返回可用且可验证的证据。重点不是增加固定关键词或固定流程，而是把工具选择、执行、结果保留和失败诊断拆成可控环节。

## 工具调用与调度

### 工具索引和按需加载

- 工具较多时，首轮不再直接携带全部 Schema。系统保留常用文件与命令工具，并提供 `tool_search` 供模型检索未加载能力。
- 工具索引只包含名称、简短用途和参数摘要；完整 Schema 仅在实际选中后提供，降低请求输入量。
- 对可识别任务按意图提供首批工具：文件检查、终端、桌面操作、Blender、联网检索和任务编排各自有最小集合。无法可靠分类的自定义工具仍完整保留，避免错误地剥夺能力。

### 批量、串行和并行执行

- 新增 `dispatch_tools`。一次最多提交 8 个已授权调用。
- 互不依赖的只读调用可在同一批中并行执行。
- 后续调用可通过 `dependsOn` 声明依赖，并用 `{"$ref":"调用ID.data.字段"}` 引用前一调用的结构化结果。
- 写入、命令、浏览器和桌面操作不允许通过依赖引用自动串接，仍由显式的权限校验和本地工具 Schema 约束。
- 调度器会验证调用 ID、工具是否已授权、参数是否为对象、依赖关系以及本地 JSON-Schema 子集；模型即使给出错误批次也不会直接绕过本地校验。

## 上下文和迭代控制

- 工具结果在执行记录中保留完整内容，但下一轮模型请求只获得有上限的版本。网页搜索和网页正文分别使用更紧的上下文限额。
- 已完成的早期工具事务会压缩成可追溯的证据摘要；保留最近一次完整事务，避免移除工具调用与结果之间的配对关系。
- 压缩后的历史证据使用滚动窗口限制大小，模型仍能知道较早结果存在，而不会让每轮输入持续线性增长。
- 后续工具调用输入预算设为独立上限，兼容上下文窗口较小的中转服务；不会仅以模型宣传的上下文长度作为请求体上限。

## 联网搜索可靠性

### 搜索与网页阅读分工

- `web_search` 返回标题、URL 和摘要，并明确标记其不是网页证据。
- 对调研和时效性结论，模型被要求从返回列表中选择相关 URL，再用 `read_web_page` 阅读正文后作答。
- `read_web_page` 提取可读正文，移除导航、脚本、页脚等噪声，并限制重定向次数、单页字符数、响应大小和请求时长。

### 搜索质量和请求保护

- 支持 Brave、Tavily 和 SearXNG 三种后端，通过已启用的搜索插件选择服务。
- 搜索请求使用缓存、同查询去重、最多 3 个并发请求和最小启动间隔，避免一个任务高频重复检索。
- SearXNG 的语言参数改为可选，不再强加语言；未指定时交给已配置的服务决定。
- 搜索结果按用户查询中的动态锚点做相关性过滤：中文按查询自身的四字片段，英文按长度足够的词条匹配标题、摘要和 URL。结果完全无关时会明确拒绝，避免把搜索引擎噪声当作证据。
- 网页访问拒绝本地地址、私网地址、带凭据 URL 和危险重定向；DNS 校验使用 `resolve4`/`resolve6`，规避部分 Windows `getaddrinfo` 环境异常。

## 本地 SearXNG

- Eva 的 Docker 管理服务使用独立的 `eva-searxng` Compose 配置，在 Windows 上将配置和缓存统一放入 `D:\Eva\searxng`。
- 服务仅绑定 `127.0.0.1:8080`，启动后会轮询 JSON API，确认可返回 `results` 数组才视为就绪。
- 设置页可测试连接：区分无法连接、HTTP/JSON API 异常，以及后端可用但部分搜索引擎限流或不可用的情况。
- 本机已重新部署容器 `eva-searxng`，并验证 `http://127.0.0.1:8080/search?...&format=json` 返回有效 JSON。

## 运行时结构与边界

- 对话生命周期、活跃运行登记、任务运行生命周期、外部 URL 策略和应用服务入口被拆分为独立服务，减少 IPC 层与 Agent 运行器之间的耦合。
- `RunRegistry` 统一保存可取消的进程内任务句柄；持久化进度仍归存储层，任务结束后登记会清理。
- IPC 注册增加可信边界与契约检查，项目新增静态校验脚本和 GitHub Actions 验证工作流。
- 未授权工具、未通过 Schema 的参数、私网网页地址和不合法工具协议都应在本地拒绝，而不是依赖模型自我约束。
