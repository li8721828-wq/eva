# Eva 多执行引擎使用说明

> 本文记录 11 月 3 日版本；当前会话、事件和前端行为见 [11 月 4 日 Agent 宿主使用说明](2026-11-04-Eva-Agent宿主使用说明.md)。

日期：2026-11-03，已更新为原生后端接管版本。

## 这次切换会改变什么

切换到 Pi 或 DeepSeek Harness 后，由对应框架管理运行时提示词、会话上下文、压缩和核心工具。Eva 继续提供界面、模型连接、权限审批、运行记录和扩展能力。

这是对当日初版的进一步改造：初版只是换框架循环，读写文件和命令仍转回 Eva；当前核心操作直接调用各框架的原生实现。

| 部分 | Pi 模式 | Harness 模式 |
| --- | --- | --- |
| 基础提示词 | Pi coding-agent 提示词构建器 | Harness 系统提示与原生工具指导 |
| 运行时上下文 | Pi Agent / SessionManager | Harness Session / Projection |
| 长历史压缩 | Pi 原生 compaction | Harness TokenMeter / compaction-basic |
| 读文件 | 原生 `read`，参数 `path` | 原生 `read`，参数 `file_path` |
| 编辑和写入 | 原生 `edit` / `write` | 原生 `edit` / `write`，包括文件观察与过期内容检查 |
| Windows 命令 | 原生 `powershell` | 原生 `pwsh` |
| 文件列举 | Pi 原生 `ls` | 保留 Eva 目录扩展；也可使用原生命令工具 |
| 网页、MCP、表格、运行管理等 | 显式保留为 Eva 扩展 | 显式保留为 Eva 扩展 |

文件搜索等未替换的 Eva 工具也作为扩展保留，模型工具说明带有 `[Eva extension]`。原生工具记录与 Eva 扩展记录分别标注来源，不会仅根据设置中选了哪个引擎就把全部工具标成原生。

前端仍然是 Eva，所以布局、字体和活动区相同。基础提示词和执行路径已经改变；你配置的智能体角色、业务记忆参考和当前项目的 `AGENTS.md` 仍可提供给原生后端。

## 如何启用

1. 使用本次代码重新构建并重启 Eva，避免继续使用已经启动的旧主进程。
2. 打开「设置 → 偏好与模型 → 通用 → 执行引擎」。
3. 选择 Eva、Pi Agent 或 DeepSeek Harness。
4. 使用后两个引擎时填写 Node 可执行文件，如 `node` 或本机的 `D:\node\node.exe`，然后保存。
5. 开始下一次对话或任务，展开工具记录可查看「Pi 原生」「Harness 原生」与「Eva 扩展」来源。

需要外部 **Node.js ≥22.19.0**。不要在路径字段里附加命令参数或引号。默认保留 Eva；保存影响新运行，当前运行及其已经创建的子任务不会热切换。

执行引擎与模型分别选择，继续使用 Eva 已配置的模型连接，不需要给 Pi 或 Harness 再填一套 API Key。原生模式要求连接支持结构化工具调用；网关只返回旧式文本/XML 工具信封时会报出不兼容，不会通过 Eva 的旧修复路径偷偷执行。

## 权限与停止

原生工具真正执行前，仍要经过 Eva 的工具能力、工作区/额外目录、只读授权、审批和沙箱检查。切换引擎不会扩大智能体的工具权限。

命令通过框架自己的进程后端执行，启动参数先经过 Eva 的沙箱包装。精确限定可写文件的运行不提供原生命令工具，防止绕过文件范围约束。Windows 沿用当前政策检查型沙箱的隔离边界，不等于系统级容器。

停止任务会取消模型请求、通知原生框架停止，并在必要时结束框架进程树。失败操作不自动原样重放，启动失败也不会静默换回 Eva 再执行一次。

## 会话和行为边界

Eva 仍保存用户可见的对话。每次运行将历史导入新的原生框架会话，然后由框架维护本轮工具往返和压缩。Harness 导入旧历史时明确标为历史参考，不编造不存在的 Harness 原生流记录。

切换发生在运行边界，不提供在途状态互迁。原生后端沿用自己的工具批次、文件观察和停止行为，不再插入 Eva 原有循环的强制回读、单工具截批或 `FINAL/CONTINUE` 阶段探针；Eva 模式的原有逻辑保持。全局安全请求上限和上层 Goal/Team 调度仍然存在。

没有自动载入 `~/.pi` / `~/.dsh` 中的凭据、用户插件或完整 CLI 配置，也不代表嵌入了两个产品的完整终端界面。

本次使用真实 SDK、真实临时文件和真实命令进程验证，模型响应受控。没有调用用户模型账号，因此尚不能宣称真实长任务完成率、延迟或费用已经改善，也不能保证模型永不提前作答。
