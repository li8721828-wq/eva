# EVA 回复链路与审查质量改进

日期：2026-09-11  
发布版本：0.1.206

## 更新背景

本次根据真实会话记录和用户截图，处理三类问题：供应商错误被当成成功回答、简单对话过度解释能力边界，以及代码审查重点不突出。

当天检查到的典型现象：

- 09:18，白菜ai / deepseek-v4.1-flash 返回“Bad request from AI provider”，但活动日志记录为 agent.completed。
- 09:19，切换到 deepseek-v4-flash 后回复成功，耗时约 3.4 秒，但对“你好”生成了 448 字的工具限制和项目介绍。
- 多轮回复把按需加载已授权工具说成需要申请新授权；切换到代码审查后仍重复天气或联网说明。
- 后续审查截图中，长开场、连续大段正文、技术标识与自然语言混排，降低了可读性；部分疑点与已确认问题没有清楚区分。

## 一、补齐供应商错误识别

### 实现

在 AgentRunner 的统一模型调用入口检查已识别的网关错误正文。识别要求正文以特定网关格式开头，并包含多个客户端或配额提示特征，避免把普通的错误解释文字误判为供应商失败。

检查覆盖普通回复、工具执行后的无工具检查点，以及最终总结调用。命中时清除临时显示的正文，抛出不可重试的 InvalidRequestError，交由现有诊断和失败流程处理，不再把该内容作为成功回答收尾。

用户会收到中文说明，提示检查供应商模型名称和接口兼容性。本轮不会因这种错误自动重试。

### 边界

- 这是对已观察到的特定错误格式的防护，不是任意供应商错误正文的通用识别器。
- 本次没有证明 deepseek-v4.1-flash 在该供应商上的具体拒绝原因，也没有修改供应商账号或模型路由。
- 流式正文可能在完整特征出现前临时显示；识别后会发出清除事件。

## 二、澄清工具按需加载

初始工具选择保留最小工具集，同时向模型提供当前 Agent 已授权的工具名称目录。

追加工具入口和系统提示明确说明：加载已有授权工具由模型按需调用，不需要用户再次批准加载。实际文件访问范围和工具动作权限继续生效，不能将“可加载”解释为所有动作均可执行。

目标是减少“我还没有工具，需要你批准”的无关解释，并让模型知道可以加载哪些工具。

## 三、改善日常回复

新增回复长度与话题切换规则：

- 简单问候以一到两句自然语言回应，避免标题、列表、工作区猜测和工具权限说明。
- 简单问题先给答案，只补充相关信息。
- 用户切换话题后直接回应新问题，不重复旧答案、已完成工作或联网检查。
- 实质性任务仍保留用户要求的深度，不统一截短所有回复。

## 四、改善代码审查组织方式

原有展示规则偏向连续自然段，并要求文件名、字段名和普通标识符尽量使用普通文本。本次调整为：

1. 审查先列可执行的问题，按高、中、低严重程度排序。
2. 每项采用简短标题，紧接经核实的代码位置、触发条件、影响和修正建议，避免长篇开场。
3. 路径、函数名、字段名、命令和代码表达式使用行内代码，便于扫描。
4. 检查相关上下文与调用方后再报告缺陷，不能仅凭可疑表达式下结论。
5. 将未验证疑点与已确认问题分开；不得编造行号或夸大影响。
6. 能继续用已授权读取工具检查的内容，应完成检查后再回复；不把同一项审查反复交回用户指挥。
7. 未经请求不修改被审查代码；重要的未覆盖范围、未运行测试放在末尾简要说明。

上述规则适用于审查请求，并继续尊重用户指定的输出格式。

## 待复测与未处理事项

- 提示规则接入已通过测试，但本轮没有发送新的付费模型请求验证最终回复质量。
- 提示规则不能保证模型每次严格遵守；需要用实际问候、话题切换和审查任务继续观察。
- 原有历史回复不会自动重写或重新组织。
- 用户截图显示的一轮审查耗时约 79.4 秒，其中工具约 44.4 秒、模型约 34.8 秒；尚未完成逐调用性能分析，本次不宣称回复速度已优化。
- QQ 网关周期性断线后重连现象已记录，本次没有修改连接逻辑。
